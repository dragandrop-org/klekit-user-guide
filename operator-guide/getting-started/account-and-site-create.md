# 계정과 사이트 만들기

<figure><img src="../.gitbook/assets/branding/page-headers/getting-started/account-and-site-create-v2.png" alt="계정과 사이트 만들기 대표 이미지"><figcaption></figcaption></figure>

**업무 대상:** 새 사이트 개설을 맡은 담당자용 안내입니다. 기존 학원 사이트의 강사·질답 조교라면 새 사이트를 만들지 말고 학원이 안내한 계정과 담당 업무를 확인하세요. 실제 작업 가능 범위는 본인 계정의 권한을 확인하세요.

클킷을 운영할 **플랫폼 계정**으로 로그인하고, 내 사이트의 이름·주소·운영정보를 정한 뒤 관리페이지로 이동합니다. **계정 가입, 사이트 생성, 플랜 시작, 관리자 진입, 방문자 공개는 서로 다른 단계**입니다.

**완료 기준:** 로그인한 계정과 생성한 사이트를 구분할 수 있고, 사이트 목록의 이름·주소·설정 상태와 해당 사이트 관리페이지를 확인합니다. 생성 알림이나 템플릿 미리보기만으로 판매·정산·학생 수강 준비가 끝났다고 판단하지 않습니다.

**진행 순서:** 기존 계정 확인 → 플랫폼 가입/로그인 → 새 사이트 또는 설정 계속하기 → 이름·주소 → 운영정보 → 템플릿 → 플랜 시작 결과 → 관리페이지 확인

## 시작 전 준비 <a href="#before-you-start" id="before-you-start"></a>

| 준비할 것 | 확인 기준 |
| --- | --- |
| 사용할 계정 | 사이트 소유자가 관리할 플랫폼 계정. 기존 가입 이메일·소셜 방식을 먼저 확인합니다 |
| 인증 수단 | 본인이 수신할 수 있는 이메일·휴대폰. 인증번호·비밀번호를 다른 사람에게 맡기지 않습니다 |
| 사이트 이름 | 예: `예시교육`. 표시할 이름과 주소를 구분합니다 |
| 사이트 주소 | 예: `example-academy`. 사용할 주소를 생성 전에 확정합니다 |
| 대표 과목·설명 | 대표 강의과목과 필요한 경우 120자 이내의 짧은 사이트 설명 |
| 초기 공개 범위 | 개인정보·학생 명단·유료 자료를 템플릿/샘플 내용에 넣지 않습니다. 새 사이트 자동 발행 가능성을 먼저 확인합니다 |

이 문서는 수강생의 학원 사이트 회원가입 안내가 아닙니다. 수강생의 가입·로그인은 수강생 가이드의 [회원가입·로그인하기](https://klekit.gitbook.io/learner-guide/account/signup-and-login), 기존 사이트의 직원 지정은 [운영자 지정·역할 관리하기](../members-and-operations/operator-assignment-and-roles.md)를 확인합니다. 이미 사이트가 있다면 새 사이트를 만드는 대신 해당 사이트의 관리 경로와 역할을 먼저 확인합니다.

## 1. 플랫폼 계정으로 가입하거나 로그인하기 <a href="#step-1" id="step-1"></a>

1. 클킷 플랫폼의 **회원가입 / 로그인** 화면에서 현재 사용할 계정을 확인합니다. 학원 수강생 로그인 화면과 구분합니다.
2. 기존 계정이 있다면 원래 사용한 이메일 또는 소셜 방식으로 로그인합니다. 같은 이름이나 연락처라고 다른 가입 방식의 계정이 자동으로 합쳐지는 것은 아닙니다.
3. 새 계정이 필요하면 **이메일 간편회원가입 / 카카오 간편회원가입 / 구글 간편회원가입** 중 제공되는 방식을 선택합니다.
4. 이메일 가입은 이메일 인증 뒤 추가 정보를 입력합니다. 이름·휴대폰 인증·비밀번호 조건과 필수 동의/선택 수신 동의를 구분합니다. 소셜 가입도 제공 정보에 따라 이메일 인증이나 추가 정보가 필요할 수 있습니다.
5. 최종 가입 후 본인 계정으로 로그인된 결과를 확인합니다. 인증 완료와 계정 생성·로그인 완료는 다릅니다.

이메일 가입에서는 계정 생성 후 로그인도 이어서 처리됩니다. 중간에 오류가 나도 **계정이 전혀 생성되지 않았다고 단정해 다시 가입하지 않습니다.** 기존 가입 여부와 정상 로그인 경로를 먼저 확인합니다. 인증번호가 입력되거나 소셜 창이 열렸다는 사실만으로 인증 완료가 된 것은 아닙니다. 완료 표시와 실제 로그인 결과를 확인하세요.

> **화면 예시 준비 중** · 플랫폼 계정과 학원 수강생 계정을 구분합니다.

> **화면 예시 준비 중** · 인증 완료와 가입·로그인 완료는 별도 단계입니다.

## 2. 새 사이트와 중단한 설정 구분하기 <a href="#step-2" id="step-2"></a>

플랫폼의 **운영중인 홈페이지** 목록에서 같은 이름·주소의 사이트가 이미 있는지 확인합니다. 목록 제목만으로 모든 항목이 활성 상태라고 판단하지 않습니다.

| 보이는 상황 | 이어서 할 일 | 구분할 것 |
| --- | --- | --- |
| 새 사이트를 만들 목적이고 기존 대상이 없음 | **새 페이지 만들기**로 사이트 생성 화면을 엽니다 | 여기서 말하는 페이지는 새 사이트입니다. 기존 사이트 안의 안내 페이지 추가가 아닙니다 |
| 초기 설정 중인 대상 사이트가 있음 | 해당 사이트의 **설정 계속하기**로 이어갑니다 | 기존 사이트를 삭제하거나 같은 사이트를 다시 만들지 않습니다 |
| 이미 시작한 사이트가 있음 | 해당 사이트의 **관리페이지**로 이동합니다 | **홈페이지**는 방문자 화면이며 관리자 진입과 다릅니다 |
| 목록 조회 오류·대상이 불명확함 | 계정·조회 결과부터 확인합니다 | 빈 목록이나 오류를 근거로 중복 생성하지 않습니다 |

모바일에서는 해당 사이트의 **더보기** 안에 **설정 계속하기 / 관리페이지 / 홈페이지**가 표시될 수 있습니다. 메뉴 이름과 사이트 이름·주소를 함께 확인합니다. **사이트 삭제**는 설정 재개나 진입 오류를 해결하는 버튼이 아닙니다.

> **화면 예시 준비 중** · 기존 사이트 설정은 이어서 진행하고 관리페이지와 홈페이지를 구분합니다.

## 3. 사이트 이름·주소 확인하고 생성하기 <a href="#step-3" id="step-3"></a>

**강좌 사이트 개설**에서 다음을 입력합니다.

| 항목 | 입력 기준 |
| --- | --- |
| 강의 사이트 이름 | 한글·영문·숫자·공백 2~30자. 특수문자·연속 공백을 피합니다 |
| 강의 사이트 주소 (URL) | 영문 소문자·숫자·하이픈 3~50자. 처음과 끝은 영문/숫자이며 연속 하이픈·숫자만의 주소·예약어는 사용할 수 없습니다 |
| 주소 미리보기 | 주소 칸에는 `example-academy`처럼 식별 부분만 입력합니다. `https://`나 도메인 접미사를 함께 넣지 않고 화면의 전체 주소를 확인합니다 |
| 중복 안내 | 이름과 주소 각각의 중복 오류를 확인합니다. 화면의 형식 검사 통과가 실제 주소 확보를 뜻하지 않습니다 |

1. 이름·주소와 미리보기의 오탈자를 확인합니다.
2. **다음**을 누르면 **사이트 주소 확인** 창이 열립니다. 창 진입은 사이트 생성 완료가 아닙니다.
3. **생성 이후 주소를 변경할 수 없다는 안내**를 읽습니다. 확정하지 못했다면 **취소**로 돌아갑니다. 사이트 이름 수정과 주소 변경은 다릅니다.
4. 실제로 생성할 대상이 맞을 때만 **사이트 생성하고 계속하기**를 누릅니다. 이 버튼은 실제 사이트를 만드는 요청입니다.
5. 생성 안내 뒤 운영정보 단계와 플랫폼의 해당 사이트 기록을 대조합니다. 이후 단계가 남아 있으므로 사이트 운영 시작까지 완료된 것으로 안내하지 않습니다.

생성 요청이 끊기거나 오류가 나면 기존 사이트 목록·설정 계속하기를 먼저 확인합니다. 이름/주소를 바꿔 반복 생성하거나 기존 사이트를 삭제해 다시 시작하지 않습니다. 앞 단계가 저장된 사이트에서는 이름·주소 입력이 잠길 수 있습니다.

> **화면 예시 준비 중** · 주소를 확정한 뒤 실제 사이트 생성 여부를 결정합니다.

> **동작 예시 준비 중** · 주소 확인 창에서 취소하는 예시이며 사이트 생성 완료가 아닙니다.

## 4. 대표 과목·사이트 설명 저장하기 <a href="#step-4" id="step-4"></a>

1. **운영정보 설정**에서 필수 **대표 강의과목**을 선택합니다.
2. 필요한 경우 **사이트 설명**을 120자 이내로 작성합니다. 예: `수학 강좌와 학습 자료를 제공하는 예시교육입니다.`
3. **다음**을 누른 뒤 운영정보 저장 안내와 다음 단계의 대상을 확인합니다. 입력만 하거나 **이전**으로 이동한 것을 저장 완료로 보지 않습니다.

이 단계의 사이트 설명과 생성 후 [사이트 기본 정보·SEO 설정](../site-and-communication/site-basic-information.md)은 구분합니다. 화면은 설명을 SEO 메타데이터로 활용한다고 안내하지만, **저장만으로 검색 결과·공유 문구·홈페이지 본문까지 모두 반영됐다고 판단하지 않습니다.** 생성 후 실제 저장값과 방문자 결과를 별도로 확인합니다.

> **화면 예시 준비 중** · 운영정보 저장과 검색·방문자 반영은 별도로 확인합니다.

## 5. 템플릿과 플랜 시작 구분하기 <a href="#step-5" id="step-5"></a>

| 단계 | 확인할 것 | 뜻하지 않는 것 |
| --- | --- | --- |
| 템플릿 선택 | 사용할 템플릿을 고르고 **완료** 후 플랜 선택 단계로 이동하는지 확인 | 템플릿 미리보기가 실제 강좌·판매 상품·주문 데이터임 |
| Free 시작 | **무료로 시작하기**에서 사이트를 확인하고, 최종 **Free 플랜으로 시작**은 실제 활성화 요청임을 확인 | 상위 플랜 14일 체험 신청·상품 판매 준비 완료 |
| 유료 시작 | 실제 선택 플랜·금액·결제수단과 신청 결과를 확인 | 카드 등록·선택만으로 구독이나 청구가 완료됨 |

현재 확인한 Free 시작은 **카드 등록이나 체험 종료일 없이 기본 Free 플랜으로 시작하는 흐름**입니다. [상위 플랜 14일 체험](../subscription-and-usage/plan-trial-and-subscription-start.md)과 혼동하지 않습니다. 유료 시작의 가격·카드·청구 조건은 플랫폼의 초기 설정 화면에서 다시 확인합니다. 사이트 생성 후에는 [플랜·무료체험과 구독 시작하기](../subscription-and-usage/plan-trial-and-subscription-start.md)와 [구독 결제수단·청구 내역 확인하기](../subscription-and-usage/billing-method-and-payment-history.md)를 참고합니다. 두 가이드에서 설명하는 관리페이지와 초기 설정 화면의 버튼·진행 순서가 같다고 가정하지 않습니다.

**새 사이트는 초기 설정을 마친 뒤 관리자 화면이나 디자인 화면으로 들어가는 과정에서 템플릿이 적용되고 메인 페이지가 자동 발행될 수 있습니다.** 마지막 단계에서 시작하거나 관리페이지로 이동하는 것을 아무 변경도 일어나지 않는 미리보기로 생각하지 않습니다. 초기 내용에 개인정보가 없는지와 공개 범위를 확인합니다. 자동 발행 여부와 사이트 주소로 직접 접속했을 때의 실제 화면을 확인하지 못했다면, 발행 완료나 비공개 유지 어느 쪽도 보장하지 않습니다.

템플릿 선택이 막히거나 적용 결과가 다르면 완료 버튼을 반복해서 누르거나 재가입·새 사이트 생성으로 해결하지 않습니다. 템플릿 연결·실제 발행·유료 결제의 성공 여부는 아직 확인이 필요하므로, **최종 활성화·카드 인증·청구·디자인 화면 진입은 보류**하고 담당자에게 확인합니다.

> **화면 예시 준비 중** · 템플릿 설정, Free 시작, 상위 플랜 체험은 서로 다른 단계입니다.

## 6. 같은 사이트의 관리페이지 확인하기 <a href="#step-6" id="step-6"></a>

1. 플랫폼 목록에서 대상 사이트의 이름·주소·상태·플랜을 대조합니다.
2. PC는 해당 사이트의 **관리페이지**, 모바일은 해당 사이트 **더보기 → 관리페이지**를 사용합니다. **홈페이지**와 구분합니다.
3. 새 탭이 열리면 도착한 사이트 이름·주소와 본인 관리 권한을 확인합니다. 디자인 화면이 먼저 열릴 수 있으므로 관리자 대시보드로만 이동한다고 보장하지 않습니다.
4. 관리자 진입과 방문자 홈페이지의 실제 표시·공개 결과를 따로 확인합니다. 진입 성공은 판매자 승인·상품 판매·학생 이용 준비의 증거가 아닙니다.

관리페이지 이동은 별도 인증과 새 탭 이동을 포함합니다. 인증 주소·SSO 토큰을 공유하거나 저장한 복귀 주소를 재사용하지 않습니다. 탭이 열리지 않거나 권한 오류가 나면 대상 사이트·로그인 계정·브라우저 안내와 기존 결과를 먼저 확인하고, 사이트 재생성·타인 계정 사용·브라우저 보안 전체 해제로 우회하지 않습니다.

> **화면 예시 준비 중** · 같은 사이트의 관리페이지와 방문자 화면을 따로 확인합니다.

## 자주 막히는 부분 <a href="#troubleshooting" id="troubleshooting"></a>

| 상황 | 먼저 확인할 것 |
| --- | --- |
| 가입 오류 뒤 다시 가입하려고 해요 | 계정 생성 뒤 로그인 단계만 실패했을 수 있습니다. 기존 가입 방식과 정상 로그인 결과부터 확인합니다 |
| 새 페이지 만들기가 기존 사이트의 페이지 추가인가요 | 플랫폼에서는 새 사이트 생성 진입입니다. 기존 사이트 내부 페이지 추가는 [페이지·메뉴](../site-and-communication/pages-and-menus.md)로 구분합니다 |
| 설정 중인 사이트가 목록에 있어요 | 같은 사이트의 설정 계속하기를 사용합니다. 삭제·중복 생성으로 다시 시작하지 않습니다 |
| 이름/주소가 사용 중이거나 입력이 잠겼어요 | 중복 오류의 대상과 이미 생성된 사이트 여부를 확인합니다. 주소 변경 가능을 임의로 약속하지 않습니다 |
| 템플릿에서 완료를 눌렀는데 아직 플랜 선택이에요 | 템플릿 설정과 사이트 활성화가 다른 단계입니다. 마지막 요청·기존 상태부터 확인합니다 |
| Free 시작이 14일 체험인가요 | 기본 Free 시작과 상위 플랜 체험은 다릅니다. 현재 적용 플랜을 확인합니다 |
| 시작 후 새 탭이 안 열리거나 다른 화면이 보여요 | 같은 사이트의 생성/활성 상태와 관리페이지 이동·권한·브라우저 안내를 구분합니다. 재생성·반복 결제하지 않습니다 |
| 게시 버튼을 누르지 않았는데 홈페이지가 보여요 | 새 사이트 템플릿의 자동 발행 가능성을 확인합니다. 메인 공개·상품 판매·커스텀 페이지 공개를 같은 상태로 보지 않습니다 |

문의에는 로그인 방식, 대상 사이트 이름·공개 주소, 막힌 단계·오류 문구·발생 시각·기기/브라우저와 이미 확인한 결과를 적습니다. **비밀번호·인증번호·계좌/카드 전체 번호·SSO/소셜 복귀 주소·토큰은 보내지 않습니다.** 실제 플랫폼 문의 경로·운영 시간은 아직 확인이 필요합니다.

## 완료 후 확인 <a href="#completion-checklist" id="completion-checklist"></a>

- [ ] 플랫폼 계정과 학원 수강생 계정을 구분했습니다.

- [ ] 사이트 생성과 운영정보/템플릿/플랜 시작의 저장 결과를 구분했습니다.

- [ ] 같은 사이트의 관리페이지와 방문자 홈페이지 결과를 별도로 확인했습니다.
- [ ] 템플릿 자동 발행 가능성과 실제 공개 결과를 확인했습니다.
- [ ] 오류·응답 유실 때 중복 가입/사이트 생성·삭제·재결제하지 않았습니다.
