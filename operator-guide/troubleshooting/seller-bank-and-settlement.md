# 판매자·계좌·정산 문제

<figure><img src="../.gitbook/assets/branding/page-headers/troubleshooting/seller-bank-and-settlement-v2.png" alt="판매자 등록·계좌·정산에 문제가 있어요 대표 이미지"><figcaption></figcaption></figure>

**강사·질답 조교라면:** 먼저 학원 사이트·로그인 계정과 오류 문구를 확인하세요. 해결되지 않으면 사이트·신청 또는 정산 회차와 표시 문구를 학원 운영자에게 전달합니다. 비밀번호·인증번호나 학생 개인정보 원문은 보내지 않습니다. 아래 상세 점검과 설정·거래 처리는 해당 업무 담당자를 위한 안내이며, 문의를 받은 것만으로 실행 권한이 생기는 것은 아닙니다.

판매자 신청이 진행되지 않거나, 계좌 인증 결과와 외부 반영 결과가 다르거나, 정산 금액·지급·명세서를 확인할 수 없을 때 운영자가 확인할 순서입니다. **사업자 정보 저장·계좌 인증·판매자 신청·심사 승인·정산 확정·외부 지급 접수·실제 지급 완료는 서로 다른 결과**입니다.

같은 사이트의 판매자와 원 신청/계좌 변경 또는 정산 회차부터 확인하세요. 성공 알림이나 연결 끊김만으로 결과를 확정해 재신청·재인증·재지급을 반복하지 않습니다. 정산 금액을 맞추려고 과거 주문·환불·계좌·정산 기록을 임의로 변경하지 않습니다.

> **문제 해결 시 주의**
> 관련 안내의 정상 절차를 오류 복구 방법으로 처음부터 반복하지 마세요. 먼저 같은 주문·파일·신청의 최신 결과를 확인하고 본문의 실행 보류 조건을 따르세요.

| --- | --- | --- |
| 정산 설정이 안 열리거나 계속 불러오는 중이에요 | 사이트·조회 권한·조회 결과와 오류 | 아래 1번 |
| 신청 버튼이 없거나 제출했는데 신청 전으로 보여요 | 소유자/제출 권한·필수 정보·원 제출/외부 반영 결과 | 아래 1번 |
| 보완 항목을 제출했는데 심사 상태가 그대로예요 | 화면 이동·정보 저장·실제 재제출과 최신 심사 결과 | 아래 1번 |

판매자 신청·계좌 변경/인증은 사이트 소유자가 진행하는 업무입니다. 조회 권한과 변경·제출 권한은 다릅니다. 일반 운영자·강사·질답조교가 소유자 계정이나 인증정보를 받아 대신 처리하지 않습니다. 다른 사이트의 금융 정보가 보이면 열람·파일 보관·변경을 중단합니다.

## 1. 판매자 신청·심사·보완 단계 확인하기 <a href="#step-1" id="step-1"></a>

관리자 **결제/정산관리 → 정산 설정**에서 현재 단계를 확인합니다. 사업자 정보는 **운영 → 사이트 운영 정보 → 사업자 정보**와 대조합니다. 번호 인증과 상호·대표자·연락처·주소 저장은 별도 결과입니다.

| 지금 상태 | 확인할 것 | 바로 하지 않을 일 |
| --- | --- | --- |
| 메뉴 없음·조회 실패·계속 로딩 | 같은 사이트/계정·판매자 조회 권한·마지막 정상 조회/오류 | 로딩을 미등록이나 심사 중으로 판단하지 않음 |
| 계좌 등록 필요·신청 전 | 저장된 사업자 정보/번호 인증·계좌 인증과 현재 신청 여부 | 계좌 인증만으로 신청 접수/심사 승인을 안내하지 않음 |
| 제출 버튼 비활성·필수 정보 안내 | 실제 누락 항목·저장/인증 상태·동의·제출 권한 | 표시 문구를 통과시키려고 가짜 정보나 다른 계정으로 제출하지 않음 |
| 신청 제출 안내 뒤 상태가 불명확 | 원 제출 시각·현재 신청 여부·심사/계좌 외부 반영 결과 | 성공 알림만으로 접수 확정하거나 같은 신청을 반복하지 않음 |
| 본인 인증/고객확인(KYC) 필요 | 해당 판매자의 실제 안내·담당 연락처와 필요한 인증 | 안내 문구만으로 이메일 발송/수신을 확정하거나 인증 링크를 공유하지 않음 |
| 보완 요청 | 보완 대상·구체적인 사유와 허용된 후속 제출 경로 | 모든 누락 문구를 서류 파일 문제로 해석하지 않음 |
| 승인 완료인데 판매/지급 불가 | 판매자 최신 자격과 상품 판매 준비·계좌/지급 조건 | 승인 배지를 상품 판매·외부 지급 성공으로 사용하지 않음 |

보완의 **다시 업로드/보완 항목 제출**을 눌러 정보 화면으로 이동했더라도 파일 업로드·정보 저장·재제출이 끝난 것은 아닙니다. 실제 필요한 항목과 저장·제출 결과를 확인합니다. 다시 제출하는 방법을 확인할 수 없으면 소유자와 담당자에게 문의합니다.

사업자등록증·통장 사본이 일반적으로는 선택 제출 서류라는 점과, 실제로 추가 보완을 요청받은 경우는 구분합니다. 확인표에 첨부 항목이 있다고 모두 필수라고 판단하거나, 현재 버튼 제한 때문에 정책을 필수 첨부로 바꾸어 안내하지 않습니다. 심사 예상 기간이나 승인일 표시만으로 승인/지급 기한을 약속하지 않습니다.

정상 준비 기준은 [판매자 등록·심사](../sellers-and-settlements/seller-registration-and-review.md)를 따릅니다. 승인 이후 상품의 판매 준비 문제는 [상품 판매·결제 점검](product-sales-and-payment.md)에서 별도로 확인합니다.

> **화면 예시 준비 중** · 정보 저장·신청·심사 결과를 나눠 확인합니다.

## 2. 계좌 입력·인증·외부 반영 따로 확인하기 <a href="#step-2" id="step-2"></a>

**화면에 계좌 값이 남아 있는 것, 저장된 것, 실명 인증된 것, 외부 정산에 반영된 것은 다릅니다.** 계좌 인증 요청에서도 먼저 입력이 저장될 수 있어, 인증 실패 안내가 나와도 이전 계좌가 그대로 유지됐다고 단정하지 않습니다.

| 상황 | 확인할 것 | 대응 기준 |
| --- | --- | --- |
| 인증 실패인데 새 입력값이 남음 | 저장된 은행/예금주·마스킹한 계좌 끝자리·최신 인증 상태 | 값 존재를 인증 성공으로 보거나 이전 값으로 즉시 덮어쓰지 않음 |
| 저장/인증 성공 알림만 확인됨 | 같은 계좌의 최신 값·인증과 외부 반영 결과 | 저장·인증을 외부 적용/지급 시작으로 안내하지 않음 |
| 첨부 없이 저장 버튼이 비활성 | 통장 사본의 선택 첨부 기준과 현재 화면의 저장 제한·기존 인증 결과 | 통장 사본을 무조건 필수라고 안내하거나 반복 인증으로 우회하지 않음 |
| 신청/승인 후 수정 영역이 안 보임 | 현재 신청 단계·소유자/변경 권한·허용된 변경 경로 | 상세의 계좌 수정 링크만 보고 변경 가능을 확정하지 않음 |
| 지급 진행 때문에 변경 반영 대기 | 해당 지급 건과 새 계좌의 저장/인증/반영 단계 | 진행 지급을 실패 처리하거나 다른 계좌를 재제출하지 않음 |
| 외부 결과 확인 중·연결 끊김·동시 변경 | 원 요청 시각·최신 입력/적용 상태·다른 담당자의 선행 변경 | 인증/신청/계좌 저장을 반복하지 않음 |

은행·계좌·예금주가 일치하는지 확인하되 **전체 번호·생년월일은 해당 인증 화면에서만 다룹니다.** 계좌 유형에 맞는 인증 방법이 없거나 지원 은행/예금주 조건을 확인할 수 없으면 임의로 다른 정보를 선택하지 않습니다.

화면의 **인증 초기화**나 편집 취소도 외부 계좌 반영 취소·이전 계좌 복원의 증거가 아닙니다. 저장/인증/변경 결과가 서로 다르면 최신 조회와 원 요청을 담당자가 대조합니다. 외부 반영 여부를 확인하기 위해 내부 기록을 대조하거나 재처리를 요청하는 일은 단순 조회와 다릅니다. 이를 사용자가 직접 누를 수 있는 복구 버튼처럼 안내하지 않습니다.

현재 입력 계좌·적용된 계좌·지급 요청 당시 계좌는 아래 5번처럼 구분합니다. 계좌 등록·변경 절차는 [정산 계좌 등록·변경](../sellers-and-settlements/settlement-bank-account.md)에서 확인합니다. 화면에 없는 계좌 상태/버전 표시를 있다고 가정하지 않습니다.

> **화면 예시 준비 중** · 계좌 저장·인증과 외부 반영은 다릅니다.

## 3. 같은 정산월·회차 찾기 <a href="#step-3" id="step-3"></a>

관리자 **결제/정산관리 → 정산 내역**에서 대상 정산월과 회차를 찾습니다. 현재 목록의 쪽당 개수·페이지를 확인하고 같은 월에 여러 내역이 있으면 상세의 대상·금액도 대조합니다.

1. 의도한 사이트·판매자의 정산 내역인지 확인합니다. 판매자 조회와 정산 조회 권한은 별도입니다.
2. 정산월·표시 기간·해당 회차 식별정보를 확인하고 다른 페이지도 비교합니다.
3. 상세의 정산월·원 주문/거래 근거·조회 시각을 대조합니다. 주문 구매월만으로 정산 회차를 정하지 않습니다.
4. 조회 오류·상세 찾기 실패·빈 목록·아직 생성 여부를 확인하지 못한 회차를 나눕니다.

| 확인한 결과 | 다음에 확인할 것 | 단정하지 않을 것 |
| --- | --- | --- |
| 목록/상세 조회 오류 | 권한·대상 회차·오류와 마지막 정상 조회 | 오류를 정산 0원·대상 없음·미판매로 해석하지 않음 |
| 목록에 회차가 없음 | 다른 페이지·대상 월/판매자와 회차 생성/포함 여부 | 새 정산 생성·확정이 필요하다고 바로 판단하지 않음 |
| 날짜/기간이 기대와 다름 | 정산월의 한국 시간 기준 범위와 원 거래 시각 | 표시 끝 날짜만 보고 다른 회차나 거래 누락으로 확정하지 않음 |
| 예상/확정 구분이 안 보임 | 같은 회차의 확정 여부·버전·근거를 담당자에게 확인 | 화면 금액을 곧바로 확정 지급액으로 사용하지 않음 |

정산월의 기간은 한국 시간 기준 해당 월 시작부터 다음 달 시작 전까지입니다. 표시된 날짜·거래 페이지와 전체 회차를 구분하고, 이전 거래의 정산 포함 여부는 해당 회차 근거로 확인합니다. 목록·페이지에서 대상 회차를 찾고 상세를 확인합니다. 기간·정렬·예상 금액 조회 기능이 필요하면 제공 여부를 담당자에게 확인합니다.

정상 확인 기준은 [정산 금액·지급 상태](../sellers-and-settlements/settlement-amount-and-payout-status.md)를 따릅니다. 필요한 정보가 보이지 않으면 같은 회차를 특정해 문의하고, 임의 주소 입력이나 다른 사이트의 회차를 열어 비교하지 않습니다.

> **화면 예시 준비 중** · 같은 판매자의 정산월과 회차를 먼저 확인합니다.

> **동작 예시 준비 중** · 기존 회차의 금액과 거래 범위를 확인하는 예시입니다.

## 4. 매출·환불·수수료·세금·전체/페이지 금액 대조하기 <a href="#step-4" id="step-4"></a>

**총 매출·순매출·정산 잔액·지급대상액은 같은 금액이 아닙니다.** 같은 회차의 원 금액 근거와 환불·수수료·이월·보류를 나누어 확인합니다. 현재 상품가나 수수료율로 과거 정산을 다시 계산하지 않습니다.

| 차이가 있는 항목 | 확인할 것 | 피할 대응 |
| --- | --- | --- |
| 매출과 정산액 | 회차에 포함된 매출·환불·수수료/조정·이월과 원장 근거 | 주문 총액에서 임의 비율/세금을 빼서 맞추지 않음 |
| 거래 목록과 전체 합계 | 거래 행/주문 집계의 의미·현재 페이지와 전체 회차 범위 | 보이는 행 수·페이지 금액만으로 전체 누락을 판단하지 않음 |
| 주문별 합계가 필요한 경우 | 해당 회차의 포함 주문 근거·전체/현재 페이지 합계 제공 여부 | 기존 거래 행을 주문별 통합 표라고 설명하거나 수수료를 주문 순매출과 섞지 않음 |
| 세금/이름/금액이 없거나 0원처럼 보임 | 실제 0원·기록 누락·표시/조회 실패와 원 근거 | 누락된 세금/이름을 현재 값이나 0으로 채우지 않음 |
| 환불액·남은 금액 차이 | 해당 원 주문의 환불 처리 결과 확정(금융 확정)과 이번 회차에 반영된 범위 | 환불 응답/현재 결제 잔액만으로 회차 금액을 덮어쓰지 않음 |
| 지급대상액 0·음수 잔액/이월 | 지급 필요 여부·음수 잔액·확정/보류와 후속 회차 근거 | 0원을 지급 완료로, 양수 지급 실패액을 자동 이월로 설명하지 않음 |
| 거래·금액 대조(대사)/근거 확인 필요 | 원장/요약·세금/결제대행사(PG) 수수료 근거와 보류 사유 | 임의 정산 조정·원 주문 수정·재확정으로 통과시키지 않음 |

페이지별 합계와 전체 합계가 제공된다면 의미를 확인하고 비교합니다. 페이지를 바꿀 때 반복되는 전체 회차 금액을 더하면 중복됩니다. 주문번호/상호 같은 과거 기록이 없으면 기록 없음으로 남기고 현재 이름으로 복원하지 않습니다.

화면의 **강좌 명/거래요약** 같은 제목만으로 모든 행을 강좌 하나·주문 하나라고 판단하지 않습니다. 교재·자료·혼합 주문의 원 거래와 구성품 근거를 구분합니다. 상세에 없는 주문별 표·보류/세금 근거가 필요하면 담당자가 같은 회차의 제공 가능한 범위를 확인합니다.

금액 불일치나 근거 부족을 조회만으로 해결됐다고 표시하지 않습니다. 환불 진행 자체의 문제는 [취소·반품·교환 점검](cancellation-return-and-exchange.md)을 참고해 별도로 전달합니다.

> **화면 예시 준비 중** · 같은 회차의 금액 구성과 집계 범위를 구분합니다.

## 5. 정산 확정과 지급 접수·예약·완료 구분하기 <a href="#step-5" id="step-5"></a>

정산 확정은 금액의 확정이며 입금 완료가 아닙니다. **정산 집계/확정일·지급 요청일·예약일·외부 결과 확인 시각·실제 완료일**을 따로 확인합니다. 시간이 지났다는 이유만으로 지급 성공/실패·예약 접수를 추정하지 않습니다.

| 상황 | 확인할 것 | 대응 기준 |
| --- | --- | --- |
| 정산 확정·입금 확인 안 됨 | 같은 회차의 지급 필요/보류·외부 요청 접수 여부·최신 지급 건 | 명세서·금액 확정만으로 입금됐다고 안내하지 않음 |
| 지급 대기·진행 | 미요청/준비·외부 접수·예약·진행 중 가운데 현재 확인된 단계 | 내부 요청 생성·날짜 경과를 외부 접수/완료로 보지 않음 |
| 지급 예정일을 알고 싶음 | 외부 접수가 확인된 실제 예약 근거와 대상 지급 건 | 정산월/확정일·임의 소요일로 입금일을 만들지 않음 |
| 지급 실패/결과 확인 중 | 같은 지급 건의 최신 확인 결과·실패 근거와 이후 시도 | 과거 실패만으로 현재 실패 확정·즉시 재지급 요청하지 않음 |
| 지급 완료 표시와 은행 확인이 다름 | 해당 회차·지급 건/금액·확인된 완료일·요청 당시 계좌와 실제 수취 확인 | 완료 배지나 계좌 끝자리만으로 판매자의 실제 입금을 대신 확정하지 않음 |
| 계좌가 없거나 이전 값으로 보임 | 아래 세 계좌 구분·반영/지급 상태·조회 결과 | 계좌를 다시 저장하거나 지급 이력을 현재 계좌로 바꾸지 않음 |

| 계좌 구분 | 확인할 의미 |
| --- | --- |
| 현재 입력한 계좌 | 저장·인증하려는 현재 정보. 외부 반영 완료와 별개 |
| 지급에 사용할 계좌 | 최신 인증과 외부 반영이 확인된 해당 계좌 |
| 지급 요청 당시 계좌 | 해당 지급 시도에 보존된 정보. 이후 입력 변경으로 바뀌는 과거 이력이 아님 |

상세의 **지급 계좌 정보** 한 영역만으로 세 계좌와 모든 지급 시도를 확인할 수 있는 것은 아닙니다. `계좌 정보 수정하기`로 이동할 수 있어도 신청 이후 편집·변경 반영·과거 지급 변경을 보장하지 않습니다. 지급 진행 또는 외부 결과 확인 중에는 계좌 반영이 보류될 수 있으므로 원 결과부터 확인합니다.

‘승인 완료’, ‘정산 가능’, ‘연동 정상’ 안내도 해당 회차의 지급 거래 성공 증거가 아닙니다. 지급 결과가 불명확하면 같은 회차·최신 지급 건을 담당자가 확인하고, 중복 지급·계좌 재제출·외부 지급 직접 요청을 해결책으로 쓰지 않습니다.

> **화면 예시 준비 중** · 정산 확정과 실제 지급 결과·당시 계좌를 구분합니다.

## 6. 정산명세서·PDF·다른 금융 문서 구분하기 <a href="#step-6" id="step-6"></a>

명세서/PDF가 필요하면 **같은 사이트·판매자·정산 회차·확정 버전**을 먼저 확인합니다. 정산명세서, 정산 조회/CSV, 구매자 영수증·거래명세서, 세금계산서는 목적과 범위가 다릅니다. 명세서 발급 여부와 실제 지급 결과도 따로 확인합니다.

| 상황 | 확인할 것 | 피할 대응 |
| --- | --- | --- |
| 명세서/PDF 버튼이 없음 | 현재 화면의 제공 경로·권한과 필요한 회차/문서 | 내부 경로·파일 주소 직접 입력·브라우저 인쇄를 정식 발급으로 안내하지 않음 |
| 미확정·버전 없음으로 제한 | 같은 회차의 확정 여부·확정 버전과 과거 기록 | 문서를 얻으려고 정산을 새로 생성/확정하거나 버전을 임의 입력하지 않음 |
| 버전/금액 변경·문서와 상세 불일치 | 같은 확정본/대상·확정 시각·문서 종류와 금액 근거 | 이전 문서를 자동 최신본으로 사용하거나 다른 회차 PDF로 대체하지 않음 |
| 정산 근거 부족·금액/내역 불일치·PDF 생성 오류 | 오류 종류·대상 회차/버전·발생 시각과 마지막 결과 | 원 금융값을 수정하거나 파일을 편집해 정상본으로 만들지 않음 |
| 파일을 받았는데 열리지 않음·내용 누락 | 확인된 제공 결과·파일 종류·같은 버전·기기에서 실제 열림/페이지 | 다운로드 안내만으로 기기에 파일을 저장하고 열어 내용을 확인했다고 보지 않음 |
| 세금계산서 없음·구매자 영수증 필요 | 필요한 문서의 대상과 확인된 제공 경로 | 세금계산서 영역을 자동 발행 기능으로 보거나 정산 PDF로 구매자 영수증을 대신하지 않음 |

‘정산 명세서의 금융 근거가 일치하지 않습니다’라는 안내는 확정된 정산 금액·내역 등 자료의 검증을 통과하지 못했다는 뜻입니다. 내려받은 PDF가 열리지 않는 문제와는 구분합니다.

예전 안내나 화면에 파일 버튼 설명이 있어도 현재 해당 회차에서 제공되는지 다시 확인합니다. CSV가 제공되는 경우에도 전체 회차/현재 페이지·요약 중 범위를 확인하며 **CSV를 정산명세서 PDF로 바꾸어 안내하지 않습니다.** 확인되지 않은 다운로드 버튼을 안내하거나 여러 페이지의 반복 요약액을 합쳐 전체 명세서로 쓰지 않습니다.

명세서의 상호·기간·금액은 같은 확정본으로 대조합니다. 이후 바뀐 사업자명/계좌·현재 상품가로 과거 문서를 맞추지 않습니다. 파일의 실제 제공·보관/공유는 승인된 경로에서 진행하고 전체 금융 문서나 인증된 다운로드 주소를 일반 문의에 첨부하지 않습니다.

상세 기준은 [정산명세서·PDF 확인](../sellers-and-settlements/settlement-statement-and-pdf.md)을 참고합니다. 현재 화면에서 필요한 문서를 확인할 수 없으면 대상 회차·필요한 범위와 오류만 담당자에게 전달합니다.

> **화면 예시 준비 중** · 같은 확정본과 문서 종류·파일 결과를 대조합니다.

## 7. 기다릴 조건과 문의할 조건 정리하기 <a href="#step-7" id="step-7"></a>

원 신청·계좌 변경·지급 건의 처리/반영 대기가 확인됐을 때만 해당 결과를 기다립니다. 조회 오류·정보 누락·권한 제한·버튼 미제공·과거 근거 부족을 모두 심사 지연으로 묶지 않습니다. 심사 승인·계좌 적용·지급·문서 제공 기한이나 자동 복구를 임의로 약속하지 않습니다.

| 문의로 넘길 상황 | 전달할 정보 |
| --- | --- |
| 신청/보완·상태 불명확 | 사이트·원 제출 시각·현재 단계·누락/보완 문구·저장/제출 등 이미 한 행동 |
| 계좌 인증/반영·변경 보류 | 소유자/담당 역할·은행/마스킹 끝자리·저장/인증/반영 구분·원 요청 시각/오류 |
| 회차·금액/세금/합계 차이 | 정산월/회차·예상/확정 여부·전체/현재 페이지 범위·차이가 있는 항목 |
| 지급/입금·과거 계좌 차이 | 같은 회차/지급 건·금액·확인된 요청/예약/완료·당시 계좌와 현재 계좌의 구분 |
| 명세서/PDF 제공·버전/파일 문제 | 필요한 문서·같은 회차/확정 버전·오류/시각·기기/열기 결과 |

강사·질답조교는 학원의 지정 운영자에게, 운영자는 판매자 신청/계좌 업무를 소유자와 확인하고 해결되지 않으면 확인된 클킷 지원 경로로 문의합니다. 대표자 인증·은행/PG 확인이 필요하면 확인된 공식 경로를 따릅니다. 로그인·인증정보를 전달하거나 비공식 계좌/파일 링크로 해결하지 않습니다.

가상 문의 예시:

> 계좌 인증 안내 뒤 판매자 신청을 제출했지만 다시 열면 신청 전으로 보입니다. 원 제출 시각·최신 신청/인증 안내와 오류를 정리했고 재신청·재인증은 하지 않았습니다. 원 제출과 계좌 외부 반영 결과를 나누어 확인해 주세요.

> 같은 정산 회차의 확정 금액은 확인했지만 실제 입금은 확인되지 않았고 상세에 이전 계좌가 보입니다. 원 회차·지급 건/금액·계좌 끝자리와 확인 시각을 정리했으며 계좌 재저장·재지급 요청은 하지 않았습니다. 현재 입력 계좌와 해당 지급 당시 계좌, 최신 지급 결과를 구분해 확인해 주세요.

> **화면 예시 준비 중** · 원 요청과 마지막 결과·이미 한 일을 전달합니다.

식별정보·금액·계좌 끝자리는 확인된 비공개 지원 경로에 필요한 최소한으로 제공합니다. **비밀번호·인증번호·토큰·생년월일·전체 계좌/카드번호·학생 명단·대표자 연락처/주소·사업자/통장 서류 원문·금융 문서 전문·PG/인증/다운로드 URL·개발자 도구·네트워크 요청 기록 원문은 일반 문의에 보내지 않습니다.** 저장 기록·심사 상태를 임의로 고치거나 결제대행사의 판매자 정보를 삭제·재등록하지 않습니다. 정산 재확정·중복 지급·내부 금액 대조/재처리 작업도 이 안내의 해결 절차가 아니므로 담당자에게 확인을 요청하세요.

## 완료 후 확인 <a href="#completion-checklist" id="completion-checklist"></a>

- [ ] 정보 저장·번호/계좌 인증·원 신청·심사/보완 결과와 화면 이동을 나눴습니다.

- [ ] 매출·환불·수수료·세금·이월 금액의 원래 근거를 확인했습니다. 실제 금액이 0원인 경우와 기록이 누락된 경우도 구분했습니다.
- [ ] 거래/주문 집계·전체 합계/현재 페이지와 화면 제공 범위를 확인했습니다.
- [ ] 정산 확정·외부 지급 접수/예약·최신 지급 결과와 실제 수취 확인을 구분했습니다.
- [ ] 현재 입력·적용된 계좌·지급 요청 당시 계좌를 나눠 확인했습니다.
- [ ] 명세서 회차/확정 버전·PDF/CSV/영수증/세금계산서와 실제 파일 결과를 구분했습니다.
- [ ] 원 결과 확인 전 재신청/재인증/재지급하지 않고 최소 정보로 문의를 준비했습니다.
