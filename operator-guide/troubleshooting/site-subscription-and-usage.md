# 사이트 접근·구독·사용량에 문제가 있어요

> **검토용 가이드** · 실제 서비스 화면·동작 확인과 이미지 보완이 남아 있습니다. 본문의 실행 보류·주의사항을 먼저 확인하세요.

사이트나 관리 메뉴에 접근하지 못하거나, 저장한 내용이 보이지 않거나, 구독 변경·카드 등록·사용량/팩 처리가 막혔을 때 운영자가 확인할 순서입니다. **계정 로그인·역할 권한·사이트 운영 상태·페이지 게시/노출·구독/결제 상태·사용량 한도는 서로 다른 조건**입니다.

같은 학원 사이트·계정·문제 대상과 마지막 요청부터 확인하세요. 접근 문제를 해결하려고 다른 계정으로 우회하거나 권한·플랜·공개 범위를 먼저 바꾸지 않습니다. 저장/청구 결과가 불명확하면 같은 요청을 반복하기 전에 최신 상태를 확인합니다.

> **문제 해결 시 주의**
> 관련 안내의 정상 절차를 오류 복구 방법으로 처음부터 반복하지 마세요. 먼저 같은 주문·파일·신청의 최신 결과를 확인하고 본문의 실행 보류 조건을 따르세요.

## 1. 사이트·계정·역할과 접근 범위 확인하기 <a href="#step-1" id="step-1"></a>

1. 의도한 학원 사이트 주소와 로그인한 계정·로그인 방식을 대조합니다. 다른 사이트에서 같은 이메일을 쓴다는 이유로 같은 권한이 있다고 판단하지 않습니다.
2. 관리자 접근·일반 방문자 접근·학생의 구매 강좌/자료 이용 중 어떤 문제인지 나눕니다.
3. 현재 역할과 해당 업무의 조회/작성/변경 권한·담당 강좌 범위를 확인합니다. 메뉴가 보이는 것과 요청이 허용되는 것은 다릅니다.
4. 조회 오류·인증/권한 거절·기능 제한·정상적으로 빈 목록을 구분하고 발생 시각과 마지막 정상 결과를 기록합니다.

| 상황 | 확인할 것 | 피할 대응 |
| --- | --- | --- |
| 로그인/계정 확인 실패 | 본인 계정·로그인 방식·확인한 오류와 대상 사이트 | 비밀번호/인증번호를 받거나 다른 계정으로 대신 로그인하지 않음 |
| 메뉴 없음·버튼 비활성 | 업무별 권한·소유자 여부·현재 상태/플랜과 오류 | 주소·내부 요청·공유 로그인으로 접근을 우회하지 않음 |
| 운영자는 보는데 강사/질답조교는 못 봄 | 실제 역할/세부 권한·담당 대상·비밀/소유 범위 | 역할 이름만 보고 모든 조회/답변 권한을 부여하지 않음 |
| 강좌가 일부만 보이거나 담당 변경 필요 | 원 담당 목록의 전체 수/선택·다음 후보 페이지·이관 영향 | 현재 보이는 일부 강좌만 다시 저장하거나 임의 공동 담당으로 바꾸지 않음 |
| 관리자 화면과 학생 결과가 다름 | 계정 역할·해당 주문/수강권·공개/접근 조건 | 관리자 미리보기를 학생 권리/실제 이용 성공으로 사용하지 않음 |
| 타인/다른 사이트 정보가 보임 | 열람 범위·대상·발생 시각과 최소 오류 정보 | 추가 열람·공유·내보내기를 중단하고 담당자에게 전달 |

담당 강좌 **후보를 더 불러오는 것과 기존 전체 선택을 보존하는 것은 별개**입니다. 전체 담당 범위가 확인되지 않은 상태에서는 역할/담당 강좌 변경을 멈추고 담당자에게 확인합니다. 일부 목록이 보인다고 서비스의 강좌 상한이나 삭제 결과로 해석하지 않습니다.

정상 확인은 [운영자 지정·역할 관리](../members-and-operations/operator-assignment-and-roles.md)를 따릅니다. **학생의 로그인 문제**는 수강생 가이드의 **학생 계정 점검**으로 연결합니다. 운영자·플랫폼 계정의 로그인에는 학생용 복구 절차를 그대로 적용하지 않고 해당 계정/로그인 방식과 공식 안내를 담당자가 확인합니다. 구매 후 접근은 [영상·자료·수강권 점검](video-resource-and-access.md)과 구분합니다. 학생에게 관리자 권한을 주거나 수강권을 재지급해 해결하지 않습니다.

> **화면 예시 준비 중** · 같은 사이트의 계정·업무 권한과 전체 담당 범위를 확인합니다.

## 2. 저장·게시·공개·메뉴·방문자 결과 나누기 <a href="#step-2" id="step-2"></a>

설정 저장·페이지 게시·메뉴 연결·실제 방문자 노출은 같은 결과가 아닙니다. 이미 확인한 최신 상태와 대상/기기를 먼저 비교하고, 보이지 않는다는 이유로 공개 범위를 넓히거나 재게시하지 않습니다.

| 문제 대상 | 확인할 것 | 바로 하지 않을 일 |
| --- | --- | --- |
| 사이트 기본 정보/이미지·SEO | 항목별 저장 결과·최신 값·업로드/반영·권한/플랜 | 한 항목 성공을 전체 저장/외부 검색 반영으로 보지 않음 |
| 페이지/메뉴 | 작업본/게시본·페이지 공개·실제 연결 페이지/주소·메뉴 노출/기기 | 메뉴 없음만으로 페이지 삭제/미게시를 판단하지 않음 |
| 빌더가 다른 페이지를 가리킴 | 요청한 페이지와 실제 선택/저장 대상 | 대상 보호가 확인되기 전 편집 저장·게시·복제로 오류를 재현하지 않음 |
| 공지/게시판·첨부 | 게시 상태·목록/상세·비공개 접근 보호·같은 첨부 결과 | 비공개 보호를 확인하려고 타인 URL/첨부를 열거나 공개로 바꾸지 않음 |
| Q&A 답글/답변 상태 | 대상 질문·답글 작성/상태 변경 권한·기존 답글/최신 상태 | 답글이 안 보인다고 중복 등록·질문 공개·임의 상태 변경하지 않음 |
| 폼 저장/게시·응답 | 최신 저장/오류·게시·연결·접수 기간/대상·응답 조회 | 저장 실패/진행 중에 게시·복제로 우회하거나 테스트 응답을 제출하지 않음 |
| 상담 채널/아이콘 | 저장한 채널·노출 대상/기기·플랜/구독·외부 연결 결과 | 설정 성공을 채널 존재/메시지 수신·자동 학생 식별로 안내하지 않음 |

**질답조교의 주 업무는 Q&A 답변**입니다. 질문 조회·답글 등록·답변 상태 변경·본인 수정은 각각 허용 범위를 확인합니다. 권한 문제 때문에 다른 담당자 계정으로 답변하거나 비밀 질문/이미지를 공개하지 않습니다. 답글 등록 결과와 답변 완료 상태가 다르면 기존 답글부터 확인해 중복 등록을 피합니다.

폼의 자동저장·게시와 상담 채널의 수동 저장도 구분합니다. 저장 실패/충돌이 있으면 편집 내용을 안전하게 보존하고 최신 저장본과 비교할 준비를 합니다. 무작정 새로고침해 미저장 내용을 잃거나, 필수 동의 내용을 확인할 수 없다는 이유로 동의 문항을 삭제해 게시하지 않습니다. 상담 저장 충돌도 최신값이 자동 병합됐다고 판단하지 않습니다.

관련 기준은 [기본 정보](../site-and-communication/site-basic-information.md)·[페이지/메뉴](../site-and-communication/pages-and-menus.md)·[게시판/공지](../site-and-communication/boards-and-notices.md)·[Q&A 답변](../site-and-communication/qna-answer.md)·[폼/응답](../site-and-communication/site-form-create-and-responses.md)·[상담 채널](../site-and-communication/connect-inquiry-channel.md)을 따릅니다. 기존 보류 기능을 이 점검안으로 실행 승인하거나 보호 완료로 바꾸지 않습니다.

> **화면 예시 준비 중** · 저장·게시·권한·실제 방문자 결과를 업무별로 나눕니다.

## 3. 운영 중지·구독 종료 예약·삭제 구분하기 <a href="#step-3" id="step-3"></a>

**사이트 운영 상태, 유료 구독 종료 예약, 사이트 삭제는 서로 다른 업무**입니다. 접근이 안 된다는 이유로 상태를 중지/재개하거나 삭제·재생성하지 않습니다.

| 확인할 상태 | 점검 기준 | 단정하지 않을 것 |
| --- | --- | --- |
| 현재 운영 상태 | 실제 조회 결과·조회 성공 여부와 대상 사이트 | 기본/대체 표시만으로 정상 운영 중이라고 판단하지 않음 |
| 운영 중지/재개 안내 | 운영 상태 변경과 실제 방문자/구매 접근·구독의 각각의 결과 | 중지 안내만으로 모든 공개 차단·즉시 구독 취소·기존 구매자 보호를 확정하지 않음 |
| 구독 종료/Free 예약 | 현재 유료 기간·예약 대상/적용 시점·진행 작업 | 예약 접수를 즉시 사이트 폐쇄·삭제로 설명하지 않음 |
| 삭제 가능/차단 안내 | 소유자·실제 삭제 조건/진행 작업·보안 확인 | 간단한 구독 표시나 버튼 노출을 전체 삭제 가능 판정으로 사용하지 않음 |
| 이미 변경 요청 후 결과 불명확 | 원 요청 시각·최신 운영/구독/예약 결과를 별도 확인 | 같은 중지/재개·구독 종료·삭제 요청을 반복하지 않음 |

**삭제 오류 확인을 위해 삭제 창에 비밀번호를 입력하거나 삭제 요청을 실행하지 않습니다. 현재 삭제 경로의 민감정보 처리와 조건 표시를 해결·검수하기 전 실행 보류를 유지합니다.** 개발자 도구·네트워크 요청 기록 원문을 지원 자료로 요구하거나 공유하지 않습니다.

운영 중지 화면의 안내만으로 실제 비공개 보호나 구독 취소를 보장하지 않습니다. 기존 학생·주문/수강권·금융/응답 기록에 영향이 있을 수 있는 변경은 소유자와 담당자가 별도 범위·조건을 확인합니다. 정상 검토 기준은 [사이트 중지·삭제](../members-and-operations/site-stop-and-delete.md)에 연결합니다.

> **화면 예시 준비 중** · 운영 중지·구독 종료 예약·삭제는 다른 업무입니다.

## 4. 현재 플랜·체험·변경 예약·진행 작업 확인하기 <a href="#step-4" id="step-4"></a>

**플랜 관리**에서 현재 플랜·체험/이용 기간·예약·결제 실패/진행 안내를 나눠 확인합니다. 소유자의 변경 동작과 위임 운영자의 조회 범위는 다를 수 있습니다. 버튼이 없다는 이유만으로 구독 없음·기능 미지원으로 판단하지 않습니다.

| 상황 | 확인할 것 | 피할 대응 |
| --- | --- | --- |
| 체험/유료 시작·플랜 선택이 안 됨 | 소유자·현재 플랜/체험 자격·상태·선택 가능한 대상·기존 진행 작업 | 다른 사이트/계정으로 체험을 다시 시작하거나 반복 신청하지 않음 |
| 견적 만료·조건/금액 변경 | 원 요청 처리 여부·최신 구독/가격/기간·확인한 견적과 오류 | 오래된 견적/동의/금액으로 실행하지 않음 |
| 관리자 유지 선택 필요 | 소유자 포함 대상·전체 관리자 수·담당 강좌/권한 영향 | 일부 관리자/강좌만 확인하고 임의 해제/이관하지 않음 |
| 팩 영향 표시가 없음 | 현재 플랜/팩·변경 후 한도·갱신/종료 영향 | 빈 영향 목록을 팩 영향 없음·한도 보장으로 해석하지 않음 |
| 변경 완료 안내 뒤 현재 플랜이 그대로 | 즉시 적용 결과인지 다음 주기 예약인지·적용/예약 시각 | 공통 성공 알림만으로 플랜이 이미 바뀌었다고 설명하지 않음 |
| 처리 중·결과 확인 불가 | 같은 원 작업의 식별정보·최신 결과·조회 성공 여부 | 새 견적/변경·체험·구독 종료로 재실행하지 않음 |

**견적 생성도 단순 화면 조회와 다릅니다.** 비교/오류 재현용으로 새 견적을 만들거나 최종 변경을 실행하지 않습니다. 정상 업무로 새 견적이 필요한 경우에는 원 요청의 결과부터 확인하고 소유자가 최신 금액·적용 시점·관리자/팩 영향을 다시 판단합니다.

**변경 예약 취소·재결제**는 현재 결과를 읽는 버튼이 아니라 실제 명령입니다. 예약을 취소해 원인을 확인하거나 실패/유예 안내만 보고 재결제하지 않습니다. 체험 만료·유료 기간·다음 결제일·변경 예약 시각도 같은 날짜로 보더라도 각각의 의미를 확인합니다.

정상 기준은 [플랜/무료체험·구독 시작](../subscription-and-usage/plan-trial-and-subscription-start.md)과 [플랜 변경·구독 종료 예약](../subscription-and-usage/plan-change-and-subscription-end-schedule.md)을 따릅니다. 현재 가격·제공량·허용 동작은 해당 사이트의 최신 확인 결과를 사용하고 새 정책 수치를 만들지 않습니다.

> **화면 예시 준비 중** · 원 작업의 처리와 즉시 적용·다음 주기 예약을 구분합니다.

> **동작 예시 준비 중** · 기존 자료에서 플랜·사용량·현재/다음 팩 상태를 나눠 읽습니다.

## 5. 카드 등록·현재 선택·구독 청구 결과 구분하기 <a href="#step-5" id="step-5"></a>

**카드 등록, 사이트에서 사용할 카드 변경, 구독/팩 결제는 별도 결과**입니다. 결제수단을 좌우로 넘겨 본 것·사용 중 표시·변경 성공·실제 청구 당시 카드를 구분합니다. 정산금을 받는 계좌와도 다른 업무입니다.

| 상황 | 확인할 것 | 대응 기준 |
| --- | --- | --- |
| 카드 영역이 없음·카드 없음 표시 | 소유자/현재 플랜·카드 조회 결과와 오류 | 미등록/삭제/미청구로 단정해 재등록하지 않음 |
| 외부 인증 후 카드 등록 실패/중 표시 | 원 등록 요청·최신 카드/등록 결과·처리 중/결과 불명확 | 일반 다시 시도 문구만 보고 새 인증·등록 세션을 만들지 않음 |
| 카드 등록 완료인데 플랜/팩은 그대로 | 등록과 별도 선택/최종 구독/팩 작업의 각각의 결과 | 카드 생성만으로 유료 전환·팩 구매·청구 성공을 확정하지 않음 |
| 다른 카드로 변경할 수 없음 | 소유자·활성/본인 카드·현재 허용 동작·진행 변경/갱신과 충돌 | 카드 삭제·다른 계정·직접 요청으로 우회하지 않음 |
| 결제 내역이 없거나 금액이 다름 | 같은 사이트·플랜/갱신/팩 유형·페이지·원 승인/환불과 현재 금액 | 빈 목록을 미청구로, 현재 금액을 원 승인액으로 해석하지 않음 |
| 카드사/영수증·서비스 결과가 다름 | 같은 청구 건·시각·당시 카드·확인된 승인/환불·영수증 제공 범위 | 중복 청구·별도 환불로 맞추지 않음 |

**구독 결제 내역**은 학원 학생의 상품 주문이나 판매자 정산 내역과 다릅니다. 소유자가 해당 사이트의 원 청구 건·유형/페이지를 확인하고, 목록·영수증 제공 범위 밖의 실패/진행/0원까지 모두 보여준다고 가정하지 않습니다. 영수증 주소·카드/인증 URL을 일반 문의에 붙이지 않습니다.

카드 등록 결과 화면/URL을 다시 열면 완료 요청이 이어질 수 있으므로 읽기 점검용으로 재진입하지 않습니다. 인증 만료와 외부 결과 불명확도 다릅니다. 이미 한 요청의 결과부터 담당자가 확인하며 처리 기한·자동 등록 복구·환불 입금 시점을 임의로 약속하지 않습니다.

정상 기준은 [구독 결제수단·청구 내역](../subscription-and-usage/billing-method-and-payment-history.md)을 따릅니다. 판매자 계좌/정산 문제는 [판매자·계좌·정산 점검](seller-bank-and-settlement.md)으로 구분합니다.

> **화면 예시 준비 중** · 카드 등록·선택 변경·실제 청구 결과를 구분합니다.

## 6. 사용량·예약량·현재 팩·다음 갱신 확인하기 <a href="#step-6" id="step-6"></a>

**사용량 및 팩**에서 저장공간과 시청시간을 따로 확인합니다. 측정 시점/기간·단위, 실제 사용/예약·이용 가능량, 기본 플랜/체험·팩의 유효 한도와 다음 갱신 설정을 구분합니다. 조회 오류·값 누락을 사용량 0이나 무제한으로 보지 않습니다.

| 상황 | 확인할 것 | 피할 대응 |
| --- | --- | --- |
| 업로드/시청 한도와 화면 수치가 다름 | 해당 리소스·집계 시점/기간·사용/예약·유효 한도와 실제 오류 | 영상/학생 기록을 지우거나 한도를 임의 초기화하지 않음 |
| 파일을 지웠는데 사용량이 기대와 다름 | 삭제/보관·예약/처리 중·집계 기준과 마지막 측정 결과 | 삭제를 반복하거나 즉시 정산/초기화를 약속하지 않음 |
| 팩 선택량과 현재 제공량/금액 차이 | 현재 적용 수량·다음 갱신 수량·화면 선택값·체험/플랜 영향 | 선택 화면을 현재 적용/과거 결제 증거로 쓰지 않음 |
| 견적의 이번/다음 금액이 다름 | 오늘 청구·전체 팩 다음 금액·플랜 포함 월 예상과 실제 원 청구 | 화면 예상 합계를 이미 청구된 금액으로 설명하지 않음 |
| 갱신 실패/유예·재개/재결제 | 해당 팩 항목·원 작업 결과·현재 허용 동작·유예/한도 영향 | 구독 전체와 팩을 같은 작업으로 재실행하지 않음 |
| 환불 수량 0·불가/금액 확인 불가 | 원 구매 단위·승인 시각/마감·과거 사용/예약·진행 환불과 최신 자격 | 현재 사용이 줄었다고 미사용으로 되돌리거나 임의 수량/금액을 넣지 않음 |
| 환불 뒤 한도/청구 결과 차이 | 원 환불 건·금융/적용 상태·현재/주기 말/다음 한도와 예약량 | 환불 완료 안내만으로 모든 한도/카드 반영을 확정하지 않음 |

팩 환불은 화면의 ‘이내’ 문구나 날짜만 보고 확정하지 않습니다. **정확한 승인/마감 시각과 최신 서버 자격·수량·금액·한도 영향**을 대조합니다. 과거 최대 사용/예약·기처리/진행 수량도 확인하므로 현재 잔여량만으로 환불 가능을 판단하지 않습니다.

**환불 가능 여부 조회도 사용 근거 관측/기록에 영향을 줄 수 있습니다.** 단순 점검이나 촬영을 위해 환불 창을 열거나 수량을 바꾸어 조회하지 않습니다. 이미 환불을 요청했다면 원 작업의 현재 결과부터 확인하고 재신청하지 않습니다.

저장공간 누적과 시청시간 집계 주기는 같은 기준이 아닙니다. 월 표시만으로 초기화 날짜를 정하거나 현재 플랜 기본 제공량에 선택 팩을 더해 실제 유효 한도를 확정하지 않습니다. 화면에 없는 예약량/시점·구매 단위 근거는 담당자가 확인하며, 파일 삭제·팩 구매/환불·플랜 변경을 시험 삼아 실행하지 않습니다.

자세한 기준은 [사용량·추가 팩](../subscription-and-usage/usage-and-additional-packs.md)을 따릅니다. 업로드/영상 이용 자체의 문제는 [영상·자료·수강권 점검](video-resource-and-access.md)으로 구분합니다.

> **화면 예시 준비 중** · 집계 기준과 현재 적용·다음 갱신·원 환불 자격을 나눕니다.

## 7. 기다릴 조건과 문의할 조건 정리하기 <a href="#step-7" id="step-7"></a>

같은 원 작업의 처리/적용 대기가 확인됐을 때만 그 결과를 기다립니다. 잘못된 사이트/계정·권한 제한·저장 실패·게시/연결 누락·견적 만료·카드 결과 불명확·사용량/팩 근거 차이를 모두 구독 장애나 자동 복구 대기로 묶지 않습니다.

| 문의로 넘길 상황 | 전달할 정보 |
| --- | --- |
| 접근/역할·강좌 범위 문제 | 사이트·역할·업무/대상·전체 수/일부 목록 차이·오류/시각과 마지막 정상 결과 |
| 저장/게시·공지/Q&A/폼/상담 차이 | 대상 페이지/질문/폼·저장/게시/노출 단계·기기/대상·이미 한 행동과 최신 결과 |
| 운영 상태/구독/삭제 안내 차이 | 실제 조회한 상태·구독/예약과 각 안내의 차이만 정리. 비밀번호/요청 전문 제외 |
| 플랜/카드/청구 결과 불명확 | 원 작업/청구 식별정보·현재 플랜/예약·마지막 요청/조회 시각·확인된 금액/카드 끝자리 |
| 사용량/팩/환불 차이 | 리소스·집계 시점/기간·현재/예약/다음 설정·원 구매/작업과 보이는 오류 |

강사·질답조교는 지정 운영자에게 전달합니다. 운영자는 소유자 업무와 조회 업무를 나누고 해결되지 않으면 확인된 클킷 지원 경로로 문의합니다. 문의 채널·담당자·운영 시간은 확인된 안내를 사용하고 답변/복구·청구/환불 기한을 임의로 만들지 않습니다.

가상 문의 예시:

> 같은 사이트의 질답조교 계정에서 질문은 보이지만 답글 등록이 거절됩니다. 대상 질문과 역할·답글/상태 변경 권한·오류 시각을 정리했습니다. 다른 계정 답변·비밀 공개·중복 등록은 하지 않았습니다. 해당 업무의 실제 허용 권한을 확인해 주세요.

> 카드 등록 결과 화면에는 실패 안내가 있지만 원 등록/외부 처리 결과는 확인되지 않았습니다. 현재 카드/플랜 상태와 원 요청 시각을 정리했고 callback 재진입·재인증·새 구독/팩 결제는 하지 않았습니다. 원 카드 등록과 실제 청구 결과를 나누어 확인해 주세요.

> **화면 예시 준비 중** · 원 대상·마지막 결과와 이미 한 행동을 전달합니다.

식별정보·금액·카드 끝자리는 확인된 비공개 지원 경로에 필요한 최소한으로 제공합니다. **비밀번호·인증번호·토큰·쿠키·학생 명단·비밀 질문/첨부·폼 응답 원문·전체 카드/계좌번호·인증·결제 연결 정보·PG/영수증/다운로드 URL·개발자 도구·네트워크 요청 기록 원문은 일반 문의에 보내지 않습니다.** 권한 확대·강좌 이관·빌더 저장/게시·사이트 삭제·중복 결제/팩 환불·직접 DB/CLI·worker/대사 실행은 이 안내의 해결 절차가 아닙니다.
