# 정산명세서·PDF 확인하기

> **이용 전 확인** · 실제 서비스 화면·동작이 아직 확인되지 않은 항목이 있습니다. 문서의 제한·주의사항을 따르고, **실행 보류**로 표시한 작업은 진행하지 마세요.

<figure><img src="../.gitbook/assets/branding/page-headers/sellers-and-settlements/settlement-statement-and-pdf-v2.png" alt="정산명세서·PDF 확인하기 대표 이미지"><figcaption></figcaption></figure>

**업무 대상:** 사이트 소유자와 판매자·정산 업무 담당자용 안내입니다. 강사가 담당 강좌를 운영하기 위해 판매자 정보나 정산 계좌를 직접 등록할 필요는 없습니다. 관련 요청은 학원의 정산 담당자에게 전달하세요. 실제 작업 가능 범위는 본인 계정의 권한을 확인하세요.

명세서·PDF가 제공되면 확정된 정산 회차의 대상·기간·금액을 대조합니다. 해당 사이트의 정산 조회 권한이 있는 사이트 소유자·담당 운영자가 사용합니다.

**정산명세서는 확정 정산 내역입니다. 실제 입금 완료를 증명하거나 세금계산서를 대신하지 않습니다.** 구매자 영수증·거래명세서와도 대상과 목적이 다릅니다.

**확인 순서:** 대상 회차 → 확정 여부·버전 → 상호·기간·금액 → PDF 파일 확인 → 제한·오류 확인

## 시작 전 준비 <a href="#before-you-start" id="before-you-start"></a>

| 준비할 것 | 확인 기준 |
| --- | --- |
| 작업 계정 | 해당 사이트의 정산 조회 권한. 다른 계정의 로그인 정보·문서 주소를 공유받아 접근하지 않음 |
| 대상 회차 | 정산월·회차와 확정 여부. 예상 금액을 확정 문서로 사용하지 않음 |
| 비교 자료 | [정산 금액·지급 상태](settlement-amount-and-payout-status.md)의 같은 회차 확정 내역 |
| 파일 확인 환경 | PDF를 열 수 있는 환경과 승인된 보관·공유 경로. 문의에 화면을 전달한다면 계좌·개인정보 등 불필요한 내용을 가림 |

명세서 확인을 위해 정산을 새로 생성·확정하거나 지급·계좌 변경을 실행하지 않습니다. 미확정 내역과 근거가 부족한 과거 내역은 담당자 확인이 필요합니다.

## 메뉴 위치 <a href="#menu-location" id="menu-location"></a>

관리자 화면의 **결제/정산관리 → 정산 내역**에서 대상 회차의 상세를 확인합니다. 회차 찾는 방법은 [정산 금액·지급 상태 확인하기](settlement-amount-and-payout-status.md)를 따릅니다.

**현재 확인한 정산 상세에는 명세서·PDF·CSV 다운로드 버튼이 없습니다.** 필요한 회차·버전과 제공 여부를 담당자에게 확인합니다. 다른 파일 주소·브라우저 인쇄·과거 CSV를 정식 명세서 발급으로 대신하지 않습니다.

> **화면 예시 준비 중** · 정산명세서의 확인 기준과 실제 화면·파일 제공 여부는 별도로 확인합니다.

## 1. 같은 회차의 확정본 확인하기 <a href="#step-1" id="step-1"></a>

1. 의도한 사이트·판매자의 정산 회차인지 확인합니다.
2. 해당 회차의 금액이 확정됐는지 확인합니다. `정산 완료` 문구만으로 실제 입금을 판단하지 않습니다.
3. 명세서 확인 기능이 제공되면 해당 회차의 확정본을 엽니다. 버전이 표시되면 상세와 문서가 같은 확정 버전인지 대조합니다.

예상 내역이나 확정 버전이 없는 과거 내역은 문서 발급이 제한될 수 있습니다. 버전을 임의 입력하거나 다른 회차의 문서를 가져와 사용하지 않습니다. 화면에서 확정 여부·버전을 확인할 수 없으면 담당자에게 대상 회차를 전달합니다.

지급대상액 0원·음수 잔액 회차도 금액 확정과 지급 결과를 구분해 읽습니다. 문서를 열 수 있다는 사실이 지급 완료를 뜻하지는 않습니다.

## 2. 문서의 상호·기간 확인하기 <a href="#step-2" id="step-2"></a>

| 확인 항목 | 읽는 기준 |
| --- | --- |
| 문서 제목·정산 번호 | 판매자 정산명세서인지, 선택한 회차와 같은 내역인지 확인 |
| 사업자 상호 | 정산 확정 당시 보존된 상호. 사이트명·관리자 이름·현재 변경한 상호와 구분 |
| 정산월·집계 기간 | 한국 시간의 해당 월 시작 이상·다음 달 시작 미만. 기간 끝 시각은 포함하지 않음 |
| 확정본 발급 기준 | 정산 확정 기준 시각. 파일을 내려받은 오늘 날짜와 반드시 같지 않음 |
| 확정 버전 | 상세와 문서가 같은 확정본을 가리키는지 확인. 문서 형식의 변경과 구분 |

상호가 `이름 기록 없음`으로 표시되면 당시 이름 근거가 없는 상태입니다. 현재 사업자 정보로 과거 문서가 자동 보완됐다고 판단하거나 파일을 직접 수정하지 않습니다. [판매자 정보](seller-registration-and-review.md)와 대상 회차를 담당자에게 확인합니다.

집계 기간은 거래를 모으는 기준이며 해당 월에 발생한 주문만 포함한다는 뜻은 아닙니다. 과거 미정산 거래가 포함될 수 있으므로 주문 발생월만으로 문서 금액을 제외하지 않습니다.

> **화면 예시 준비 중** · 확정 당시 상호와 집계 기간을 확인합니다. 확정 기준 시각과 다운로드 시각은 다릅니다.

## 3. 확정 금액과 포함 근거 대조하기 <a href="#step-3" id="step-3"></a>

같은 회차의 확정 내역과 문서의 금액을 비교합니다. 예상값·실제 입금액·거래 일부를 비교 대상으로 섞지 않습니다.

| 확인 항목 | 읽는 기준 |
| --- | --- |
| 매출·취소·순매출 | 해당 회차에 반영된 확정 거래 근거. 취소 요청이나 처리 중 금액을 완료 취소로 더하지 않음 |
| 조정·플랫폼/PG 수수료 | 문서에 보존된 조정·수수료 근거. 현재 요율로 과거 금액을 재계산하지 않음 |
| 이전 회차 이월 차감 | 이전 음수 잔액에서 반영된 차감. 이번 회차의 새 취소와 구분 |
| 정산 잔액 | 수수료·조정·이월 차감 등이 반영된 부호 있는 잔액. 음수를 0원으로 바꾸지 않음 |
| 확정 지급대상액 | 확정 금액 중 지급 대상인 금액. 실제 입금 완료액을 뜻하지 않음 |
| 다음 회차 이월 | 음수 잔액의 후속 차감 대상. 양수 지급 실패액의 자동 이월과 구분 |
| 공급가액·부가세·면세 | 매출 세금과 취소 반영 후 세금, 수수료 세금을 구분. 누락 근거를 0원으로 보완하지 않음 |
| 포함 근거 내역 | 문서 전체의 결제·취소·수수료·조정 등 반영 내역. 현재 화면 거래 페이지 일부와 구분 |

명세서를 제공받으면 **확정 회차·버전과 전체 포함 범위**를 먼저 확인합니다. 원천 내역·주문별 집계·전체 요약은 범위가 서로 다릅니다. 위 표는 확인 항목을 설명한 것이며, 실제 거래 내역이나 전체 명세서를 대신하지 않습니다. 원장·상호·금액을 대조하고 마지막 페이지까지 읽습니다. 여러 거래 페이지의 요약이나 과거 CSV를 더해 전체 명세서로 만들지 않습니다.

금액·세금 근거가 다르거나 누락됐으면 대상 회차의 확인을 요청합니다. 총액에서 세금을 임의 추정하거나 부가세를 한 번 더 차감하지 않습니다. 확정 이후 완료된 취소는 후속 회차에 반영될 수 있으므로 과거 PDF를 수정해 금액을 맞추지 않습니다.

지급 계좌·지급 진행 상태·실제 완료일은 [정산 상세](settlement-amount-and-payout-status.md)에서 별도로 확인합니다. 문서에 계좌나 입금 완료 표시가 없다는 이유로 발급 실패로 판단하지 않습니다.

> **화면 예시 준비 중** · 같은 확정본의 금액과 전체 포함 근거를 대조합니다. 지급대상액은 입금 완료액이 아닙니다.

## 4. PDF 파일 확인하기 <a href="#step-4" id="step-4"></a>

아래는 **명세서·PDF 기능이 화면에서 제공될 때 확인할 순서**입니다. 실제 버튼명과 제공 절차는 아직 확인이 필요합니다.

1. 대상 회차의 확정본을 확인한 뒤 화면에서 제공하는 PDF 다운로드를 실행합니다.
2. 처리 결과를 기다리고 실제 파일이 저장됐는지 확인합니다. 생성 알림만으로 성공으로 판단하지 않습니다.
3. 파일을 PDF 뷰어로 열어 제목·상호·정산월·기간·버전·금액을 같은 확정 내역과 대조합니다.
4. 모든 페이지의 한글·금액 부호·포함 근거가 읽히는지 확인합니다.
5. 승인된 경로에 보관하고 필요한 담당자에게만 공유합니다.

파일 이름이나 `.pdf` 확장자만으로 정상 파일을 판단하지 않습니다. 열리지 않는 파일·오류 안내가 저장된 파일·CSV는 명세서 PDF가 아닙니다. 브라우저 인쇄 파일도 서비스의 PDF 다운로드 결과로 안내하지 않습니다.

같은 확정본을 다시 받으면 금융 내용과 확정 기준을 비교합니다. 파일 크기나 파일 자체가 완전히 같아야 한다고 판단하지 않습니다. 문서 형식이 바뀐 경우에는 같은 형식의 문서끼리 비교하고 차이는 담당자에게 확인합니다.

> **화면 예시 준비 중** · 실제 PDF를 열고 기간·버전·금액과 모든 페이지의 내용을 확인합니다.

> **동작 예시 준비 중** · 명세서를 확인하고 저장된 PDF 파일의 내용을 대조합니다. 정산 확정·지급·계좌 변경은 실행하지 않습니다.

## 5. 제한·오류가 있으면 <a href="#step-5" id="step-5"></a>

| 상황 | 확인할 것 |
| --- | --- |
| 명세서 메뉴·PDF 버튼이 없어요 | 명세서·PDF 제공 여부와 계정 권한을 확인합니다. 기존 CSV를 PDF로 대신 안내하지 않습니다 |
| 로그인·조회 권한이 필요해요 | 의도한 사이트와 계정으로 다시 확인합니다. 다른 계정의 문서 주소를 공유받아 우회하지 않습니다 |
| 미확정·발급 불가로 나와요 | 해당 회차의 확정 여부·과거 근거를 확인합니다. 문서 발급을 위해 직접 정산을 재확정하지 않습니다 |
| 내역이나 버전이 변경됐어요 | 상세를 다시 조회하고 최신 확정본을 확인합니다. 오래된 화면에서 다운로드를 반복하지 않습니다 |
| 대상 회차를 찾을 수 없어요 | 사이트·판매자·정산월·선택한 회차를 확인합니다. 조회 오류와 실제 내역 없음은 다릅니다 |
| 금액·근거가 일치하지 않아요 | 해당 회차의 확인을 요청합니다. 금액이나 세금을 직접 보완해 사용하지 않습니다 |
| PDF 생성·다운로드가 실패해요 | 같은 유효 확정본인지 재조회하고 화면 안내에 따라 다시 확인합니다. 반복 실패면 오류를 정리해 문의합니다 |
| 파일이 안 열리거나 내용이 잘려요 | 저장 결과와 모든 페이지를 확인해 문의합니다. 파일 이름·성공 알림만으로 정상 처리하지 않습니다 |

**PDF 실패는 지급 실패가 아닙니다.** 다운로드 문제를 정산 재생성·재확정·재지급으로 해결하지 않습니다. 실패 원인이 권한·미확정·버전 변경·근거 불일치인지 먼저 구분합니다.

문의할 때는 사이트·정산월·대상 회차·발생 시각·오류 문구와 마스킹한 화면을 정리합니다. 로그인 토큰·문서 다운로드 주소·전체 계좌번호·학생 개인정보·금융 문서 전문을 일반 문의에 붙이지 않습니다.

> **화면 예시 준비 중** · 제한·변경·파일 실패를 구분합니다. PDF 실패는 지급 실패가 아닙니다.

## 완료 후 확인 <a href="#completion-checklist" id="completion-checklist"></a>

- [ ] 의도한 사이트·판매자·정산 회차의 확정본을 확인했습니다.
- [ ] 확정 당시 상호·집계 기간·확정 기준 시각을 대조했습니다.
- [ ] 확정 금액·전체 포함 근거와 실제 입금 결과를 구분했습니다.
- [ ] 실제 PDF 파일을 열고 모든 페이지의 내용·가독성을 확인했습니다.
- [ ] 발급 제한·버전 변경·다운로드 실패를 구분하고 필요한 문의를 정리했습니다.
- [ ] 문서를 승인된 경로에 보관하고 개인정보·금융정보를 보호했습니다.
