# 정산 금액·지급 상태 확인하기

> **검토용 가이드** · 실제 서비스 화면·동작 확인과 이미지 보완이 남아 있습니다. 본문의 실행 보류·주의사항을 먼저 확인하세요.

정산 회차의 금액과 포함 거래를 확인하고 실제 지급 결과를 구분합니다. 정산 조회 권한이 있는 사이트 소유자·담당 운영자가 사용합니다.

**정산 금액이 확정됐다는 것과 계좌로 입금됐다는 것은 다릅니다.** `정산 완료` 표시나 정산명세서 발급만으로 입금 완료를 판단하지 않습니다.

**확인 순서:** 정산 내역 → 대상 회차 → 금액·포함 거래 → 정산 확정 여부 → 지급 결과·계좌 → 같은 회차 재조회

## 시작 전 준비

| 준비할 것 | 확인 기준 |
| --- | --- |
| 작업 계정 | 해당 사이트의 정산 조회 권한. 강사·조교라는 역할 이름만으로 접근을 전제하지 않음 |
| 대상 회차 | 확인할 정산월과 필요하면 관련 주문번호 |
| 판매자·계좌 | [판매자 등록·심사](seller-registration-and-review.md)와 [정산 계좌 등록·변경](settlement-bank-account.md)의 상태 |
| 비교 자료 | 같은 회차의 금액·거래·지급 결과. 주문 구매 내역과 정산 회차를 혼동하지 않음 |

조회 권한과 계좌 변경 권한은 다릅니다. 계좌 변경은 사이트 소유자가 진행하며 이 페이지에서 정산 생성·확정·재지급을 직접 실행하지 않습니다.

## 메뉴 위치

관리자 화면의 **결제/정산관리 → 정산 내역**으로 이동합니다. 목록에서 확인할 회차의 행을 선택하면 상세로 이동합니다.

메뉴가 보이지 않으면 로그인한 사이트와 계정 권한을 담당자에게 확인합니다. 다른 계정의 로그인 정보나 금융 문서 링크를 공유받아 접근하지 않습니다.

> **화면 예시 준비 중** · 대상 회차와 페이지를 확인합니다.

## 1. 대상 정산 회차 찾기

1. 목록의 정산월/표시 기간과 대상 회차를 확인합니다.
2. 현재 목록의 쪽당 개수·페이지로 대상 회차를 찾습니다. 기간/정렬 필터가 있는 것으로 가정하지 않습니다.
3. 같은 월에 여러 항목이 있으면 금액과 상세를 함께 확인하고 원하는 항목을 선택합니다.

현재 목록의 쪽당 개수·페이지로 회차를 확인합니다. 빈 목록과 조회 오류, 대상 월·판매자·다른 페이지를 구분하고 회차가 없다는 이유로 정산을 새로 만들거나 확정하지 않습니다.

정산은 한국 시간의 달력월을 기준으로 합니다. 해당 월 시작부터 다음 달 시작 전까지가 기간이며, 이전 달에 아직 정산되지 않은 거래가 포함될 수도 있습니다. 주문 발생월만으로 회차에 포함된 금액을 제외하지 않습니다.

기간 끝 날짜·거래일이 예상과 다르게 보이면 대상 정산월과 주문 발생 시각을 함께 확인합니다. 현재 날짜 표시의 시간대 차이는 확인 대기이므로 화면 날짜만으로 귀속 회차를 임의 변경하지 않습니다.

## 2. 상세에서 금액 구성 확인하기

대상 회차를 열고 **총 매출**, **정산 금액**, **정산 금액 구성**을 확인합니다. 금액을 비교할 때는 회차·예상/확정 여부·전체 합계인지 거래 일부인지부터 맞춥니다.

아래는 금액을 읽는 기준입니다. 정산 잔액·이월·예상/보류 등 신규 항목의 최종 표시 위치는 확인 대기이며, 현재 화면의 지급대상액을 부호 있는 정산 잔액으로 대신 읽지 않습니다.

| 확인 항목 | 읽는 기준 |
| --- | --- |
| 총 매출 | 해당 회차에 반영된 매출. 이번 달의 전체 주문 결제액과 반드시 같은 금액은 아님 |
| 환불(정산 반영) | 해당 회차에 반영된 실제 환불. 접수·승인 대기·실패·결과 확인 중인 요청을 완료 환불로 합산하지 않음 |
| PG 수수료 | 결제·취소에 연결된 수수료 근거. 예상 또는 확인 대기인 값은 확정 수수료와 구분 |
| 플랫폼 수수료 | 구매 당시 적용 요율과 거래 근거. 현재 설정한 요율로 과거 정산을 다시 계산하지 않음 |
| 이월 공제 | 이전 음수 잔액의 차감 반영. 이번 회차의 새 환불이나 양수 지급 실패액과 구분 |
| 공급가액·부가세 | 저장된 과세 매출의 세금 정보. 면세 매출이나 취소 반영 후 세금 합계와 구분 |
| 정산 잔액 | 수수료·환불·조정·이월 차감 등이 반영된 부호 있는 잔액. 음수 잔액과 0원 지급대상액을 구분 |
| 정산 금액·지급액 | 현재 화면에서 사용하는 0원 이상의 지급대상액. 부호 있는 잔액이나 실제 입금 완료액을 뜻하지 않음 |

세금 정보가 비어 있거나 과거 자료의 근거가 부족하면 임의로 0원 처리하지 않습니다. 과세·면세가 섞인 총액을 나눠 세금을 추정하거나, 표에 있는 부가세를 임의로 다시 공제해 지급액을 만들지 않습니다. **현재 화면의 0원 표시만으로 세금·수수료 근거가 확인됐다고 판단하지 않습니다.**

합계와 거래 근거가 다르거나 예상/보류 여부를 확인할 수 없으면 해당 회차의 확인을 요청합니다. 정산 금액을 맞추려고 주문·환불·재고·계좌 정보를 수정하지 않습니다.

> **화면 예시 준비 중** · 금액 구성과 근거를 확인합니다. 지급대상액과 입금 완료액은 다릅니다.

## 3. 포함 거래 확인하기

상세의 **거래요약**에서 거래 종류·금액·일자를 확인하고 페이지를 이동해 다른 거래도 확인합니다. 관련 주문이 있으면 [주문·결제 상태 확인하기](../orders-and-shipping/order-and-payment-status.md)의 내역과 대조합니다.

현재 거래 표는 결제·환불 원천별 표시이며 **주문 하나당 한 행으로 묶인 표가 아닙니다.** 같은 주문의 결제와 여러 취소가 나뉘어 보일 수 있습니다. 현재 페이지의 행만 합산해 회차 총 매출·최종 지급액을 계산하지 않습니다.

현재 열 제목은 `강좌 명`, `수강생 명`이지만 교재·자료·묶음상품 거래도 같은 정산 근거로 확인해야 합니다. 이름이 비어 있거나 `-`로 보인다고 거래 금액을 제외하지 않습니다. 주문별 통합 거래 표의 새 화면은 확인 대기입니다.

확정된 회차 이후에 완료된 환불은 후속 회차에서 별도로 반영될 수 있습니다. 과거 확정 금액을 수정하거나 이미 반영된 원 결제액을 다음 회차에 다시 더하지 않습니다. 취소 조건은 [구성품별 취소·환불](../cancellations-and-returns/component-cancellation-and-refund.md), 반품 비용과 실제 환불은 [교재 반품](../cancellations-and-returns/textbook-return.md)을 따릅니다.

> **화면 예시 준비 중** · 거래 페이지와 전체 회차·파일 제공 범위를 구분합니다.

## 4. 정산 확정과 지급 상태 구분하기

먼저 금액이 예상인지 확정인지, 이어서 실제 지급이 요청·진행·완료됐는지 확인합니다. **아래는 업무상 구분 기준이며 신규 상태의 최종 화면 표시와 확인 위치는 검수 대기입니다.** 화면에 필요한 정보가 없으면 상태를 추정하지 말고 담당자에게 확인합니다.

| 구분 | 확인할 것 |
| --- | --- |
| 예상 금액 | 아직 확정되지 않은 조회 금액. 회차가 생성되지 않은 예상은 저장된 확정 내역과 다름 |
| 정산 확정 | 해당 회차의 금액·근거 확정. 지급 요청·입금 완료와 별도 |
| 보류 | 원장·세금·수수료 근거 또는 지급/계좌의 확인 사유. 보류 위치와 사유를 먼저 구분 |
| 음수 잔액 이월 | 다음 사용 가능한 회차의 차감 대상. 지급 실패액의 자동 이월과 다름 |
| 지급 대기·처리 중 | 미요청과 요청 후 진행을 구분. 진행 중이라는 이유로 완료·실패를 판단하지 않음 |
| 지급 완료 | 해당 지급 건의 확인된 결과·완료일·금액·계좌. 금액 확정이나 날짜 경과만으로 완료 처리하지 않음 |
| 지급 실패 | 실제 미지급 실패가 확인된 결과. 재처리는 담당자의 별도 확인 대상 |
| 결과 확인 중 | 완료·실패를 아직 확정할 수 없는 상태. 중복 지급을 요청하거나 실패로 안내하지 않음 |

기존 화면의 **정산 완료** 표시는 금액 확정과 입금 완료를 구별해 읽어야 합니다. 신규 지급 완료·보류·이월 표시가 연결되지 않은 경우 기존 상태 문구만으로 지급 결과를 확답하지 않습니다. 과거 실패 이력만 보고 이후에 확인된 지급 완료를 실패로 안내하지 않습니다.

**정산 집계·확정일, 지급 요청일, 지급 예정일, 실제 완료일은 서로 다릅니다.** 매월 8일 정산 집계/확정 기준을 입금 예정일로 사용하지 않습니다. 지급 예정일은 외부 지급 접수가 확인된 실제 예약 근거가 있을 때만 확인하며, 현재 새 일정 표시의 연결은 대기입니다.

지급대상액 0원은 지급 완료를 뜻하지 않습니다. 음수 잔액만 후속 차감 이월로 관리하며, 양수 지급 실패액을 다음 회차에 자동으로 더하거나 불명확한 지급을 재요청하지 않습니다.

### 지급 계좌 확인하기

상세의 **지급 계좌 정보**를 확인합니다. 계좌 수정이 필요하면 사이트 소유자가 [정산 계좌 등록·변경하기](settlement-bank-account.md)를 따릅니다. `계좌 정보 수정하기` 링크가 있다는 사실만으로 모든 계정·신청 상태에서 변경 가능하다고 판단하지 않습니다.

| 계좌 구분 | 확인 기준 |
| --- | --- |
| 현재 입력한 계좌 | 저장·인증 여부. 실제 외부 반영이나 다음 지급 계좌와 동일하다고 가정하지 않음 |
| 지급에 사용할 계좌 | 최신 인증과 외부 반영이 확인된 계좌 |
| 지급 요청 당시 계좌 | 해당 지급 시도에 보존된 계좌. 이후 입력 변경으로 과거 이력을 덮어쓰지 않음 |

현재 화면의 단일 계좌 영역만으로 위 세 상태를 모두 확인할 수 있는 것은 아닙니다. 계좌가 없거나 이전 계좌가 표시되면 외부 반영·해당 지급 시도를 함께 확인합니다. 저장·인증 성공만으로 다음 지급이 새 계좌로 입금된다고 확답하지 않습니다.

지급 진행 또는 결과 확인 중에는 새 계좌의 외부 반영이 보류될 수 있습니다. 계좌·인증·신청을 반복하지 말고 해당 지급 결과와 변경 반영 여부를 확인합니다.

> **화면 예시 준비 중** · 금액 확정과 지급 결과, 현재 입력 계좌와 지급 요청 당시 계좌를 따로 확인합니다.

## 5. 파일로 확인할 때

현재 확인한 정산 상세/서비스에는 **CSV·정산명세서/PDF 다운로드 연결이 없습니다.** 과거의 엑셀파일 내려받기 설명을 현재 버튼으로 찾도록 안내하지 않습니다. 필요한 회차·범위와 실제 제공 경로를 담당자에게 확인하며 브라우저 인쇄/다른 파일 주소로 대신 발급하지 않습니다.

거래 화면의 현재 페이지와 회차 전체 금액·확정 정산명세서는 범위가 다릅니다. 현재 화면에 없는 주문별 통합 표를 제공된 것으로 판단하지 않습니다. 필요한 확정 문서는 [정산명세서·PDF 확인하기](settlement-statement-and-pdf.md)를 따르고 여러 페이지의 요약이나 CSV를 더해 전체 명세서로 만들지 않습니다.

화면의 `세금 계산서` 영역이나 발행 내역 없음 표시는 자동 발행 기능을 뜻하지 않습니다. 정산명세서도 세금계산서가 아니며 구매자 영수증 문의는 [주문·결제 가이드](../orders-and-shipping/order-and-payment-status.md)로 연결합니다.

> **동작 예시 준비 중** · 대상 회차와 포함 거래를 확인하고 같은 회차를 다시 조회합니다.
