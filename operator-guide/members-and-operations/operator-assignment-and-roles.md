# 운영자 지정·역할 관리하기

> **검토용 가이드** · 실제 서비스 화면·동작 확인과 이미지 보완이 남아 있습니다. 본문의 실행 보류·주의사항을 먼저 확인하세요.

<figure><img src="../.gitbook/assets/branding/page-headers/members-and-operations/operator-assignment-and-roles-v2.png" alt="운영자 지정·역할 관리하기 대표 이미지"><figcaption></figcaption></figure>

**업무 대상:** 운영자 지정과 역할·담당 강좌 배정을 맡은 관리자용 안내입니다. 강사는 배정 누락이나 권한 문제를 학원 운영자에게 요청하세요. 아래 역할 설명이 본인 계정의 변경 권한을 뜻하지는 않습니다.

**운영 → 운영자 목록**에서 이미 가입한 회원을 운영자로 지정하고, 기존 운영자의 역할과 강사 담당 강좌를 관리합니다. 이메일 초대를 보내거나 새 계정을 만드는 절차가 아닙니다.

**완료 기준:** 대상 회원·역할·담당 강좌와 기존 담당자 영향을 확인한 뒤 필요한 작업만 한 번 실행하고, 최신 목록/상세와 실제 업무 접근을 대조합니다. 역할 안내나 성공 메시지만으로 모든 메뉴·Q&A·결제/정산 권한이 확인됐다고 판단하지 않습니다.

가입 회원 식별은 [회원 정보·이용 내역 확인하기](member-information-and-history.md), 학생 수강권 변경은 [수강권·이용 기간 관리하기](enrollment-and-access-period.md), 질답 조교의 질문·답글 업무는 [Q&A 질문에 답변하기](../site-and-communication/qna-answer.md)에서 다룹니다.

## 시작 전 준비 <a href="#before-you-start" id="before-you-start"></a>

| 준비할 것 | 확인 기준 |
| --- | --- |
| 지정 대상 | 같은 사이트에 이미 가입한 회원인지 확인합니다. 이름이 같으면 이메일·휴대폰도 대조합니다 |
| 필요한 업무·역할 | 매니저·강사·조교·디자이너 중 필요한 역할을 정합니다. 직함만 보고 넓은 권한을 부여하지 않습니다 |
| 작업 권한·좌석 | 지정/변경은 소유자·매니저 역할과 해당 작업 권한, 해제는 소유자와 삭제 권한을 확인합니다. 플랜·구독과 운영자 좌석 한도도 확인합니다 |
| 담당 강좌·기존 담당자 | 강사는 기존 담당 강좌를 선택하지 않아도 지정할 수 있습니다. 선택한다면 전체 대상과 현재 담당 강사·이관 영향을 먼저 확인합니다 |
| 변경 전 기록 | 현재 역할·전체 담당 강좌·변경 사유를 확인합니다. 상세의 일부 강좌만 보고 전체를 파악했다고 판단하지 않습니다 |
| 테스트·촬영 대상 | 가상 회원·테스트 강좌를 사용합니다. 실제 지정/변경/해제는 해당 대상과 실행 범위를 승인받은 경우에만 진행합니다 |

메뉴나 버튼이 없으면 권한·역할·구독 조건을 확인합니다. 버튼이 보여도 클킷에서 작업이 거절될 수 있으며 다른 사람의 계정으로 우회하지 않습니다. 소유자 지정·소유권 이전은 이 화면의 업무가 아닙니다.

| 필요한 업무 | 진입 위치·버튼 | 바뀌는 것과 주의할 점 |
| --- | --- | --- |
| 가입 회원을 운영자로 지정 | 운영자 목록 → 운영자 지정 | 기존 회원의 역할을 바꿉니다. 초대메일·수락 링크·외부 계정 생성이 아닙니다 |
| 기존 운영자의 역할 변경 | 목록 → 상세 보기 → 역할 변경 | 역할 하나를 교체합니다. 역할을 추가로 겹쳐 부여하거나 세부 권한표를 편집하는 작업이 아닙니다 |
| 강사의 담당 강좌 변경 | 강사 상세 → 담당 강좌 → 설정 | 선택한 전체 목록으로 담당 강좌를 바꿉니다. 선택 제외·다른 강사 강좌 선택의 이관 영향을 확인합니다 |
| 운영자 역할 해제 | 목록의 해당 운영자 액션 메뉴 → 삭제 | 소유자만 처리합니다. 회원 역할로 전환하며 회원 탈퇴·구매 취소·환불이 아닙니다 |
| 운영 기록 확인 | 상세의 최근 활동 로그/전체 로그, 또는 운영 → 운영자 활동 로그 | 일부 최근 기록과 별도 조회 화면을 구분합니다. 학생의 전체 활동 이력이 아닙니다 |

**대상 식별 → 현재 역할/전체 담당 범위 확인 → 변경 영향 확인 → 최종 실행 → 최신 정보와 접근 결과 확인** 순서로 진행합니다.

## 1. 운영자 찾기 <a href="#step-1" id="step-1"></a>

1. **운영 → 운영자 목록**을 엽니다. 이름·이메일·전화번호 검색어를 입력하고 **검색** 또는 Enter로 실행합니다. 입력만 한 상태와 적용된 검색 조건을 구분합니다.
2. 역할·정렬 조건을 바꿨다면 **적용하기**를 누릅니다. 적용된 조건 칩과 결과 수를 확인하고 필요하면 칩 제거 또는 **전체 해제**로 되돌립니다.
3. 이름·이메일·역할·등록일을 대조합니다. 행을 누르거나 해당 행의 점 세 개 액션 메뉴 → **상세 보기**로 상세를 엽니다.
4. 이미 운영자라면 새 지정 대신 역할 변경을 검토합니다. 검색 결과가 비어도 사이트에 운영자가 전혀 없다는 뜻으로 해석하지 않습니다.

`운영자 목록을 불러오지 못했습니다.`가 보이면 조회부터 다시 확인합니다. 빈 검색 결과·권한 제한·조회 실패를 구분하고 계정을 중복 생성하거나 다른 운영자를 삭제하지 않습니다.

> **화면 예시 준비 중** · 운영자 목록에서 적용된 조건과 대상의 현재 역할을 확인합니다.

## 2. 가입 회원을 운영자로 지정하기 <a href="#step-2" id="step-2"></a>

1. 목록 상단의 **운영자 지정**을 누릅니다.
2. **회원 선택** 단계에서 **회원 검색**의 이름을 입력하고 **검색** 또는 Enter를 누릅니다. 목록 검색과 달리 이 창의 검색 기준 선택지는 이름입니다.
3. 검색 결과의 이름·이메일·휴대폰·가입일을 확인하고 한 명을 선택한 뒤 **다음**을 누릅니다.
4. **역할 지정** 단계에서 역할 안내와 선택한 회원을 확인하고 매니저·강사·조교·디자이너 중 필요한 역할을 선택합니다. **소유자**는 선택 대상이 아닙니다.
5. 강사라면 **강좌 선택으로**를 눌러 아래 담당 강좌 안내를 확인합니다. 다른 역할은 강좌 선택 단계 없이 최종 지정을 진행합니다.
6. 회원·역할·강좌와 좌석/변경 영향을 다시 확인하고 최종 **운영자 지정**을 한 번 누릅니다. 선택만 했거나 **취소**로 나온 상태는 지정 완료가 아닙니다.
7. **운영자로 지정했습니다.** 안내 후 목록을 다시 확인하고 같은 사람의 상세에서 역할·운영 이력·강사 담당 강좌를 대조합니다. 당사자의 실제 업무 접근도 별도로 확인합니다.

이미 운영자인 회원과 본인은 지정 후보에서 제외됩니다. 검색 결과가 없다고 미가입으로 단정하지 말고 검색어·같은 사이트 가입 여부·기존 운영자 여부와 조회 오류를 확인합니다.

지정 후에는 운영자 목록에서 확인합니다. [회원 목록](member-information-and-history.md)은 학생·학부모 역할 대상이므로 지정된 계정이 그 목록에서 빠져도 회원 탈퇴·구매 권리 삭제를 뜻하지 않습니다. 운영자 해제 후 역할은 아래 해제 안내에서 별도로 확인합니다.

현재 지정 창은 검색 결과 첫 8명을 표시하고 다음 페이지 이동을 제공하지 않습니다. 동명이인이 많거나 대상이 보이지 않으면 이름 검색어를 더 구체적으로 입력합니다. 이름만 보고 다른 회원을 선택하거나 실제 회원 정보를 예시 캡처에 노출하지 않습니다.

> **화면 예시 준비 중** · 이미 가입한 회원을 이름으로 검색하고 식별 정보를 대조합니다.

> **화면 예시 준비 중** · 필요한 역할을 선택합니다. 소유자 지정·세부 권한 편집 화면이 아닙니다.

### 역할을 고를 때 <a href="#section-5" id="section-5"></a>

| 역할 | 지정 전에 확인할 것 |
| --- | --- |
| 매니저 | 운영 전반의 관리 업무가 필요한지 확인합니다. 운영자 해제 등 소유자 전용 작업까지 허용된다고 가정하지 않습니다 |
| 강사 | 담당 강좌 운영이 필요한지 확인합니다. 기존 강좌 선택은 선택 사항이며 타 강사 강좌를 선택하면 담당자가 바뀝니다 |
| 조교 | 질답 업무에 필요한 역할인지 확인합니다. 강사와 같은 담당 강좌 선택 단계는 없으며 실제 질문 열람·답글·상태 변경 권한은 각각 확인합니다 |
| 디자이너 | 디자인 업무에 필요한지 확인합니다. 회원·결제·운영자 관리 권한까지 함께 부여된다고 판단하지 않습니다 |

역할 설명만으로 실제 권한이 모두 확인된 것은 아닙니다. 조교로 지정했다고 모든 비밀 질문·답변·상태 변경이 가능하다고 안내하지 않습니다. [Q&A 질문에 답변하기](../site-and-communication/qna-answer.md)의 게시글과 댓글 권한 차이는 아직 확인이 필요합니다. 세부 권한 체크박스 편집 절차는 이 문서에서 제공하지 않습니다.

## 3. 강사 담당 강좌 선택하기 <a href="#step-3" id="step-3"></a>

1. 강사 지정의 **강좌 선택** 단계에서 강좌명·수업 수·현재 **담당 강사**를 대조합니다. 필요하면 **강좌 상세보기**로 새 탭에서 확인합니다.
2. 기존 강좌를 맡기려면 필요한 강좌만 선택하고 **담당 강좌 N개 선택**을 확인합니다. 목록 아래로 스크롤해 추가 결과도 확인합니다.
3. 이미 다른 강사가 맡은 강좌는 이전 담당자와 이관 범위를 먼저 확인합니다. 공동 담당자를 추가하는 기능으로 해석하지 않습니다.
4. 기존 담당 강좌 없이 지정하려면 선택하지 않은 상태를 유지합니다. 강좌를 선택하지 않아도 지정할 수 있지만 이후 강좌 생성·Q&A 등 실제 작업이 가능한지는 해당 역할의 권한을 확인해야 합니다.
5. 최종 **운영자 지정** 후 새 강사뿐 아니라 이관된 강좌와 이전 담당자의 관리 접근도 대조합니다.

강좌 목록에는 작업본 강좌도 포함될 수 있습니다. 게시된 강좌나 현재 무담당 강좌만 고르는 화면으로 설명하지 않습니다. `강좌 목록을 불러오지 못했습니다.`와 `선택할 강좌가 없습니다.`를 구분하고 조회 실패 상태에서 임의로 담당 범위를 확정하지 않습니다.

> **화면 예시 준비 중** · 강사 담당 강좌는 선택 사항입니다. 선택한 강좌의 기존 담당자가 바뀔 수 있습니다.

강좌 **후보 목록은 다음 페이지를 계속 불러오는 방식**입니다. 후보를 더 볼 수 있다는 것과 기존 담당 강좌가 전부 초기 선택됐다는 것은 다릅니다. 현재 상세 화면과 변경 창의 초기 선택에는 담당 강좌 중 일부인 최대 5개만 반영될 수 있습니다. 전체 담당 강좌 수와 구분하고, 전체 범위를 확인하지 못했다면 아래 저장 중단 조건을 따릅니다.

## 4. 기존 역할·담당 강좌 변경하기 <a href="#step-4" id="step-4"></a>

> **저장 중단 조건:** 현재 상세는 담당 강좌를 최대 5개만 표시하고 변경 창도 그 일부 목록을 초기 선택으로 사용합니다. 저장은 전체 담당 목록을 교체하므로, **기존 담당 강좌가 6개 이상이거나 전체 목록을 확인하지 못했다면 역할/담당 강좌 변경을 실행하지 않습니다.** 표시된 5개가 전부라는 뜻도, 강사당 5개 제한이라는 뜻도 아닙니다. 전체 선택 보존 방식의 수정·검수 전에는 임의 저장하거나 누락 강좌를 수동 복구하는 방법으로 우회하지 않습니다.

### 역할 변경 <a href="#section-8" id="section-8"></a>

1. **상세 보기**에서 대상·현재 역할·운영 이력과 전체 담당 강좌를 확인합니다. 위 중단 조건에 해당하면 최종 실행을 보류합니다.
2. **역할 변경**으로 **운영자 역할 변경** 창을 엽니다. 본인 역할 변경과 소유자의 역할 변경은 이 절차로 처리하지 않습니다.
3. 새 역할을 선택합니다. 강사로 변경한다면 유지할 강좌까지 포함해 전체 선택을 확인합니다. 기존 역할을 그대로 두고 다른 역할을 추가하는 기능이 아닙니다.
4. 강사를 다른 역할로 바꾸면 기존 담당 강좌는 소유자로 이관되고 관리용 접근도 달라질 수 있습니다. 업무 인수인계를 먼저 확인합니다.
5. 승인된 대상·역할·전체 강좌가 맞을 때만 **변경**을 한 번 누릅니다. **취소**는 입력을 적용하지 않습니다.
6. **운영자 역할을 변경했습니다.** 안내 후 같은 대상의 최신 역할·담당자·업무 접근을 대조합니다.

### 강사 담당 강좌 설정 <a href="#section-9" id="section-9"></a>

1. 전체 목록 확인과 중단 조건 검토를 마친 강사 상세의 **담당 강좌 → 설정**을 엽니다.
2. **담당 강좌 설정**에서 새로 맡길 강좌뿐 아니라 **기존에 계속 맡을 강좌도 모두 선택**합니다. 추가분만 고르는 방식이 아닙니다.
3. 선택에서 제외한 기존 강좌는 소유자로 이관됩니다. 다른 강사의 강좌를 선택하면 해당 강좌의 담당 강사가 바뀝니다. 전체 선택을 해제한 저장은 기존 담당 강좌를 모두 제외하는 작업이므로 연습용으로 실행하지 않습니다.
4. 변경 사유·유지/추가/제외 강좌·기존 담당자 영향을 확인하고 **저장**을 한 번 누릅니다. 대상 범위가 불명확하면 **취소**합니다.
5. **담당 강좌를 설정했습니다.** 안내 후 최신 상세·전체 강좌 담당자·이전/새 담당자의 실제 접근을 확인합니다. 일부 상세 목록이나 성공 안내만으로 전체 보존을 판정하지 않습니다.

> **화면 예시 준비 중** · 유지할 강좌까지 전체 선택을 확인합니다. 6개 이상 또는 전체 미확인이면 변경 저장을 중단합니다.

## 5. 운영자 역할 해제하기 <a href="#step-5" id="step-5"></a>

> **해제 전 확인:** 화면의 **삭제**는 운영자 역할 해제입니다. 대상 계정은 회원(Student) 역할로 바뀌며 기존 학부모 역할로 자동 복원되지 않습니다. 담당 강좌·관리용 접근과 로그인 세션에도 영향이 있으므로 소유자가 대상·인수인계·영향을 승인한 경우에만 처리합니다. 회원 탈퇴·구매 취소·환불을 대신하지 않습니다.

1. 소유자 계정과 운영자 삭제 권한을 확인하고 대상의 역할·담당 강좌·인수인계 필요 사항을 확인합니다. 매니저에게 버튼이 보이더라도 해제를 진행하지 않습니다.
2. 목록의 해당 운영자 점 세 개 액션 메뉴 → **삭제**를 엽니다. 소유자와 본인은 해제 대상이 아닙니다.
3. **운영자 삭제** 확인 창의 이름과 **이 작업은 되돌릴 수 없습니다.** 안내를 읽습니다. 기존 역할·담당 범위를 자동으로 되돌리는 기능으로 생각하지 않습니다.
4. 승인된 대상이 맞을 때만 확인 창의 최종 **삭제**를 한 번 누릅니다. 단순 역할 교체가 목적이면 삭제로 대신 처리하지 않습니다.
5. 최신 운영자 목록에서 대상이 제외됐는지, 회원 역할·강좌 인계·관리 접근과 세션 처리 결과가 예상과 같은지 확인합니다. 구매 권리·주문은 별도로 대조합니다.

강사 해제 시 담당 강좌는 소유자로 이관됩니다. 관리용 접근 정리와 모든 기기 로그아웃 처리가 있지만, 이미 발급된 접근 토큰까지 즉시 모두 무효화된다고 보장하지 않습니다. 역할을 해제했다고 유료 구매 권리나 계정 데이터가 삭제됐다고 안내하지 않습니다.

> **화면 예시 준비 중** · 운영자 삭제는 회원 역할로 전환하는 작업입니다. 회원 탈퇴·구매 취소가 아닙니다.

## 6. 결과와 운영 기록 확인하기 <a href="#step-6" id="step-6"></a>

성공 안내 후 최신 조회가 끝난 목록/상세를 확인합니다. 오래 열린 화면이나 결과가 불명확한 요청을 근거로 지정·변경·해제를 반복하지 않습니다.

상세의 **운영 이력**에는 지정일·최근 로그인·지정자 등이 표시됩니다. **최근 활동 로그**는 일부 최근 기록이며 **전체 로그** 또는 목록의 **활동 로그 보기**, **운영 → 운영자 활동 로그**는 별도 조회 화면입니다. 별도 로그 읽기 권한이 필요할 수 있으며 링크 노출 자체가 조회 권한 증거는 아닙니다.

로그에서 대상·시각·작업·결과를 대조하되 모든 변경이나 학생의 모든 행동이 기록된다고 가정하지 않습니다. 역할 변경의 로그는 작업한 운영자 기준일 수 있으므로 변경 대상의 최근 기록에 없다는 이유만으로 실패로 판단하지 않습니다. 최종 역할·전체 담당자·실제 접근 결과와 함께 확인합니다.

조회/작업 실패·좌석 제한·결과 불명확이면 대상·선택 역할·강좌·시도 시각·오류를 정리합니다. 좌석을 비우려고 다른 운영자를 삭제하거나 조교 답변 권한을 만들려고 매니저로 임의 승격하지 않습니다.

> **화면 예시 준비 중** · 최신 정보와 실제 접근을 대조합니다. 일부 최근 기록만으로 전체 결과를 확정하지 않습니다.

> **동작 예시 준비 중** · 대상과 역할·담당자를 확인하는 예시입니다. 최종 지정 전 취소하며 변경은 적용하지 않습니다.

## 완료 후 확인 <a href="#completion-checklist" id="completion-checklist"></a>

- [ ] 같은 사이트의 대상 회원을 식별하고 기존 운영자·동명이인을 구분했습니다.
- [ ] 이메일 초대가 아닌 기존 회원 지정이며 역할 교체와 권한 편집이 다름을 확인했습니다.
- [ ] 지정/변경·해제의 역할/권한과 플랜·구독·좌석 조건을 확인했습니다.
- [ ] 강사 강좌 미선택 가능과 기존 담당자 이관 영향을 확인했습니다.
- [ ] 전체 담당 강좌를 확인하고 6개 이상 또는 전체 범위 미확인 대상의 변경 저장을 중단했습니다.
- [ ] 변경 시 유지/추가/제외 강좌·인수인계와 본인/소유자 제한을 확인했습니다.
- [ ] 해제의 회원 역할 전환·강좌/관리 접근·세션 영향과 구매 권리 보존을 확인했습니다.
- [ ] 최신 목록/상세·필요한 실제 업무 접근을 대조하고 부분 로그만으로 완료를 확정하지 않았습니다.
- [ ] 실패·불명확 결과는 재조회 후 담당자에게 확인하고 임의 재실행·승격·삭제하지 않았습니다.

| 담당 강좌가 5개만 보여요 | 전체가 5개라는 증거가 아닙니다. 6개 이상 또는 전체 미확인이면 역할/담당 설정 저장을 중단하고 담당자에게 확인합니다 |

| 본인 역할 변경이나 매니저의 삭제가 실패해요 | 본인 역할 변경은 제한되고 해제는 소유자 전용입니다. 버튼 표시만으로 허용됐다고 판단하지 않습니다 |
| 해제했는데 회원 계정·구매 내역이 남아요 | 운영자 해제는 회원 역할 전환입니다. 탈퇴·구매 취소·환불과 다르며 학부모 역할 자동 복원도 아닙니다 |
| 전체 로그가 안 열리거나 기록이 없어요 | 별도 읽기 권한·조건·작업자 기준·기록 범위를 확인합니다. 최근 기록 없음이 미처리 증거는 아닙니다 |
| 성공 안내 뒤 화면이 다르거나 연결이 끊겼어요 | 최신 역할·전체 담당자·접근 결과를 재조회합니다. 미처리로 단정해 같은 작업을 반복하지 않습니다 |
