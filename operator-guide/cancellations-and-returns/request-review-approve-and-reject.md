# 신청 확인·승인·거절하기

<figure><img src="../.gitbook/assets/branding/page-headers/cancellations-and-returns/request-review-approve-and-reject-v2.png" alt="신청 확인·승인·거절하기 대표 이미지"><figcaption></figcaption></figure>

**업무 대상:** 취소·반품·교환 처리를 맡은 담당자용 안내입니다. 해당 처리 업무를 맡지 않은 강사·질답 조교는 환불을 확정하거나 승인하지 말고 학생의 요청을 처리 담당자에게 전달하세요. 실제 작업 가능 범위는 본인 계정의 권한을 확인하세요.

접수된 신청의 대상과 사유를 확인하고, 담당자가 승인하거나 거절한 뒤 최신 처리 결과를 확인할 때 사용합니다. 구성품별 취소 조건, 교재 회수·검수·재배송의 상세 절차는 별도 가이드에서 다룹니다.

**심사 내용을 저장하는 것과 환불을 승인하는 것은 다릅니다. 승인 응답이나 성공 알림만으로 환불 완료를 안내하지 않습니다.** 교환 완료도 환불 완료와 구분합니다.

**확인 순서:** 신청 찾기 → 대상·수량·유형·상태·이력 확인 → 필요한 심사·검수 확인 → 취소/반품은 최신 금액 재확인 후 승인, 교환은 별도 재배송·수령 절차 → 같은 신청의 최신 결과 확인. 거절은 각 유형의 허용 상태에서 사유와 함께 처리합니다.

## 시작 전 준비 <a href="#before-you-start" id="before-you-start"></a>

| 준비할 것 | 확인 기준 |
| --- | --- |
| 현재 사이트·담당 계정 | 해당 사이트의 신청을 조회·처리할 수 있는지 확인 |
| 권한 | 조회 권한과 승인·거절·심사 권한을 구분 |
| 대상 신청 | 신청 식별정보와 주문번호. 같은 주문에 여러 신청이 있을 수 있음 |
| 구매 당시 구성 | 상품·구성품 이름과 유형, 구매 수량·신청 수량 |
| 판단 근거 | 신청 사유·연락처, 이용 기록·발송/수령 사실·심사/검수 기록 |
| 후속 담당자 | 환불 결과 확인 또는 교재 회수·검수·재배송을 맡는 담당자 |

학생 이름·연락처·이용 기록·주문 정보는 확인된 업무 경로에서만 다룹니다. 문의에 화면을 전달할 때는 불필요한 개인정보를 가립니다.

## 메뉴 위치 <a href="#menu-location" id="menu-location"></a>

**결제/정산관리 → 취소·반품·교환 내역**에서 신청 목록과 상세를 엽니다. 상세에서 승인 전 금액, 귀책·이용 기록 심사, 반품·교환 단계를 각각 확인합니다. 지금 처리할 신청의 식별정보와 원 주문번호를 상세에서 대조합니다. 이 안내만으로 실제 조회·처리 권한이나 환불·후속 처리 결과를 확정할 수 없습니다. 확인되지 않은 결과는 완료로 안내하지 않습니다.

구성품별 신청과 주문 전체 환불의 버튼·신청번호를 서로 대신 사용하지 마세요. 신청 조회, 심사 저장, 환불 승인, 실제 교재 회수·배송은 서로 다른 작업입니다. 필요한 화면을 사용할 수 없으면 다른 경로로 우회하지 말고 담당자에게 확인합니다.

## 1. 처리할 신청 찾기 <a href="#step-1" id="step-1"></a>

목록의 검색·필터·요청 기간과 정렬 순서를 이용하거나 페이지를 옮겨 같은 신청을 찾습니다. **요청 기간**은 신청일 기준이며 주문일/발송일과 구분합니다. 적용한 조회 조건을 확인하고, 조회 결과가 없는 경우와 조회 오류가 발생한 경우를 구분합니다.

| 조회 기준 | 확인할 것 |
| --- | --- |
| 검색 | 학생 이름·이메일, 주문번호·주문명, 신청 사유 |
| 신청 유형 | 취소·반품·교환 중 어떤 업무인지 |
| 처리 상태 | 접수·심사·반품/교환 진행·거절·환불 처리 중·완료 구분 |
| 구성품 유형 | 강좌·교재·디지털 자료 중 대상 확인 |
| 처리 경로 | 자동 취소·관리자 심사·반품 검수·수동 교환 구분 |
| 신청 기간 | 주문일이 아니라 신청일 기준. 날짜 범위는 한국 시간 기준 양 끝 날짜 포함 |
| 정렬·건수 | 신청일·예상 취소액 정렬과 현재 조회 조건의 건수 확인. 미확정 금액을 0원으로 취급하지 않음 |

검색 결과가 없으면 현재 사이트·기간·유형·상태와 주문번호를 먼저 확인합니다. 조회 오류를 신청 없음으로 판단하거나 같은 신청을 새로 만들도록 안내하지 않습니다.

> **화면 예시 준비 중** · 신청 유형·처리 상태와 조회 조건을 대조해 대상을 찾습니다.

## 2. 신청 대상·사유·현재 상태 확인하기 <a href="#step-2" id="step-2"></a>

상세를 열면 같은 주문의 다른 신청과 혼동하지 않도록 아래 내용을 대조합니다.

| 항목 | 확인 기준 |
| --- | --- |
| 신청·주문 | 지금 처리할 신청 식별정보와 주문번호 일치 |
| 상품·구성품 | 구매 당시 구성품 하나가 대상인지 확인. 현재 판매 상품의 이름·가격과 구분 |
| 수량 | 원 구매 수량과 이번 신청 수량 구분. 같은 주문의 다른 신청도 확인 |
| 사유·연락처 | 신청 상세 사유와 필요한 확인 내용을 대조 |
| 금액 | 주문 전체 결제액·구성품 결제액·예상 취소액·확정 취소액 구분 |
| 처리 이력 | 처리자·시각·사유·상태 변경을 확인. 조회할 수 없는 처리자 이름은 추정하지 않음 |
| 적용 상태 | 이용 제한·해제 등 해당 신청의 적용 결과가 대기인지 확인 |

**운영자가 승인 단계에서 구성품·수량·금액을 임의로 바꾸는 절차는 아닙니다.** 대상이 잘못됐거나 수량이 다르면 처리를 멈추고 현재 신청과 허용된 후속 업무를 확인합니다. 모든 구성품을 한 번에 취소하거나 새 신청을 중복 생성하지 않습니다.

아래는 처리 단계의 의미입니다. 실제 화면의 표시명은 아직 확인되지 않은 부분이 있으므로, 문구만으로 판단하기 어렵다면 해당 신청의 처리 결과를 담당자에게 확인합니다.

| 업무 단계 | 해야 할 확인 |
| --- | --- |
| 접수·심사 | 신청 대상과 최신 근거 확인. 자동 처리 경로라는 이유만으로 완료 판정하지 않음 |
| 반품 진행 | 회수·입고·검수 단계를 확인. 검수 합격만으로 환불 완료 판정하지 않음 |
| 교환 진행 | 회수·입고·검수·재배송·수령 단계를 확인하고, 저장한 재배송·수령 기록의 상태 반영(동기화)도 확인. 일반 환불 승인과 구분 |
| 환불 처리 중 | 같은 신청의 결과 확인. 승인·거절·새 취소를 반복하지 않음 |
| 거절 | 사유와 해당 신청의 이용 제한 해제 적용 결과 확인 |
| 완료 | 취소/반품 완료인지 교환 완료인지 구분하고 후속 결과 대조 |

신청 접수와 이용 제한 적용은 별개일 수 있습니다. 거절 상태가 됐어도 해제 반영은 대기일 수 있으며, 신청 하나가 다른 주문·수강권까지 취소하거나 복원하는 것은 아닙니다.

> **화면 예시 준비 중** · 같은 주문의 다른 신청과 구분하고 대상·사유·현재 결과를 확인합니다.

## 3. 심사·반품·교환 중 필요한 업무 구분하기 <a href="#step-3" id="step-3"></a>

| 신청 상황 | 이어서 할 업무 | 완료로 오해하지 않을 것 |
| --- | --- | --- |
| 취소 조건·금액을 확인할 수 있음 | 승인 전에 최신 조건·금액과 현재 처리 가능 여부 확인 | 자동 처리 경로·예상액 표시가 환불 완료는 아님 |
| 강좌·디지털 자료의 판매자 귀책 신청 | 해당 귀책 근거를 심사하고 인정 내용을 저장한 뒤 새 금액 확인·별도 승인 | 귀책 사유 선택·인정 저장만으로 환불하지 않음 |
| 강좌·디지털 자료 이용 기록 이의 | 이번 구매 권리에 속한 원본 기록을 확인·심사한 뒤 새 금액 확인·별도 승인 | 원본 삭제·진도 초기화·임의 시청시간/금액 입력 아님 |
| 교재 반품 | 회수·입고·검수·비용·재입고 가능 수량을 확인한 뒤 별도 환불 승인 | 회수 승인·검수 합격만으로 결제대행사(PG)를 통한 환불이나 교재 재입고가 완료되는 것은 아님 |
| 교재 교환 | 동일 교재의 회수·검수·수동 재배송·수령 확인 | 환불 승인 대상 아님. 원 결제를 환불하지 않음 |

귀책·이용 기록 심사에서 인정 내용을 저장했더라도 환불액이 아직 확정되지 않았을 수 있습니다. 이는 곧바로 오류나 0원 환불을 뜻하지 않습니다. 저장 후 최신 신청을 조회하고, **승인 전에 금액을 다시 확인**합니다.

심사 불인정·검수 불합격은 거절 가능한 상태에서 구체적인 사유와 함께 처리합니다. 교환은 재배송 등록 이후 거절할 수 없으므로 상세 단계도 반드시 확인합니다.

구성품별 조건·귀책/이용 기록 심사는 [구성품별 취소·환불 처리하기](component-cancellation-and-refund.md), 반품의 회수·입고·검수·비용·재입고는 [교재 반품 처리하기](textbook-return.md), 동일 교재 교환의 수동 재배송·수령·동기화는 [교재 교환 처리하기](textbook-exchange.md)를 확인하세요. 담당자에게 이용 가능한 방법을 확인하기 전에는 학생에게 해당 처리가 가능하다고 안내하지 않습니다.

## 4. 취소·반품의 최신 금액 확인 후 승인하기 <a href="#step-4" id="step-4"></a>

**승인 전 금액 확인은 조회입니다. 확인 결과를 열거나 심사를 저장하는 것만으로 환불이 실행되지 않습니다.** 교환에는 이 환불 승인 절차를 사용하지 않습니다.

상세의 **취소 승인**은 최신 조건/금액 확인창을 열고, 확인창의 최종 승인은 실제 승인 요청을 보냅니다. 두 단계를 구분하고, 조건·금액만 확인하려는 경우에는 최종 승인하지 않습니다.

1. 대상 신청을 다시 조회하고 현재 상태·처리 권한·적용 결과를 확인합니다.
2. 필요한 심사·반품 검수가 끝났는지 확인합니다. 적용이 대기 중이거나 근거가 부족하면 승인하지 않습니다.
3. 최신 신청 기준으로 승인 전 조건·금액을 다시 확인합니다.
4. 신청 구성품·수량·처리 가능 여부와 서버가 계산한 최신 취소액을 대조합니다.
5. 예상액이 미확정이면 금액을 직접 입력하거나 0원으로 바꾸지 않습니다. 실제 0원인 경우에도 처리 가능한 결과인지 구분합니다.
6. 확인한 최신 조건·금액으로 승인합니다. 변경 안내가 나오면 최신 상세·금액을 다시 확인한 뒤 승인 여부를 새로 판단합니다.
7. 같은 신청의 최신 상세를 다시 조회해 처리 상태·확정액·이력과 후속 결과를 확인합니다.

승인 금액은 현재 상품가·단가·주문 총액으로 대신 계산하지 않습니다. 이용 기록·배송·다른 취소가 먼저 반영되면 금액이나 처리 가능 여부가 달라질 수 있습니다. 오래된 결과를 자동 적용하지 않습니다.

> **화면 예시 준비 중** · 최신 조건·금액을 확인합니다. 조회만으로 환불되지는 않습니다.

> **동작 예시 준비 중** · 승인 후 같은 신청의 최신 상태·금액·후속 결과를 다시 확인합니다.

## 5. 거절 사유를 남기고 적용 결과 확인하기 <a href="#step-5" id="step-5"></a>

거절은 환불 실행이 아니라 해당 신청을 받아들이지 않는 처리입니다. 거절 상태와 기존 이용 제한 해제 완료를 구분합니다.

1. 최신 상세에서 현재 신청·사유·심사/검수 이력과 거절 가능한 단계를 확인합니다.
2. 판단 근거와 학생이 확인할 내용을 구체적인 사유로 작성합니다. 빈 사유로 처리하지 않습니다.
3. 담당자와 확인한 거절 화면과 순서에 따라 처리합니다. 다른 담당자의 선행 처리나 상태 변경 안내가 나오면 최신 상세를 다시 확인합니다.
4. 같은 신청을 재조회해 거절 상태·처리 사유·이력을 확인합니다.
5. 해당 신청의 이용 제한 해제가 적용됐는지 확인합니다. 대기 상태라면 복원 완료로 안내하지 않습니다.

환불 처리 중·완료 상태에서는 거절할 수 없습니다. 교환도 재배송 등록 이후에는 거절할 수 없으며, 원 배송 상태를 되돌리거나 송장을 바꿔 우회하지 않습니다.

처리 결과 안내만으로 전체 이력이 확인된 것은 아닙니다. 최신 상세에서 처리자·시각·사유를 다시 대조합니다. 조회할 수 없는 값은 임의로 채우지 않습니다.

## 6. 처리 결과를 확인하고 학생에게 안내하기 <a href="#step-6" id="step-6"></a>

| 최신 결과 | 확인·안내 기준 |
| --- | --- |
| 환불 처리 중 | 결과 확인·후속 적용이 남아 있음. 실패·완료를 단정하거나 승인/취소를 반복하지 않음 |
| 확정 취소액은 있지만 아직 처리 중 | 금액 확정과 대상 권리·배송/재고 후속 처리를 구분 |
| 취소·반품 완료 | 해당 신청의 확정액과 권리·배송/재고 결과 확인. 카드/계좌 반영 시점·정산 지급 완료와 구분 |
| 취소 조건을 충족하고 환불액이 0원인 취소 완료 | 취소 후속 결과 확인. 0원 입금이나 PG 환불 거래가 생겼다고 안내하지 않음 |
| 거절·해제 적용 대기 | 거절 사유는 기록됐지만 해제 확인은 남아 있음. 즉시 이용 복원으로 안내하지 않음 |
| 거절·해제 적용 확인 | 이번 신청의 제한 해제와 실제 이용 결과 대조. 다른 주문·만료 권리까지 복원한다고 안내하지 않음 |
| 교환 완료 | 재배송 수령·동기화가 확인된 교환 결과. 확정 취소액 없음은 환불 실패가 아님 |

결과가 불명확하면 **같은 신청의 식별정보·주문번호·최신 상태·처리 시각·확인되지 않은 결과**를 담당자에게 전달합니다. 새 신청·재승인·중복 PG 취소로 해결하려 하지 않습니다. 담당자 승인 없이 재처리하거나 처리 데이터를 직접 고치지 않습니다.

학생에게는 확인된 대상·사유·금액·처리 단계와 아직 확인이 필요한 사항만 안내합니다. 확인되지 않은 카드/계좌 반영 기한을 약속하지 않습니다. 안내 전에 구매자의 신청 상태 표시와 운영자 최신 상세가 같은 결과인지도 확인합니다.

> **화면 예시 준비 중** · 거절 기록과 해제 적용, 환불 처리 중과 전체 완료를 구분합니다.

## 완료 후 확인 <a href="#completion-checklist" id="completion-checklist"></a>

- [ ] 현재 사이트·조회/처리 권한과 정확한 신청·주문을 확인했습니다.
- [ ] 구매 당시 구성품 하나·원 구매 수량·신청 수량을 대조했습니다.
- [ ] 신청 유형·처리 경로·상태·심사/검수 이력을 구분했습니다.
- [ ] 주문 총액·구성품 결제액·예상/확정액과 미확정/0원을 구분했습니다.
- [ ] 필요한 심사·검수 후, 승인 전에 최신 조건·금액을 확인했습니다.
- [ ] 금액·대상·수량·원본 기록을 임의 수정하거나 중복 처리하지 않았습니다.
- [ ] 승인/거절 후 같은 신청의 최신 상세·사유·이력을 재조회했습니다.
- [ ] 환불 처리 중인 상태, 취소 결과·환불액이 클킷에 확정 기록된 단계, 권리·배송·재고의 후속 처리와 전체 완료를 구분했습니다.
- [ ] 거절 시 해당 신청의 제한 해제, 교환 시 재배송·수령·동기화 결과를 확인했습니다.
- [ ] 학생에게 확인된 결과만 안내하고 남은 확인은 담당자에게 전달했습니다.

## 자주 막히는 상황 <a href="#troubleshooting" id="troubleshooting"></a>

| 상황 | 확인할 것 |
| --- | --- |
| 환불 목록에 신청이 보이지 않음 | 구성품별 신청과 주문 전체 환불을 구분합니다. 현재 사이트·조회 조건과 실제 신청 경로를 담당자에게 확인합니다. 다른 환불 버튼으로 대신 처리하지 않습니다 |
| 상세는 보이지만 승인·거절이 불가 | 처리 권한·최신 상태·적용 대기·교환 재배송 단계 확인. 조회 권한만으로 실행하지 않음 |
| 심사를 저장했는데 금액이 없음 | 저장과 금액 재계산·승인 분리. 승인 전에 최신 조건·금액 확인 필요, 0원으로 대체 금지 |
| 금액·조건 변경 또는 동시 처리 안내 | 최신 신청·이력·조건·금액 재조회 후 재확인. 오래된 결과 덮어쓰기 금지 |
| 성공 알림 뒤 아직 처리 중 | 같은 신청의 최신 상세와 후속 결과 확인. 새 신청·재승인·거절 반복 금지 |
| 거절됐지만 이용할 수 없음 | 해당 신청 해제 적용, 실제 권리·기간·다른 제한 확인. 다른 권리를 임의 복원하지 않음 |
| 교환에 확정 환불액이 없음 | 교환은 환불이 아님. 재배송·수령·동기화와 전체 완료 확인 |
