# 페이지·메뉴 구성하기

> **검토용 가이드** · 실제 서비스 화면·동작 확인과 이미지 보완이 남아 있습니다. 본문의 실행 보류·주의사항을 먼저 확인하세요.

<figure><img src="../.gitbook/assets/branding/site-and-communication-illustration-v1.png" alt="사이트·소통 대표 이미지"><figcaption></figcaption></figure>

사이트에 안내 페이지를 준비하고, 방문자가 찾을 수 있도록 메뉴에 연결합니다. **페이지는 내용과 주소**, **메뉴는 이동 경로와 순서**를 관리합니다. 페이지 생성, 작업본 저장, 발행, 페이지 공개, 메뉴 노출은 서로 다른 작업입니다.

**완료 기준:** 의도한 페이지의 발행본·공개 상태를 확인하고, 저장한 메뉴가 PC·모바일에서 올바른 페이지로 연결됩니다. 관리자 미리보기나 저장 안내만으로 완료를 판단하지 않습니다.

> **커스텀 페이지 편집은 대상 연결 확인 전까지 중단하세요.**
> 커스텀 페이지와 메인 페이지의 편집 대상이 섞일 위험이 있습니다. 편집 대상이 안전하게 구분되는지 확인되기 전에는 커스텀 페이지의 빌더 진입·편집·저장·게시를 진행하지 않습니다.

## 시작 전 준비 <a href="#before-you-start" id="before-you-start"></a>

| 준비할 것 | 예시·확인 기준 |
| --- | --- |
| 제공 범위·권한 | 페이지 관리가 제공되는 환경인지 확인합니다. 페이지·메뉴 조회, 생성, 수정·발행·공개, 삭제 권한은 같지 않을 수 있습니다 |
| 페이지 이름·주소 | 이름 `학습 안내`, URL 입력값 `study-guide`. 이름과 URL은 각각 직접 입력합니다 |
| 페이지 내용 | 제목·소개·이미지·연결할 콘텐츠를 준비합니다. 학생 개인정보나 회원 전용 자료를 공개 페이지에 넣지 않습니다 |
| 메뉴 구조 | `학습 안내 → 이용 방법 / 자주 묻는 질문`처럼 상위·하위를 정합니다. 같은 위치의 이름·페이지 중복을 피합니다 |
| 연결할 기존 페이지 | 메뉴 작업은 실제 사용 가능한 페이지부터 진행합니다. 커스텀 페이지라면 발행본·공개·접속 결과가 확인된 대상이어야 합니다 |
| 작업 환경 | 빌더의 편집 대상 확인은 승인된 테스트 사이트와 PC 환경에서 합니다. 운영 메인 페이지로 문제를 재현하지 않습니다 |

페이지 관리 메뉴가 없거나 열리지 않으면 담당자에게 제공 여부·배포 환경·권한을 확인합니다. 메뉴 관리가 보인다는 이유로 새 페이지 편집까지 제공된다고 판단하지 않습니다.

## 메뉴 위치 <a href="#menu-location" id="menu-location"></a>

관리자 **홈페이지 관리**에서 작업에 맞는 메뉴를 엽니다.

| 메뉴 | 할 일 |
| --- | --- |
| 페이지 관리 | 페이지 검색·생성, 상세의 이름·URL·공개 상태·연결된 메뉴 확인 |
| 메뉴 관리 | 상위·하위 메뉴 이름, 페이지 연결, 메뉴 공개·순서 변경 |

페이지 상세의 **메뉴 관리로 이동**을 사용해 연결 작업으로 이동할 수도 있습니다. 사이트 이름·로고·전체 SEO는 [사이트 기본 정보 설정하기](site-basic-information.md)와 구분합니다.

## 1. 페이지 상태부터 확인하기 <a href="#step-1" id="step-1"></a>

**페이지 관리**에서 페이지명 또는 URL을 입력하고 **검색**을 누릅니다. **전체 / 기본 페이지 / 커스텀 페이지** 탭과 **공개 범위 / 발행 상태** 필터를 구분하며, 필터를 바꾼 뒤에는 **적용하기**를 누릅니다. 입력·선택만으로 조회 조건이 적용됐다고 판단하지 않습니다.

| 표시 | 뜻 | 함께 확인할 것 |
| --- | --- | --- |
| 공개·비공개 | 페이지를 방문자에게 제공할지 정한 설정 | 커스텀 페이지는 발행본도 있어야 합니다 |
| 발행됨·미발행 | 발행본 유무를 나타내는 표시 | 공개 여부·실제 접속 결과를 따로 확인합니다 |
| 게시됨·임시저장 | 저장된 작업본 유무를 나타내는 표시 | 게시됨 표시만으로 발행·공개 완료를 판단하지 않습니다 |
| 연결된 메뉴·연결 없음 | 페이지로 이동하는 메뉴 연결 정보 | 메뉴 공개와 실제 노출도 따로 확인합니다 |

**기본 페이지와 커스텀 페이지는 같은 편집 절차를 쓰지 않습니다.** 기본 기능 페이지의 웹빌더 편집은 현재 상세에서 준비 중으로 표시됩니다. 기본 페이지의 상태 표시나 이동 경로를 커스텀 페이지의 발행 절차로 대신 사용하지 않습니다.

> **화면 예시 준비 중** · 공개 여부·발행본·작업본 상태를 따로 확인합니다. 게시됨 표시만으로 방문자 공개를 판단하지 않습니다.

## 2. 새 페이지의 이름·주소 준비하기 <a href="#step-2" id="step-2"></a>

페이지 생성이 제공되는 환경과 생성 권한을 확인한 뒤 진행합니다.

1. **페이지 생성**을 엽니다.
2. **페이지명**에 이름을 입력합니다. 예: `학습 안내`.
3. **페이지 URL**에 고유 경로를 입력합니다. 예: `study-guide`. 화면의 `/` 접두사를 입력값에 중복해서 넣지 않습니다.
4. 필요하면 **SEO·공유 설정 → 설정 열기**에서 이 페이지의 검색·공유 정보를 준비합니다.
5. **페이지 생성**을 누른 뒤 같은 이름·URL의 상세가 열리는지 확인합니다.
6. 생성 직후에는 **비공개·미발행**입니다. 방문자에게 보여줄 준비가 끝난 것으로 안내하지 않습니다.

| 입력 | 준비 기준 |
| --- | --- |
| 페이지명 | 1~50자. 메뉴에 표시할 이름과 별개입니다 |
| 페이지 URL | 1~60자의 영문 소문자·숫자·단어 사이 하이픈. `study-guide`처럼 입력하고 공백·한글·여러 단계 경로는 사용하지 않습니다 |
| 주소 중복·예약어 | 기존 주소나 `admin`, `products`, `notice` 등 시스템 주소는 사용할 수 없습니다. 오류가 나면 안내된 항목을 확인합니다 |
| 페이지별 SEO·공유 | 선택 입력입니다. 제목 40자·설명 120자 이내의 짧은 문구부터 준비합니다. 전체 사이트 SEO와 별도 설정입니다 |

페이지별 SEO·공유 정보는 이 페이지의 설정이며 [사이트 전체 SEO](site-basic-information.md)를 바꾸는 작업이 아닙니다. 페이지별 공유 이미지의 용량 안내와 실제 저장 시 허용 기준에 차이가 있으므로, 사용할 파일 기준은 담당자에게 먼저 확인합니다. 생성 중 이미지 업로드 오류가 나면 페이지까지 생성됐다고 가정하지 말고 목록을 먼저 확인합니다.

> **화면 예시 준비 중** · 이름과 URL을 입력해 생성합니다. 생성된 페이지는 비공개·미발행으로 시작합니다.

## 3. 작업본·발행·페이지 공개 구분하기 <a href="#step-3" id="step-3"></a>

**현재 커스텀 빌더 연결 문제로 이 단계의 실행은 확인 대기입니다.** 생성된 페이지에서 웹빌더로 바로 이동해 작업하지 않습니다. 아래 순서는 편집 대상 연결이 수정되고 실제 결과가 확인된 뒤에만 진행합니다. 현재 사용할 수 있는 작업 절차로 받아들이지 마세요.

| 순서 | 확인할 작업 | 다음으로 넘어갈 기준 |
| --- | --- | --- |
| 편집 대상 확인 | 선택한 페이지의 이름·URL과 실제 불러온 내용을 대조 | 선택한 커스텀 페이지가 조회·저장·게시 대상인지 실제 결과로 확인했습니다 |
| 작업본 저장 | 작업 중인 내용을 저장하고 같은 페이지를 다시 열어 확인 | 저장 실패·오프라인·다른 페이지 저장이 없고 내용이 유지됩니다 |
| 미리보기 | PC·모바일 구성과 링크·이미지·글자 잘림 점검 | 관리자 미리보기와 실제 공개 결과가 다름을 구분합니다 |
| 발행 | 검토한 내용을 발행본으로 반영 | 대상 페이지의 최신 발행 결과를 확인했습니다 |
| 페이지 공개 | 상세의 페이지 공개 설정과 결과 확인 | 커스텀 페이지의 발행본·공개 상태·직접 URL 접속이 확인됩니다 |

빌더의 **저장**은 작업본 보관이고 **게시하기**는 발행 동작입니다. 커스텀 페이지의 **페이지 공개**와 같은 설정이 아닙니다. 공개 중인 페이지를 수정할 때는 작업본과 기존 발행본을 구분합니다. 새 발행 결과가 확인되기 전에는 방문자에게 변경 완료라고 안내하지 않습니다.

‘현재 공개 화면 보기’가 보인다고 실제 공개 접근이 성공한 것은 아닙니다. 발행본이 있어도 비공개이면 방문자에게 제공되지 않을 수 있으므로 직접 URL과 페이지 상태를 대조합니다. 메뉴 연결은 이 확인을 마친 페이지를 대상으로 진행합니다.

> **화면 예시 준비 중** · 선택한 페이지와 실제 저장·발행 대상을 대조하고 발행본·페이지 공개를 각각 확인합니다.

## 4. 메뉴 만들고 페이지 연결하기 <a href="#step-4" id="step-4"></a>

**메뉴 관리**에서 상위 메뉴를 선택합니다. 메뉴 이름은 현재 입력 화면에 맞춰 10자 이내의 짧은 이름으로 준비합니다. 최종 이름 길이와 상위·하위 메뉴 개수 제한은 아직 확인되지 않았으므로 화면 카운터와 제한 안내를 함께 확인합니다.

| 구조 | 페이지 연결 방식 |
| --- | --- |
| 하위 메뉴가 없는 상위 메뉴 | 상위 메뉴에 페이지를 직접 연결합니다 |
| 하위 메뉴가 있는 상위 메뉴 | 페이지를 상위에 직접 연결하지 않고 각 하위 메뉴에 연결합니다 |
| 하위 메뉴 | 연결 페이지가 필요합니다. 같은 상위 아래 다른 하위 메뉴와 이름·연결 페이지가 중복되지 않게 합니다 |

### 하위 메뉴 없는 상위 메뉴 만들기 <a href="#section-7" id="section-7"></a>

1. **새 상위 메뉴 추가**를 누릅니다.
2. **상위 메뉴 이름**을 입력합니다.
3. 연결 아이콘의 **페이지 선택**에서 사용할 페이지를 찾습니다. 이름·URL·공개/발행 상태를 대조합니다.
4. **변경사항 저장**을 누릅니다. 페이지를 선택한 것만으로 메뉴 연결이 저장되지는 않습니다.
5. 다시 열어 메뉴 이름과 연결 페이지를 확인합니다. 새 메뉴는 **비공개**로 시작합니다.
6. 연결 페이지의 공개·사용 가능 상태를 확인한 뒤 메뉴 공개를 켜고 **변경사항 저장**합니다. 새 메뉴 생성과 메뉴 공개는 별도 저장입니다.

### 하위 메뉴 추가하기 <a href="#section-8" id="section-8"></a>

1. 하위 메뉴를 둘 상위 메뉴를 선택하고 **새 하위 메뉴 추가**를 누릅니다.
2. 하위 메뉴 이름과 연결 페이지를 지정하고 **변경사항 저장**합니다.
3. **첫 하위 메뉴를 저장하면 상위 메뉴의 기존 직접 페이지 연결이 해제됩니다.** 기존 페이지를 계속 노출하려면 필요한 하위 메뉴에 다시 연결할지 먼저 검토합니다. 페이지 자체가 삭제되는 것은 아닙니다.
4. 각 하위 메뉴의 연결·공개 상태를 저장하고 다시 확인합니다.
5. 상위 메뉴도 공개 상태인지 확인합니다. 공개 가능한 하위 메뉴가 없으면 상위 메뉴가 표시되지 않을 수 있습니다.

**공개 설정과 실제 노출은 다릅니다.** 메뉴가 공개여도 연결 페이지가 없거나 비공개·미발행이면 보이지 않을 수 있습니다. 하위 메뉴는 상위 메뉴의 공개 여부도 함께 확인합니다.

> **화면 예시 준비 중** · 메뉴 구조에 맞는 페이지를 연결합니다. 첫 하위 메뉴를 저장하면 상위의 직접 연결은 해제되지만 페이지는 남습니다.

> **동작 예시 준비 중** · 메뉴 연결과 공개를 저장한 뒤 다시 열어 확인하고, 방문자 메뉴에서 의도한 페이지로 이동하는지 확인합니다.

## 5. 메뉴 순서·노출 변경하기 <a href="#step-5" id="step-5"></a>

순서를 바꾸기 전에 이름·연결·공개 변경을 먼저 저장하고 다시 확인합니다. 여러 종류의 변경이 한꺼번에 저장되면 일부 요청만 성공할 수 있어 각각의 결과를 확인해야 합니다.

1. 상위 메뉴끼리 순서를 옮깁니다. 하위 메뉴는 **순서 변경**에서 같은 상위 아래의 순서를 옮깁니다.
2. **순서 변경 완료**로 편집을 마쳐도 클킷에 저장된 것은 아닙니다. **변경사항 저장**을 누릅니다.
3. 같은 메뉴를 다시 열어 순서가 유지되는지 확인합니다.
4. 노출을 중단할 메뉴는 메뉴 공개를 끄고 **변경사항 저장**한 뒤 방문자 내비게이션에서 확인합니다.

하위 메뉴를 다른 상위 메뉴로 끌어 옮길 수 있다고 가정하지 않습니다. 저장 전 다른 메뉴를 선택하면 입력 중인 값이 바뀔 수 있으므로 한 메뉴씩 저장하고 이동합니다.

> **화면 예시 준비 중** · 순서 변경 완료 뒤 변경사항을 저장합니다. 다시 열어 순서가 유지되는지 확인합니다.

## 6. 방문자 화면과 직접 URL 확인하기 <a href="#step-6" id="step-6"></a>

PC·모바일에서 메뉴 이름·상하위 구조·순서와 링크 결과를 확인합니다. 메뉴를 눌러 이동한 주소가 설정한 페이지 URL인지, 내용이 의도한 발행본인지 대조합니다. 로그인 회원과 비회원의 결과도 필요한 범위에서 각각 확인합니다.

**메뉴를 숨겨도 연결 페이지가 비공개가 되는 것은 아닙니다.** 공개된 페이지는 메뉴가 없어도 직접 주소로 접근할 수 있습니다. 메뉴 노출, 페이지 공개, 사이트 운영 중지, 강좌·자료의 회원/구매 권한을 같은 설정으로 취급하지 않습니다.

> **화면 예시 준비 중** · PC·모바일 메뉴의 구조·순서와 도착 페이지를 확인합니다. 메뉴 숨김과 페이지 비공개는 다릅니다.

## 기존 페이지 수정·정리할 때 <a href="#section-11" id="section-11"></a>

| 작업 | 변경 전 확인 |
| --- | --- |
| 페이지 이름 변경 | 상세의 페이지 이름을 수정해 저장합니다. 페이지 URL이나 메뉴 이름까지 자동 변경된다고 판단하지 않습니다 |
| 접속 URL 변경 | 외부 링크·북마크·검색 결과에 영향을 줍니다. 발행 이력이 있는 주소 변경에는 30일 재변경 제한과 이전 주소 전환 처리가 있으므로 안내문·링크 수정 계획부터 확인합니다. 영구 전환을 보장하지 않습니다 |
| 복제해서 새 페이지 만들기 | 새 이름·URL을 지정합니다. 작업본이 있으면 작업본을 우선 복사하며 복제본은 비공개·미발행이고 메뉴 연결은 따라오지 않습니다. 빌더 연결 문제 해결 전 복제본 편집도 진행하지 않습니다 |
| 메뉴 삭제 | 삭제 가능한 메뉴의 확인 창에서 대상을 대조합니다. 연결했던 페이지는 남습니다. 하위 메뉴가 있는 상위·기본 메뉴는 삭제가 제한될 수 있습니다. 상위 삭제의 최종 버튼 위치는 확인 대기입니다 |
| 페이지 삭제 | 커스텀 페이지의 삭제 확인 창에서 이름과 연결 메뉴를 확인합니다. 페이지가 사라지고 해당 메뉴 연결도 끊어집니다. 방문자 링크와 메뉴 결과를 다시 확인합니다 |

삭제·URL 변경은 촬영이나 시험을 위해 운영 사이트에서 실행하지 않습니다. 실패했을 때 복구가 보장된다고 안내하지 않으며, 먼저 현재 목록·상세·연결 결과를 확인합니다.

## 완료 후 확인 <a href="#completion-checklist" id="completion-checklist"></a>

- [ ] 작업한 페이지의 이름·URL과 실제 편집·저장·발행 대상이 일치합니다. 빌더 연결 문제 해결 전에는 진행하지 않았습니다.
- [ ] 공개·발행·작업본 상태를 따로 확인했습니다. 생성·게시됨 표시만으로 공개 완료를 판단하지 않았습니다.
- [ ] 메뉴 이름·연결 페이지·상하위 구조와 새 메뉴의 공개 저장을 확인했습니다.
- [ ] 첫 하위 메뉴 추가로 해제된 상위 연결과 기존 페이지의 노출 계획을 확인했습니다.
- [ ] 순서를 저장하고 다시 열었을 때 같은 순서가 유지됩니다.
- [ ] PC·모바일 메뉴에서 의도한 URL과 내용을 확인했습니다.
- [ ] 메뉴 숨김·페이지 비공개·직접 주소 접근과 콘텐츠 수강 권한을 구분했습니다.

## 자주 막히는 부분 <a href="#troubleshooting" id="troubleshooting"></a>

| 상황 | 확인할 것 |
| --- | --- |
| 페이지 관리가 없거나 열리지 않아요 | 해당 환경의 제공 여부·배포·권한을 확인합니다. 메뉴 관리가 보인다는 사실만으로 페이지 관리도 제공된다고 판단하지 않습니다 |
| 선택한 페이지 대신 메인이 열려요 | 편집·저장·게시를 중단하고 대상 연결 문제를 담당자에게 알립니다. URL에 페이지 식별자가 있다는 이유만으로 올바른 대상을 저장한다고 판단하지 않습니다 |
| 페이지 생성·URL 저장이 안 돼요 | 이름·경로 형식, 중복·예약 주소, 권한을 확인합니다. 기존 발행 페이지의 URL은 재변경 제한도 확인합니다 |
| 게시됨인데 방문자에게 안 보여요 | 발행됨/미발행과 공개/비공개, 직접 URL을 따로 확인합니다. 기본 페이지와 커스텀 페이지도 구분합니다 |
| 메뉴 공개를 켰는데 안 보여요 | 연결 페이지 상태, 상위 공개, 공개 가능한 하위 메뉴와 미노출 경고를 확인합니다 |
| 원하는 페이지가 선택 목록에 없어요 | 페이지 관리에서 이름·URL을 먼저 확인하고 같은 위치의 중복 연결 여부를 확인합니다. 선택 목록은 현재 불러온 일부 페이지에서 검색하므로 검색 실패를 삭제 증거로 보지 않습니다 |
| 순서·이름·공개 설정 일부만 바뀌었어요 | 메뉴 정보와 순서의 저장 결과를 따로 다시 확인합니다. 저장 실패 시 전부 취소됐다고 가정하지 않습니다 |
| 상위 메뉴에 페이지가 연결되지 않아요 | 하위 메뉴가 있으면 상위 직접 연결은 사용할 수 없습니다. 연결할 하위 메뉴를 확인합니다 |
| 검색·공유 설정이 저장되지 않아요 | 페이지별 제목·설명 길이와 이미지 기준 차이를 확인합니다. 검색 제외 설정을 비공개 기능으로 사용하지 않습니다 |
