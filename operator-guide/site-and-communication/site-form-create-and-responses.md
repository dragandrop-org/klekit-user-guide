# 폼 만들고 응답 확인하기

> **검토용 가이드** · 실제 서비스 화면·동작 확인과 이미지 보완이 남아 있습니다. 본문의 실행 보류·주의사항을 먼저 확인하세요.

<figure><img src="../.gitbook/assets/branding/page-headers/site-and-communication/site-form-create-and-responses-v2.png" alt="폼 만들고 응답 확인하기 대표 이미지"><figcaption></figcaption></figure>

**업무 대상:** 설문·신청 폼 운영을 맡은 담당자용 안내입니다. 학생의 학습 질문에 답변하려는 강사·질답 조교는 Q&A 안내를 이용하세요. 폼 연결·제출 등 미확인 기능은 아래 제한을 먼저 확인합니다.

**홈페이지 관리 → 사이트 폼 관리**에서 설문·신청에 사용할 문항을 준비하고 접수된 답변을 확인합니다. 학생 질문에 답글을 다는 [Q&A](qna-answer.md)와는 다른 기능입니다.

**완료 기준:** 저장한 문항·접수 조건이 다시 열어도 유지되고, 연결·공개 결과를 확인한 페이지에서 허용된 대상이 제출한 샘플 응답을 관리자 상세에서 확인할 수 있습니다. 폼 저장·게시만으로 페이지 노출이나 실제 접수까지 완료된 것은 아닙니다.

> **현재 안내 범위**
> 문항 작성·자동저장·게시·응답 확인을 구분합니다. 전체 폼 미리보기·동의 내용 편집·페이지 연결/방문자 제출·게시 후 설정·CSV 내보내기는 화면 제공 여부와 실제 동작 확인이 남아 있습니다. 확인 전에는 해당 기능을 이용할 수 있다고 가정하지 않습니다.

## 시작 전 준비 <a href="#before-you-start" id="before-you-start"></a>

| 준비할 것 | 확인 기준 |
| --- | --- |
| 제공 환경·계정 | 사이트 폼 관리 메뉴가 제공되고 폼 조회·생성·수정 권한이 있는지 확인합니다. 메뉴가 없으면 운영자에게 제공 범위·권한을 확인합니다 |
| 폼의 목적 | 무엇을 신청하거나 조사할지 정합니다. 폼 제출을 결제·수강권 지급·상담 예약 확정으로 안내하지 않습니다 |
| 문항·안내 내용 | 필요한 질문·선택지·필수 여부와 승인된 안내 내용을 준비합니다. 개인정보·동의가 필요한 폼은 관련 입력/표시 기능 검수 전 게시하지 않습니다 |
| 접수 조건 | 대상·제출 횟수·기간·최대 응답 수와 운영 기기의 시간대를 확인합니다 |
| 응답 담당자 | 응답 원문 조회·삭제·내보내기 권한을 별도로 확인합니다. 폼 편집 권한이 모든 응답 작업을 허용하는 것은 아닙니다 |
| 검수·촬영 시에만 준비 | 승인된 테스트 사이트·회원/비회원 계정·개인정보 없는 샘플 응답을 사용합니다 |

## 저장·게시·접수 상태 구분하기 <a href="#section-2" id="section-2"></a>

**문항 작성 → 자동저장 확인 → 다시 열어 확인 → 게시 → 페이지 연결/공개 검수 → 샘플 제출 → 응답 확인** 순서로 진행합니다. 연결·제출 결과를 확인할 수 없다면 문항 저장이나 게시를 마쳤더라도 접수 준비가 끝난 것은 아닙니다.

| 표시·단계 | 뜻·주의할 점 |
| --- | --- |
| 저장 중… / 저장됨 | 초안 변경의 저장 상태입니다. 게시·노출·제출 성공 표시가 아닙니다 |
| 작성 중 | 아직 게시하지 않은 폼입니다. 문항과 설정을 편집합니다 |
| 오픈 예정 | 게시했지만 접수 시작 전인 상태입니다 |
| 응답 중 | 접수 상태가 열려 있습니다. 실제 페이지 노출·해당 사용자의 제출 가능 여부도 확인해야 합니다 |
| 응답 종료 | 수동 종료·종료 시각·응답 한도 등을 확인합니다. 표시만으로 종료 원인을 단정하지 않습니다 |
| 보관 / 삭제 예정 | 접수·일반 편집과 다른 관리 상태입니다. 수동 응답 종료와 구분합니다 |

목록의 **게시 목록**에는 작성 중인 폼도 포함될 수 있습니다. 탭 이름만 보고 모든 폼이 게시됐다고 판단하지 않습니다.

## 1. 폼 만들고 기본 정보 입력하기 <a href="#step-1" id="step-1"></a>

1. **사이트 폼 관리 → 사이트 폼 만들기**를 누릅니다. 빈 초안을 만든 뒤 편집 화면으로 이동합니다.
2. **관리자용 폼 이름**에는 목록에서 구별할 이름을 입력합니다. 예: `10월 수업 만족도 조사`.
3. **사용자 노출 제목**과 **설명**에는 응답자가 볼 제목과 안내를 입력합니다. 관리자용 이름과 사용자 제목은 구분합니다.
4. 저장이 끝난 뒤 목록에서 같은 폼을 다시 열 수 있는지 확인합니다. 생성 결과가 불명확하면 목록부터 확인하고 만들기 버튼을 반복하지 않습니다.

> **화면 예시 준비 중** · 사이트 폼 관리에서 새 폼을 만듭니다. 게시 목록의 폼도 상태를 각각 확인합니다.

> **화면 예시 준비 중** · 관리할 이름과 응답자에게 보일 제목·설명을 구분해 입력합니다.

## 2. 문항 추가하고 순서 정하기 <a href="#step-2" id="step-2"></a>

1. **문항 추가**에서 필요한 종류를 선택합니다.
2. **문항 제목**과 필요한 설명을 입력하고 **필수 문항** 여부를 정합니다.
3. 선택형 문항은 **선택지 추가**로 내용을 입력합니다. 게시 전 비어 있거나 중복된 선택지가 없는지 확인하고 두 개 이상의 유효한 선택지를 준비합니다.
4. 문항의 이동 손잡이로 순서를 바꿉니다. **문항 종류**를 바꾸면 기존 유형별 설정·선택지를 다시 확인합니다.
5. 불필요한 문항만 **문항 삭제**로 제거하고 자동저장 후 다시 확인합니다. 삭제한 문항이 자동 복구된다고 가정하지 않습니다.

| 문항 종류 | 사용할 때 |
| --- | --- |
| 단답 / 질문형 | 짧은 답변 / 긴 서술형 답변을 받습니다. 긴 답변 유형의 현재 화면 이름은 **질문형**입니다 |
| 단일 선택 / 복수 선택 / 드롭다운 | 선택지 중 하나 또는 여러 답변을 받습니다. 기타 입력 허용 여부도 확인합니다 |
| 숫자 / 척도 | 수치나 점수로 응답받습니다. 범위·표시 방식 등 유형별 설정을 확인합니다 |
| 연락처 / 이메일 / 날짜 / 시간 | 해당 형식의 값을 받습니다. 입력 형식과 필수 여부를 확인합니다 |
| 동의 | 동의 내용을 입력·수정하는 방법은 아직 확인이 필요합니다. 문항 추가만으로 동의 안내를 마쳤다고 판단하지 않습니다 |

**동의 문항 주의:** 검토한 화면에서는 동의 내용을 입력하는 편집 경로를 확인하지 못했고, 내용이 비어 있으면 게시 검증에 걸립니다. 개인정보 수집·동의가 필요한 폼은 담당자에게 확인하고 게시를 보류합니다. 게시 오류를 피하려고 필요한 동의 문항을 지우거나 다른 유형으로 대체하지 않습니다.

현재 문항 목록에는 일반 파일 업로드 유형이 없습니다. 영상·PDF 첨부를 받을 수 있다고 가정하지 않습니다. 개별 문항 확인 화면과 상단 **폼 미리보기**는 다르며, 전체 폼 미리보기 버튼은 현재 확인한 화면에서 비활성입니다.

> **화면 예시 준비 중** · 질문과 선택지를 입력하고 필수 여부·문항 순서를 확인합니다.

## 3. 응답 대상·기간·완료 화면 정하기 <a href="#step-3" id="step-3"></a>

**폼 설정**에서 아래 항목을 정합니다. 게시 후 문항 편집이 잠기므로 접수 조건도 게시 전에 충분히 확인합니다.

| 설정 | 선택·확인할 내용 |
| --- | --- |
| 응답 권한 → 접근 대상 | **로그인 회원 / 활성 수강 회원 / 모든 사용자** 중 선택합니다. 활성 수강 회원을 특정 강좌 수강생만의 조건으로 안내하지 않습니다 |
| 제출 횟수 | **1회 / 무제한**을 선택합니다. 비회원의 1회를 휴대폰 본인인증 기반의 전 기기 1회 제한으로 보장하지 않습니다 |
| 최대 응답 수 | **제한 없음 / 응답 수 제한**을 선택합니다. 제한은 유효 응답 수 기준이며 서로 다른 사람 수와 같다고 단정하지 않습니다 |
| 응답 시작 | **즉시 시작 / 날짜 지정**을 선택하고 지정 시 날짜·시각을 함께 확인합니다 |
| 응답 종료 | **종료일 없음 / 날짜 지정**을 선택하고 시작·종료 순서를 확인합니다 |
| 제출 완료 화면 | **제출 버튼 문구 / 완료 제목 / 완료 설명**을 입력합니다. 제출 완료를 결제·수강 등록·예약 확정으로 표현하지 않습니다 |
| 기타 설정 | **제출 전 확인 팝업 / 신규 응답 인앱 알림**을 정합니다. 알림 설정 저장과 실제 수신은 별도로 검수합니다 |

기간은 작업 중인 기기에 설정된 시간대를 기준으로 입력합니다. 한국 시간 기준으로 운영한다면 기기의 시간대가 `Asia/Seoul`인지 확인하고, 저장 후 표시되는 날짜·시각과 실제 접수 경계를 다시 확인합니다. 화면이 항상 한국 시간으로 고정된다고 가정하지 않습니다. [프로모션](boards-and-notices.md)의 한국 시간 기준과는 입력 방식이 다릅니다.

> **화면 예시 준비 중** · 응답 대상과 기간·한도를 정하고 제출 완료 안내를 확인합니다.

## 4. 최신 저장을 확인한 뒤 게시하기 <a href="#step-4" id="step-4"></a>

1. 입력을 마친 뒤 `저장 중…`이 끝나고 **저장됨**이 표시되는지 확인합니다. 초안은 자동저장되므로 별도 수동 저장 버튼을 찾을 필요는 없습니다.
2. **저장됨** 확인 후 **닫기**로 나갔다가 같은 초안을 다시 열어 최신 문항·순서·설정이 유지됐는지 대조합니다.
3. 입력 오류·저장 오류·충돌이 없고 동의 문항 등 확인 대기가 해소된 경우에만 **게시**를 누릅니다.
4. 같은 폼의 상세를 다시 열어 문항과 접수 상태를 확인합니다. **오픈 예정 / 응답 중 / 응답 종료**를 기간·한도·종료 설정과 대조합니다.

**저장 중이거나 저장 오류가 난 상태에서 게시하지 않습니다.** 게시 버튼이 보이더라도 최신 저장본이 반영됐다는 뜻은 아닙니다. 게시를 저장 재시도 수단으로 쓰지 말고 오류 뒤에는 입력 내용을 보존한 채 최신 저장본부터 확인합니다.

저장 오류는 안내 메시지·입력 오류를 확인하고 수정한 뒤 저장 결과를 다시 확인합니다. **저장됨**이 없다고 무조건 저장 실패인 것도 아니므로, 표시가 불명확하면 게시를 보류하고 재조회합니다. 충돌로 **새로고침**이 필요할 때는 미저장 문항·설정을 먼저 보존합니다. 화면을 닫거나 새로고침한 입력의 자동 복원·자동 병합은 보장하지 않습니다.

> **화면 예시 준비 중** · 최신 저장과 재진입 결과를 확인한 뒤 게시합니다. 게시와 접수 상태는 다릅니다.

> **동작 예시 준비 중** · 자동저장이 끝난 뒤 폼을 다시 열어 변경한 문항과 설정을 대조합니다.

자동저장과 게시는 별도로 처리됩니다. 저장에 실패했거나 저장 중인 상태에서도 게시 요청이 이어질 위험이 남아 있으므로 최신 저장본·오류·동의 내용을 확인하기 전에는 게시하지 않습니다. 입력 내용을 안전하게 보존하고 오류를 피하려고 새로고침·복제하거나 필요한 동의 문항을 삭제하지 않습니다.

## 5. 페이지 연결과 실제 접수 확인하기 <a href="#step-5" id="step-5"></a>

상세의 **연결 페이지**는 연결 현황을 보는 목록이며 연결을 추가·삭제하는 편집 화면이 아닙니다. 작업본 연결도 표시될 수 있고 **미공개**이면 방문자에게 노출되는 연결과 구분해야 합니다.

> **페이지 연결 전 주의**
> 폼의 최종 페이지 연결·방문자 제출 화면은 확인 대기입니다. **웹빌더 편집**의 이동 경로와 [페이지·메뉴 구성하기](pages-and-menus.md)의 커스텀 빌더 메인 대상 고정 문제도 남아 있으므로, 대상 연결 수정·검수 전 커스텀 빌더에 들어가 저장·게시하지 않습니다. 기존 빌더의 문의 폼을 사이트 폼과 같은 기능으로 대신 연결하지 않습니다.

연결 기능과 대상 페이지의 문제가 해결되고 실제 결과가 확인된 뒤에만 아래 순서로 접수를 확인합니다.

1. 의도한 페이지·섹션에 **이번 폼**이 연결됐는지 확인합니다. 연결 건수만으로 판단하지 않습니다.
2. 페이지의 발행·공개와 폼의 게시·접수 상태를 각각 확인합니다.
3. 승인된 회원/비회원 계정으로 해당 페이지를 열어 문항·대상 제한·기간·필수 응답을 확인합니다.
4. 개인정보 없는 샘플을 제출하고 완료 화면을 확인한 뒤 관리자에서 같은 응답을 찾습니다. 제출 결과가 불명확하면 응답 조회부터 하고 반복 제출하지 않습니다.

> **화면 예시 준비 중** · 연결 현황과 공개 페이지를 각각 확인하고 샘플 제출 결과를 대조합니다.

## 6. 응답 목록과 제출 답변 확인하기 <a href="#step-6" id="step-6"></a>

1. 폼 상세의 **응답 데이터**를 엽니다. 응답 원문 조회 권한이 필요합니다.
2. **전체 / 로그인 회원 / 비회원**으로 응답자 범위를 정하고, **응답 번호 또는 이름**을 입력해 **검색**합니다.
3. 기간·유입 페이지 조건은 **필터 → 적용하기**, 순서는 **최신순 / 오래된순**으로 정합니다.
4. **응답 번호 / 응답자 / 유입 페이지 / 제출일시**를 대조한 뒤 해당 행을 엽니다.
5. 상세의 **제출 답변 / 제출 정보**에서 문항·선택지·답변을 확인합니다. 제출 당시의 문항 기록이므로 현재 폼 내용과 다를 수 있습니다.

**총 노출 / 제출 완료 / 제출 전환율**은 응답자 개인의 읽음·예약·결제 완료 지표가 아닙니다. 통계는 기간·유입 페이지를 기준으로 계산하며, 응답 목록의 검색어·회원/비회원 탭까지 같은 방식으로 적용되는 것은 아닙니다. 통계와 목록 건수가 다르면 먼저 조건 차이를 확인합니다.

목록으로 돌아왔을 때 검색·필터가 그대로 유지된다고 보장하지 않습니다. 필요한 조건을 다시 확인합니다. 조회 오류를 응답 0건으로 해석하거나 권한 없는 다른 계정으로 원문을 열지 않습니다.

> **화면 예시 준비 중** · 응답 번호·이름과 기간·페이지로 응답을 찾습니다. 통계와 목록의 조건을 구분합니다.

> **화면 예시 준비 중** · 응답 상세에서 제출 당시 질문과 답변을 확인합니다.

## 7. 접수 종료·내용 변경·응답 정리하기 <a href="#step-7" id="step-7"></a>

| 필요한 작업 | 순서·주의할 점 |
| --- | --- |
| 접수를 수동 종료 | 상세에서 **응답 종료** → 결과 재조회 → 실제 제출 차단 확인. 폼 삭제와 다릅니다 |
| 수동 종료한 접수 재개 | **다시 받기** → 상태·기간·한도 재조회. 수동 종료만 해제하며 지난 종료일·응답 한도·대상/횟수 제한까지 없어지는 것은 아닙니다 |
| 게시한 폼의 문항 변경 | 문항 편집은 잠깁니다. **폼 복제** 또는 **복제해서 새 폼 만들기**로 새 초안을 준비하고 이름·기간·조건을 다시 확인합니다. 기존 응답·페이지 연결이 새 폼으로 옮겨지거나 자동 교체되지는 않습니다 |
| 게시 후 운영 설정 변경 | 게시 후 설정을 바꾸려면 이름·알림·응답 한도·종료 설정에 대해 담당자에게 문의합니다. 변경 처리는 이 항목으로 제한되며, 실제 화면에서 편집하는 방법은 아직 확인되지 않았습니다 |
| 개별 응답 삭제 | 삭제 권한과 대상을 확인한 뒤 **응답 삭제 → 삭제**합니다. 목록·통계·유효 응답 수에 영향을 주며 1회 제출 제한도 다시 열릴 수 있습니다. 한도 확보·오류 재시도 목적으로 삭제하지 않습니다 |
| CSV 내보내기 | 원문 조회와 별도 권한입니다. 최종 버튼·필터/포함 범위·파일 결과 확인 전에는 다운로드 절차를 확정하지 않습니다 |

개별 응답 삭제 화면의 복구 안내만으로 운영자가 복구할 수 있다고 보장하지 않습니다. 현재 개별 응답의 복구 화면·서비스를 확인하지 못했습니다. 폼 자체의 휴지통/복원과 응답 한 건의 복구는 다른 기능입니다. 폼을 정리할 때도 작업본·발행본 연결을 함께 확인하고 연결된 폼을 삭제해 우회하지 않습니다.

## 완료 후 확인 <a href="#completion-checklist" id="completion-checklist"></a>

- [ ] 사이트 폼 제공 범위와 편집·응답 원문/삭제/내보내기 권한을 구분했습니다.
- [ ] 관리자용 이름·사용자 제목·문항/선택지·필수 여부·순서를 다시 확인했습니다.
- [ ] 동의 내용 편집·표시가 미확인인 폼을 게시하지 않았고 전체 미리보기를 가정하지 않았습니다.
- [ ] 대상·횟수·기간/시간대·한도·완료 문구를 확인했습니다.
- [ ] 최신 저장 완료와 재진입 결과를 확인한 뒤 게시했고 게시·접수 상태를 구분했습니다.
- [ ] 페이지 대상/연결 문제를 먼저 검수했고 실제 공개 페이지에서 허용 대상의 샘플 제출을 확인했습니다.
- [ ] 같은 응답의 번호·제출 답변·제출 정보를 확인했고 통계/목록 조건 차이를 구분했습니다.
- [ ] 종료/재개·복제·삭제의 영향을 구분했고 개별 응답 복구·CSV·알림 수신을 미확인 상태로 보장하지 않았습니다.

## 자주 막히는 부분 <a href="#troubleshooting" id="troubleshooting"></a>

| 상황 | 확인할 것 |
| --- | --- |
| 사이트 폼 메뉴가 없어요 | 로그인한 사이트와 기능 제공 여부·권한을 운영자에게 확인합니다. 메뉴가 보이지 않을 때 관리자 화면에서 직접 켤 수 있다고 가정하지 않습니다 |
| 저장 버튼이나 전체 미리보기가 안 보여요 | 초안은 자동저장이며 전체 폼 미리보기는 현재 비활성입니다. 저장 상태와 재진입 결과로 확인합니다 |
| 동의 문항 때문에 게시가 안 돼요 | 동의 내용 편집 경로가 확인될 때까지 보류합니다. 필요한 동의 문항을 삭제해 우회하지 않습니다 |
| 저장 오류 후 게시했는데 옛 내용이에요 | 게시를 더 반복하지 않고 현재 저장된 문항·상태를 확인해 담당자에게 전달합니다. 자동 복원이나 이전 상태로 되돌리기를 보장하지 않습니다 |
| 게시했는데 응답을 못 받아요 | 실제 연결·페이지 공개·접수 기간/한도·대상/횟수를 각각 확인합니다. 커스텀 빌더 문제를 먼저 해결합니다 |
| 다시 받기를 눌렀는데도 종료예요 | 종료일·응답 한도 등 다른 종료 조건을 확인합니다. 응답 삭제로 제한을 우회하지 않습니다 |
| 게시 후 문항을 고칠 수 없어요 | 새 폼을 복제해 준비하고 이름·기간·별도 게시/연결을 다시 확인합니다. 기존 응답은 원래 폼에 남습니다 |
| 통계와 검색 결과 수가 달라요 | 기간/유입 페이지와 검색어·응답자 탭의 적용 범위를 비교합니다 |
| 응답 원문이나 CSV가 안 열려요 | 조회와 내보내기 권한·기능 제공을 별도로 확인합니다. CSV 내보내기의 실제 화면과 진행 방법은 아직 확인되지 않았습니다 |
