# 결제수단·청구 내역 보기

<figure><img src="../.gitbook/assets/branding/page-headers/subscription-and-usage/billing-method-and-payment-history-v2.png" alt="구독 결제수단·청구 내역 확인하기 대표 이미지"><figcaption></figcaption></figure>

**업무 대상:** 클킷 이용 비용과 사이트 한도를 관리하는 소유자·담당자용 안내입니다. 이 업무를 맡지 않은 강사는 영상 업로드·수강 문의 때문에 플랜이나 카드를 직접 변경하지 말고 학원 운영자에게 요청하세요. 실제 작업 가능 범위는 본인 계정의 권한을 확인하세요.

**구독 관리 → 플랜 관리**에서 결제수단을, **구독 관리 → 구독 결제 내역**에서 플랜·팩의 청구를 확인합니다. **카드 등록, 카드 보기, 사용할 카드 변경, 결제 승인**은 서로 다른 단계입니다.

**완료 기준:** 대상 사이트의 사용 중 카드와 해당 청구 건의 주문번호·유형·상태·금액/당시 결제수단을 구분합니다. 카드 변경을 요청했다면 최신 결과까지 확인하고, 환불은 원 승인액·처리 상태·환불 후 금액을 대조합니다.

처음 유료로 시작하려면 [플랜·무료체험과 구독 시작하기](plan-trial-and-subscription-start.md), 플랜 변경·종료 예약은 [플랜 변경·구독 종료 예약하기](plan-change-and-subscription-end-schedule.md), 팩 관리·미사용 환불 조건과 신청은 [사용량 확인·추가 팩 관리하기](usage-and-additional-packs.md)에서 확인합니다. 이 문서는 클킷 서비스 구독 청구를 다루며 수강생 상품 주문·판매대금 정산·정산 계좌 등록과 별개입니다.

## 시작 전 준비 <a href="#before-you-start" id="before-you-start"></a>

| 준비할 것 | 확인할 내용 |
| --- | --- |
| 사이트·소유자 | 대상 사이트와 구독 결제자에 연결된 소유자 계정인지 확인합니다. 사용량 조회 권한만으로 카드/청구 상세에 접근할 수 있는 것은 아닙니다 |
| 현재 구독·작업 | 플랜·기간/다음 결제일, 예약·체험·실패/처리 중 안내와 기존 카드 등록 결과를 준비합니다 |
| 확인할 결제 | 플랜 구독/플랜 갱신/사용량 팩 중 유형과 해당 주문번호·금액·대략적인 시각을 준비합니다 |
| 카드 확인 범위 | 카드사·마스킹 번호로 구분합니다. 다른 계정의 카드나 카드 전체 번호/인증정보를 공유하지 않습니다 |
| 업무 승인 | 카드 등록·변경과 청구 내역 조회를 맡은 담당자에게 필요한 작업과 비용을 확인합니다. 아래 실행 보류 안내를 먼저 읽습니다 |

카드 등록을 시작하면 인증을 위한 등록 세션이 생성되고 외부 인증으로 이어집니다. **이 카드로 변경**은 실제 설정 변경입니다. 조회만 하려는 경우 등록·변경 버튼을 누르지 않습니다.

| 목적 | 확인할 곳 | 다른 업무와의 차이 |
| --- | --- | --- |
| 지금 사용할 카드 확인 | 플랜 관리 → 결제수단 | 화면에 보이는 카드와 **사용 중** 표시는 다릅니다 |
| 카드 등록 준비 | 카드 등록 또는 견적의 카드 등록하고 계속 | 등록 완료가 플랜 변경·청구 완료를 뜻하지 않습니다 |
| 등록된 다른 카드로 변경 | 카드 보기 → 이 카드로 변경 | 이전/다음 카드 보기는 변경 요청이 아닙니다 |
| 실제 청구 확인 | 구독 결제 내역 → 해당 결제 상세 | 월 예상액·견적·작업 접수와 실제 결제 내역은 다릅니다 |
| 팩 환불 확인 | 팩 결제 상세 → 환불 내역 | 환불 신청/한도 확인은 [사용량 확인·추가 팩 관리하기](usage-and-additional-packs.md)이며 갱신 종료 예약과도 다릅니다 |

## 1. 결제수단 화면과 대상 확인하기 <a href="#step-1" id="step-1"></a>

1. **구독 관리 → 플랜 관리**를 엽니다.
2. 현재 플랜·구독 기간/다음 결제일과 실패/진행 안내를 읽습니다.
3. **결제수단**에서 카드사·마스킹 번호와 **사용 중** 여부를 확인합니다.
4. 카드가 여러 장이면 **이전 카드 / 다음 카드** 또는 카드 위치 표시로 다른 카드를 봅니다.

카드 보기는 현재 표시만 바꿉니다. 보고 있는 카드가 다음 결제에 사용할 카드로 자동 변경되지는 않습니다.

결제수단 영역은 소유자·현재 플랜에 따라 보이지 않을 수 있으며 Free에서는 숨겨집니다. **영역이 안 보임 = 등록 카드 없음**은 아닙니다. 카드 목록 조회가 실패해도 빈 등록 화면처럼 보일 수 있으므로, 기존 카드가 있었다면 상태부터 확인하고 새 등록을 시작하지 않습니다.

> **화면 예시 준비 중** · 카드 보기와 사용 중을 구분합니다. 영역이 숨겨졌다고 카드가 없는 것은 아닙니다.

## 2. 카드 등록 진입과 범위 확인하기 <a href="#step-2" id="step-2"></a>

| 현재 상황 | 확인할 진입 | 주의할 점 |
| --- | --- | --- |
| 유료 변경 견적에서 카드가 필요함 | **카드 등록하고 계속** | 견적·등록 세션 생성도 별도 승인 대상입니다. 등록 후 최신 견적을 다시 확인합니다 |
| 결제수단 영역에서 등록 카드가 없음 | **카드 등록** | 실제 조회 성공/카드 없음인지 확인한 뒤 진행합니다 |
| 이미 등록 카드가 있음 | 등록된 카드 보기/사용 중 확인 | 등록된 카드가 있을 때 새 카드를 추가하는 방법은 아직 확인이 필요합니다. 새 카드가 필요하면 먼저 담당자에게 추가 방법을 확인합니다 |
| Free라 결제수단 영역이 없음 | [플랜·무료체험과 구독 시작하기](plan-trial-and-subscription-start.md)의 유료 시작 준비 범위 확인 | 카드 등록을 위해 원치 않는 유료 변경을 적용하거나 숨겨진 경로로 우회하지 않습니다 |

카드 등록은 **등록 시작 → 외부 카드 인증 → 클킷의 등록 결과 확인 → 플랜 관리 재확인**으로 이어집니다. 등록 세션은 만들어진 뒤 **15분** 동안 유효합니다. 외부 인증 화면을 열거나 인증 성공 후 돌아오는 주소로 이동했더라도 카드 등록이 완료된 것은 아닙니다. 실제 등록 결과는 아직 확인이 필요하므로 아래 실행 보류를 따릅니다.

**현재 외부 카드 인증·등록 실행은 보류합니다.** 기존 카드가 있을 때 새 카드가 필요하면 실제 추가 방법을 담당자에게 확인합니다. 기존 카드를 임의로 삭제하거나 다른 계정으로 대신 등록하지 않습니다.

> **화면 예시 준비 중** · 제공되는 등록 진입부터 확인합니다. 카드 등록과 플랜 변경은 별개입니다.

## 3. 카드 등록 결과와 플랜 복귀 확인하기 <a href="#step-3" id="step-3"></a>

| 화면 안내 | 확인할 내용 |
| --- | --- |
| **카드 등록 중** | 결과를 확인하는 단계입니다. 새 인증·등록 요청을 만들지 않습니다 |
| **카드 등록 완료** | 등록 결과 안내입니다. **플랜 관리로 이동** 후 카드 목록/사용 중과 현재 구독을 대조합니다 |
| **카드 등록 실패** 또는 인증 정보/만료 안내 | 확정 실패와 결과 불명확을 먼저 구분합니다. 기존 등록 결과 확인 없이 재등록하지 않습니다 |
| 돌아온 플랜 변경 견적 | 현재 조건으로 다시 열린 최신 금액·카드·동의/영향을 확인합니다. 이전 견적/동의를 재사용하지 않습니다 |

현재 화면은 처리 중·결과 불명확도 일반 실패/다시 시도 문구로 안내할 수 있습니다. **실패 문구만으로 카드가 등록되지 않았다고 단정하지 않습니다.** 특히 외부 인증 후 멈췄거나 결과를 확인하지 못했다면 새 등록을 반복하지 말고 기존 결과를 담당자에게 확인합니다. 등록 결과 복구를 위해 성공 주소·인증정보를 다시 열거나 공유하지 않습니다.

카드가 등록됐더라도 유료 플랜 전환·기존 실패 청구의 재결제까지 완료된 것은 아닙니다. 유료 변경 견적이 다시 열리면 [플랜·무료체험과 구독 시작하기](plan-trial-and-subscription-start.md)/[플랜 변경·구독 종료 예약하기](plan-change-and-subscription-end-schedule.md)의 최신 조건 확인으로 이어가며 최종 변경은 별도 승인 범위입니다.

> **화면 예시 준비 중** · 등록 결과와 플랜/청구 결과를 나눠 확인합니다. 불명확하면 재등록하지 않습니다.

## 4. 등록된 다른 카드로 변경 준비하기 <a href="#step-4" id="step-4"></a>

1. **결제수단**에서 변경하려는 카드사·마스킹 번호를 확인합니다.
2. 해당 카드에 **사용 중**이 있는지, **이 카드로 변경**이 가능한지 확인합니다.
3. 비활성이라면 카드 상태·소유자·현재 구독 상태·다른 변경/갱신 작업부터 확인합니다.
4. 승인된 범위에서 변경을 요청했다면 완료 안내와 최신 카드 목록·해당 사이트의 구독 결과를 함께 대조합니다.

**이 카드로 변경**은 누르는 즉시 실제 변경을 요청하며 추가 확인 창이 없을 수 있습니다. 실제 변경 결과가 아직 확인되지 않았으므로 **최종 실행을 보류**합니다. 카드를 바꿔야 한다면 담당자에게 안전한 처리 방법을 먼저 확인하세요.

**사용 중**은 기존 선택 또는 기본 카드 표시일 수 있습니다. 새 요청 전부터 있던 배지만으로 이번 변경의 저장 성공을 판단하지 않습니다. 결과 불명확이면 같은 버튼을 반복하지 않고 기존 결과를 확인합니다.

카드 변경은 해당 사이트 구독에 사용할 결제수단을 다룹니다. 다른 사이트 전체의 선택 카드·이미 승인된 결제의 당시 카드/금액을 일괄 변경하거나 실패한 청구를 자동 재결제하는 작업이 아닙니다. 카드 삭제·공유 절차는 이 화면에서 안내하지 않습니다.

> **화면 예시 준비 중** · 카드 보기는 표시만 바꿉니다. 이 카드로 변경은 실제 요청입니다.

## 5. 구독 결제 목록에서 해당 건 찾기 <a href="#step-5" id="step-5"></a>

1. **구독 관리 → 구독 결제 내역**을 엽니다.
2. **결제 유형**에서 **전체 / 플랜 구독 / 플랜 갱신 / 사용량 팩**을 선택합니다.
3. **10개씩 / 20개씩 / 50개씩 보기**와 페이지 이동으로 해당 건을 찾습니다. 유형·표시 개수를 바꾸면 첫 페이지로 돌아갑니다.
4. **결제일, 주문번호, 구분, 결제 항목, 결제수단, 상태, 금액**을 대조하고 해당 행을 엽니다.

이 목록은 해당 사이트 소유자의 클킷 서비스 청구 범위입니다. 수강생 주문을 보는 **결제/정산관리 → 결제 내역**과 구분합니다. 주문번호 검색·기간/상태 필터·정렬·CSV/PDF 다운로드는 현재 화면에서 제공되지 않습니다. 필요한 내역을 찾기 어렵다면 결제 유형과 페이지를 확인하고 담당자에게 문의합니다.

결제일은 승인일이 없으면 생성 시각으로 표시될 수 있습니다. 목록 순서와 결제일이 항상 같은 시간 기준은 아니며 날짜만으로 승인 성공을 판정하지 않습니다. 정확한 시각·시간대가 필요하면 담당자에게 확인합니다.

**상세로 열리지 않는 행**은 상세 진입 정보가 없을 수 있습니다. 클릭이 안 된다는 이유로 미결제·실패 처리하지 않습니다.

### 내역 없음과 조회 실패 구분하기 <a href="#section-8" id="section-8"></a>

- **선택한 조건의 결제 내역이 없습니다**이면 유형·사이트·페이지를 먼저 확인합니다.
- **아직 구독 결제 내역이 없습니다**라는 안내만으로 모든 요청이나 청구가 없었다고 판단하지 않습니다.
- **구독 결제 내역을 불러오지 못했습니다**이면 조회 재확인과 기존 작업 확인을 진행합니다. 재결제 버튼으로 해결하지 않습니다.
- **결제 내역은 사이트 소유자만 확인할 수 있습니다**이면 권한 문제입니다. 다른 사람의 로그인 정보를 사용하지 않습니다.

목록은 승인/환불 중심이며 **실패·진행 중·0원 작업 전체 목록이 아닙니다**. 팩 축소/종료 설정처럼 0원 작업도 실제 변경이 있을 수 있습니다. 목록에 없다고 같은 결제·변경을 다시 요청하지 않습니다. 플랜과 팩은 각각 청구되므로 월 예상 합계가 한 행으로 나타난다고 가정하지 않습니다.

> **화면 예시 준비 중** · 유형과 페이지를 먼저 확인합니다. 목록은 실패·진행 중·0원 작업 전체가 아닙니다.

## 6. 플랜 결제 상세 읽기 <a href="#step-6" id="step-6"></a>

**플랜 구독 / 플랜 갱신** 행을 열고 **거래 정보**와 **결제 확인**을 함께 확인합니다.

| 확인할 정보 | 읽는 방법 |
| --- | --- |
| 주문번호·결제 항목 | 목록과 같은 청구 건인지 확인합니다. 현재 플랜명·월 가격만으로 찾지 않습니다 |
| 결제일 | 승인 시각 또는 생성 시각 대체 표시일 수 있습니다. 상태를 함께 읽습니다 |
| 결제수단 | 당시 기록된 카드사·마스킹 번호입니다. 현재 사용 중 카드와 다를 수 있습니다 |
| 상태·최종 결제 금액 | 같은 거래에 대해 클킷에 표시된 결과를 확인합니다. 팩 상세의 환불 차감 후 금액과 같은 계산 구조라고 가정하지 않습니다 |
| 영수증 보기 | 제공되는 경우에만 외부 영수증을 확인합니다 |

플랜 상세에는 팩과 같은 이용 기간·항목별 수량/세금·환불 내역 표가 제공된다고 전제하지 않습니다. 환불 상태인데 원 승인액/차감 후 금액의 의미가 불명확하면 순결제액을 임의 계산해 확정하지 말고 해당 거래의 근거를 담당자에게 확인합니다.

**카드**로만 표시되거나 카드 상세 정보가 없다는 사실을 결제 실패로 해석하지 않습니다. 과거 카드 정보가 제한된 경우 현재 카드로 원 승인 당시 정보를 채워 넣지 않습니다.

> **화면 예시 준비 중** · 당시 결제수단과 현재 카드를 구분하고 플랜 청구의 상태·금액을 함께 읽습니다.

## 7. 팩 상세의 원 승인액·환불 후 금액 대조하기 <a href="#step-7" id="step-7"></a>

**사용량 팩** 결제를 열면 **거래 정보, 이용 기간, 결제 항목, 결제 확인**을 읽습니다.

| 표시 | 의미 |
| --- | --- |
| 결제 항목의 이름·수량·금액 | 이번에 청구된 증가/갱신 항목입니다. 현재 보유한 팩 전체나 다음 갱신 설정 전체가 아닙니다 |
| 항목 합계 | 이번 청구 항목의 합계입니다. 환불 후 남은 금액과 다를 수 있습니다 |
| 공급가액·부가세 | 원 승인 기준 구분입니다. 최종액에 세금을 다시 더하지 않습니다 |
| 환불 금액 | 반영된 환불 합계입니다. 준비/처리 중 금액까지 임의로 합치지 않습니다 |
| 최종 결제 금액 | 원 승인액에서 반영된 환불액을 뺀 값입니다. 목록 금액과 다를 수 있습니다 |
| 이용 기간 | 해당 팩 청구의 주기입니다. 현재 시청 집계 주기·다음 갱신 설정과 혼동하지 않습니다 |

팩 목록의 **금액**은 원 승인액 기준이며 환불 뒤에도 그 값이 남을 수 있습니다. 처음 승인액이 양수인 전액 환불 건은 목록에 계속 나타날 수 있고 상세의 최종액은 0원일 수 있습니다. 이를 새로운 0원 구매·추가 청구로 해석하지 않습니다.

현재 보유 팩/다음 수량과 한도는 **사용량 및 팩**에서 별도로 대조합니다. 청구 상세만으로 최신 혜택/갱신 종료까지 확인됐다고 판단하지 않습니다.

> **화면 예시 준비 중** · 목록의 원 승인액과 팩 상세의 환불 후 최종 금액은 다를 수 있습니다.

### 환불 내역과 신청 진입은 다릅니다 <a href="#section-11" id="section-11"></a>

**환불 내역**에서 해당 수량·금액과 표시 시각·상태를 함께 읽습니다. 시각은 처리 기록의 갱신 시각일 수 있어 카드사 입금 시각이나 최초 신청 시각으로 단정하지 않습니다.

| 상태 | 읽는 방법 |
| --- | --- |
| 환불 준비 중 / 환불 처리 중 | 접수/진행 단계입니다. 환불 완료 금액으로 합산하지 않습니다 |
| 환불 완료 | 해당 요청의 반영된 결과와 원 승인액/환불액/최종액·현재 한도를 대조합니다 |
| 환불 실패 | 기존 요청의 결과부터 확인합니다. 새 환불이나 팩 구매로 우회하지 않습니다 |

**미사용 팩 환불**의 구매/사용/환불 가능 수량·기한은 신청 자격 정보이며 **환불 완료 내역이 아닙니다**. 자격은 승인 후 **24시간 미만**인지, 사용량·예약량이 해당 팩에 반영됐는지 등 최신 조건으로 판정하며 정확히 24시간이 되면 불가입니다.

환불 가능 수량만 보고 바로 신청하지 않습니다. 수량/예상액·환불 후 한도·신청과 최종 결과는 [사용량 팩 환불 안내](usage-and-additional-packs.md)를 따릅니다. 청구 내역만 확인하려는 경우에는 환불 창을 열거나 신청하지 않습니다.

> **화면 예시 준비 중** · 환불 내역의 처리 상태와 새 신청의 가능 수량은 다른 정보입니다.

## 8. 영수증 제공 여부 확인하기 <a href="#step-8" id="step-8"></a>

상세의 **영수증 보기**가 제공되면 별도 승인된 범위에서 외부 영수증의 해당 거래·금액/상태를 확인합니다. 플랜과 팩의 영수증은 각 청구 건별로 확인하며 하나의 월 통합 영수증으로 안내하지 않습니다.

버튼이 없으면 해당 내역에 영수증 링크가 제공되지 않은 상태일 수 있습니다. **영수증 없음 = 미결제**가 아니며 임의 주소로 열거나 현재 카드 정보로 증빙을 만들어 대체하지 않습니다.

새 창을 열었다는 사실만으로 증빙 확인이 끝나지 않습니다. 원 거래와 대조하되 외부 영수증의 실제 표시·환불 반영과 과거 건의 제공 여부는 아직 확인이 필요한 항목입니다.

이 화면의 **영수증 보기**는 카드 영수증을 확인하는 기능이며, 세금계산서·판매대금 정산명세서 PDF 자동 발급과 다릅니다. 문의하거나 화면을 공유할 때는 불필요한 개인정보·카드/주문 정보를 가리고, 영수증 주소 원문을 보내지 않습니다.

> **화면 예시 준비 중** · 영수증 링크가 없다고 미결제는 아닙니다. 조회 오류와 정보 미제공도 구분합니다.

## 자주 막히는 부분 <a href="#troubleshooting" id="troubleshooting"></a>

| 상황 | 먼저 확인할 것 |
| --- | --- |
| 결제수단 영역이 안 보여요 | 사이트·소유자·현재 Free 여부와 조회 상태를 확인합니다. 숨김이 카드 없음은 아닙니다 |
| 기존 카드가 있는데 카드 등록 화면만 보여요 | 조회 실패와 실제 카드 없음부터 구분합니다. 새 등록 세션을 반복하지 않습니다 |
| 카드가 있는데 새 카드 추가가 안 보여요 | 기존 카드가 있을 때 새 카드를 추가하는 방법은 아직 확인이 필요합니다. 카드 삭제·계정 우회로 해결하지 않습니다 |
| 화면에서 보고 있는 카드와 사용 중인 카드가 달라요 | 카드 보기와 선택 변경은 별개입니다. 변경 요청 전후 같은 사이트의 최신 결과를 확인합니다 |
| 이 카드로 변경이 비활성이에요 | 카드 상태·구독/소유자·진행 작업/갱신과 허용 여부를 확인합니다 |
| 카드 등록 실패라고 떠요 | 외부 인증 뒤 결과 불명확인지 먼저 확인합니다. 기존 결과를 확인하기 전 재등록하지 않습니다 |
| 카드를 등록했는데 유료 플랜으로 안 바뀌어요 | 등록과 플랜 변경은 별개입니다. 최신 견적·동의와 기존 변경 결과부터 확인합니다 |
| 카드 변경 후 과거 결제의 카드가 그대로예요 | 과거 상세는 당시 기록입니다. 현재 카드로 소급 변경하지 않습니다 |
| 목록에 청구가 안 보여요 | 사이트·유형/페이지·기존 처리 결과를 확인합니다. 실패/진행 중·0원 전체 목록은 아닙니다 |
| 목록 금액과 팩 상세 최종액이 달라요 | 원 승인액과 반영된 환불 후 금액을 구분합니다. 새로운 청구로 단정하지 않습니다 |
| 상세가 없거나 불러오지 못했어요 | 상세 진입 정보·권한/사이트·조회 실패를 구분합니다. 새 결제로 해결하지 않습니다 |
| 영수증 보기 버튼이 없어요 | 링크 미제공과 미결제를 구분합니다. 담당자에게 해당 거래의 제공 가능 여부를 확인합니다 |

문의에는 대상 사이트, 확인 시각, 플랜/팩 유형, 해당 주문번호·금액/상태, 카드 등록/변경 중 어떤 단계인지와 화면 문구를 적습니다. 비밀번호·카드 전체 번호·인증 키·등록/영수증 주소·콘솔/요청 원문은 보내지 않습니다.

> **동작 예시 준비 중** · 같은 청구의 목록과 상세를 대조합니다. 결제·환불 실행 예시가 아닙니다.

## 완료 후 확인 <a href="#completion-checklist" id="completion-checklist"></a>

- [ ] 같은 사이트의 구독 결제자에 연결된 소유자 계정인지 확인하고, 카드·청구 내역 조회 권한도 별도로 확인했습니다.
- [ ] 카드 목록 조회/빈 화면·Free 미노출·기존 카드 추가 확인 대기를 구분했습니다.
- [ ] 카드 등록 세션의 15분 제한을 확인했습니다. 외부 인증·등록 결과·플랜 변경 완료·청구 완료가 서로 다른 단계라는 점도 구분했습니다.
- [ ] 실패 문구만으로 미등록을 단정하지 않고 불명확한 기존 결과부터 확인했습니다.
- [ ] 카드 보기·사용 중 표시·실제 변경 요청을 구분하고 요청했다면 최신 결과를 대조했습니다.
- [ ] 같은 청구 건의 유형·주문번호·결제일·상태를 대조했습니다. 조회 페이지와 조건, 목록에 포함되지 않는 내역의 범위도 확인했습니다.
- [ ] 당시 결제수단과 현재 카드, 플랜 상세/팩 상세의 표시 범위를 구분했습니다.
- [ ] 팩 원 승인액·완료된 환불 합계·최종액과 환불 진행/가능 수량을 구분했습니다.
- [ ] 조건부 영수증 제공과 실제 확인·세금계산서/정산명세서의 차이를 확인했습니다.
- [ ] 중복 등록·청구·환불을 하지 않았고, 실행이 보류된 작업은 담당자에게 확인했습니다.
