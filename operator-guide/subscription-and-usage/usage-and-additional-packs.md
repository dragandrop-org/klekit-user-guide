# 사용량·추가 팩 관리하기

<figure><img src="../.gitbook/assets/branding/page-headers/subscription-and-usage/usage-and-additional-packs-v2.png" alt="사용량 확인·추가 팩 관리하기 대표 이미지"><figcaption></figcaption></figure>

**업무 대상:** 클킷 이용 비용과 사이트 한도를 관리하는 소유자·담당자용 안내입니다. 이 업무를 맡지 않은 강사는 영상 업로드·수강 문의 때문에 플랜이나 카드를 직접 변경하지 말고 학원 운영자에게 요청하세요. 실제 작업 가능 범위는 본인 계정의 권한을 확인하세요.

**구독 관리 → 사용량 및 팩**에서 저장공간·시청시간을 확인하고 필요한 추가 팩을 검토합니다. **현재 사용량, 현재 적용 중인 팩, 다음 갱신 설정, 환불**은 서로 다른 정보입니다.

**완료 기준:** 실제 집계 기준과 현재 한도를 읽고, 팩 변경을 검토했다면 이번/다음 금액·적용 시점까지 구분합니다. 요청했다면 같은 작업의 최종 결과와 현재/다음 팩·한도·청구 또는 환불 내역을 대조합니다.

플랜·체험은 [플랜·무료체험과 구독 시작하기](plan-trial-and-subscription-start.md), 플랜 변경·Free 전환 예약은 [플랜 변경·구독 종료 예약하기](plan-change-and-subscription-end-schedule.md)를 봅니다. 카드 등록/선택·청구 상세는 [구독 결제수단·청구 내역 확인하기](billing-method-and-payment-history.md)를 봅니다. 여기서 다루는 팩은 클킷 서비스 사용량이며 학생의 강좌 상품·수강권·주문 환불과 별개입니다.

## 시작 전 준비 <a href="#before-you-start" id="before-you-start"></a>

| 준비할 것 | 확인할 내용 |
| --- | --- |
| 사이트·계정 | 대상 사이트를 확인합니다. 사용량 조회와 팩 변경/청구 상세 권한은 다르며 변경은 구독 결제자에 연결된 소유자 범위입니다 |
| 현재 구독 | 현재 플랜·체험·구독 기간/다음 결제일과 기존 예약·실패/처리 중 안내를 확인합니다 |
| 필요한 사용량 | 저장공간과 시청시간 중 부족한 항목, 현재 사용량·진행 중 업로드, 현재/다음 팩을 준비합니다 |
| 결제수단·예산 | 유효 결제수단과 이번 청구액·다음 주기 팩 비용을 확인할 담당자를 정합니다 |
| 업무 승인 | 구독 담당자와 조회·변경·갱신·환불 중 필요한 작업과 예산을 확인합니다. 아래 실행 보류 안내를 먼저 읽습니다 |

**변경 내용 확인**도 견적을 생성·저장하는 동작입니다. 사용량만 확인하려는 경우에는 누르지 않습니다. 실제 청구·변경·환불은 구독 담당자의 업무 승인과 아래 실행 보류 조건을 확인해야 합니다.

## 먼저 업무 구분하기 <a href="#section-2" id="section-2"></a>

| 목적 | 확인할 곳 | 구분할 점 |
| --- | --- | --- |
| 얼마나 사용했는지 확인 | 저장공간·시청시간, 최근 사용량 살펴보기 | 월 표시·최근 추이와 실제 집계 주기는 다릅니다 |
| 추가 사용량 확보 | 팩 선택 → 변경 내용 확인 | 선택만으로 구매되지 않으며 증가는 결제·작업 성공 후 반영됩니다 |
| 다음부터 팩 줄이기/종료 | 작은 팩 또는 추가 팩 없음 → 견적 | 감소는 다음 갱신 설정이며 기존 결제의 즉시 환불이 아닙니다 |
| 실패한 갱신 확인 | 결제 실패·갱신 중단과 조건부 버튼 | 갱신 재개는 설정 변경, 재결제는 실제 청구 요청입니다 |
| 미사용 팩 환불 검토 | 구독 결제 내역 → 해당 팩 결제 상세 | 승인 후 24시간 미만의 클킷 판정과 환불 후 한도를 확인합니다 |

## 1. 현재 사용량·총 한도 확인하기 <a href="#step-1" id="step-1"></a>

1. **구독 관리 → 사용량 및 팩**을 엽니다.
2. 상단의 **현재 플랜**, **기본 저장공간 / 기본 시청시간**과 조건부 체험 안내를 읽습니다.
3. 저장공간·시청시간 카드에서 **사용 / 총**, **기본 제공 · 현재 추가 팩**과 한도 상태를 확인합니다.
4. 팩 변경 전에 현재 표시와 진행 중인 업로드·기존 팩 작업이 있는지 함께 확인합니다.

상단의 기본 제공량은 플랜 기준이며 카드의 **총**은 현재 유효 한도입니다. 체험 중에는 플랜의 기본 제공량에 현재 유효한 팩의 제공량을 더한 값과 체험용 최소 제공량을 비교해 더 큰 값을 적용합니다. 체험 제공량을 기존 한도에 무조건 더하는 방식이 아닙니다.

**사용량 정보를 불러오지 못했습니다** 또는 **표시할 사용량 정보가 없습니다**를 사용량 0·한도 무제한·팩 없음으로 판단하지 않습니다. 조회가 되지 않으면 새 구매보다 기존 상태 확인을 먼저 합니다.

> **화면 예시 준비 중** · 플랜 기본량과 현재 총 한도를 구분하고 저장공간·시청시간을 각각 확인합니다.

## 2. 저장공간과 시청시간의 기준 읽기 <a href="#step-2" id="step-2"></a>

시청시간 항목은 클킷에 직접 업로드한 영상(CDN 영상)의 시청 사용량을 다룹니다. 업로드한 원본 영상 길이의 합계나 개별 학생의 진도율과 같은 값이 아닙니다. 외부 영상의 학습 상태는 [외부 영상 연결하기](../content-management/external-video.md)에서 별도로 확인합니다.

| 항목 | 집계 기준 | 주의할 점 |
| --- | --- | --- |
| 저장공간 | 현재 보관 중인 사용량입니다 | 이번 달 업로드 합계가 아니며 월이 바뀌어도 보관 파일이 초기화되지 않습니다 |
| 시청시간 | 실제 구독 주기의 시작 시각부터 종료 시각 직전까지입니다 | 모든 사이트가 매월 1일 초기화되는 방식이 아닙니다 |
| Free 기준 체험의 시청시간 | 14일 체험 전체 기간입니다 | 날짜가 다음 달로 넘어가도 새 월 한도가 생긴다고 안내하지 않습니다 |
| 유료 기준 체험의 시청시간 | 기존 유료 구독 주기를 유지합니다 | 체험 시작·팩 구매가 시청량 초기화를 뜻하지 않습니다 |
| 화면 상단 월 표시 | 사용량을 측정한 시각의 달입니다 | 실제 시청 집계 주기·초기화일을 나타내는 표시가 아닙니다 |

**최근 사용량 살펴보기**를 열면 항목에 따라 **지난달 말 / 3개월 평균 / 현재** 또는 **지난 주기 / 3개 주기 평균 / 현재 주기**가 표시됩니다. 저장량의 월말 추이와 시청량의 구독 주기 추이를 같은 월 사용량으로 비교하지 않습니다.

이력이 부족하거나 불러오지 못하면 `-`와 안내가 표시될 수 있습니다. 기록 지연·표시 단위 차이 때문에 재생 직후 수치가 그대로라고 사용량이 발생하지 않았다고 단정하지 않습니다. 이 화면에는 기간 선택·파일별 상세 분석 기능이 없습니다. 정확한 시작/종료 시각·시간대가 필요하면 담당자에게 확인합니다.

### 남은 양과 바로 사용할 수 있는 양은 다릅니다 <a href="#section-5" id="section-5"></a>

남은 양은 **유효 한도에서 사용량을 뺀 양**, 사용 가능량은 여기에 **진행 중 업로드의 예약량까지 뺀 양**입니다. 각 값이 0보다 작으면 해당 값을 0으로 계산합니다. 사용/총 숫자만으로 다음 업로드가 가능한지 확정하지 않습니다.

현재 사용량 카드에는 예약량·사용 가능량·정확한 주기 시각이 각각 표시되지 않습니다. 필요한 세부 수치는 담당자에게 확인하고, 환불 창에 제공되는 **예약 사용량 / 환불 후 사용 가능량**과 구분합니다.

한도 소진/초과 안내가 곧 기존 영상 자동 삭제나 학생 수강권 회수를 뜻하지는 않습니다. 실제 업로드·재생 제한은 해당 작업에서 확인합니다. 저장 팩을 늘려도 [영상 파일당 형식·용량 기준](../content-management/video-upload.md)은 별도로 적용됩니다.

> **화면 예시 준비 중** · 저장량의 월말 추이와 시청량의 구독 주기 추이는 집계 기준이 다릅니다.

## 3. 필요한 팩 선택하기 <a href="#step-3" id="step-3"></a>

<figure><img src="../.gitbook/assets/branding/plan-capacity-illustration-v1.png" alt="서비스 플랜 패널과 저장공간"><figcaption></figcaption></figure>

1. **추가 사용량**에서 저장공간·시청시간의 현재/다음 갱신 팩을 읽습니다.
2. **추가할 저장공간 / 추가할 시청시간**에서 필요한 팩 또는 **추가 팩 없음**을 선택합니다.
3. 팩 제공량·월 금액·선택 불가 안내와 오른쪽 **변경 요약**을 확인합니다.
4. 두 항목을 함께 바꾼다면 저장공간과 시청시간의 선택을 모두 대조합니다.

현재 화면에서는 **항목별로 팩 한 종류만 선택**합니다. 변경할 수량은 선택한 종류가 1개, 같은 항목의 다른 종류가 0개로 정해집니다. 자유 수량 입력이나 같은 항목의 여러 팩 동시 선택 화면은 아닙니다. 기존에 복수 종류/여러 수량이 있다면 일부만 바뀐다고 가정하지 말고 전체 변경 범위를 담당자에게 확인합니다.

선택은 처음에 **다음 갱신 설정**을 기준으로 표시됩니다. 현재 적용량과 선택 표시가 다를 수 있으며 선택한 것만으로 저장·청구되지 않습니다. **다음 갱신 설정으로 되돌리기**는 화면 선택을 불러온 설정으로 돌릴 뿐, 이미 저장된 변경이나 종료 예약을 취소하는 요청이 아닙니다.

체험 기간·현재 플랜 비호환·비활성 구독·결제수단 없음·판매/가격 미확인 등의 사유로 선택이 제한될 수 있습니다. 체험 중에도 기존 팩 관리·환불 가능 여부는 신규 구매·증가 제한과 별도로 확인합니다. 다음 갱신부터 팩을 종료하려면 이 화면의 **추가 팩 없음** 선택과 견적 확인 절차를 따릅니다. 별도의 **갱신 중단** 버튼이나 카드 등록 바로가기는 이 화면에서 제공되지 않습니다. 카드가 필요하면 결제수단 담당자에게 확인하고, 아래 실행 보류 조건을 따릅니다.

> **화면 예시 준비 중** · 선택은 다음 갱신 설정에서 시작합니다. 되돌리기는 화면 선택만 복원합니다.

## 4. 견적의 이번/다음 금액 확인하기 <a href="#step-4" id="step-4"></a>

승인된 범위에서 **변경 내용 확인**을 누르면 **사용량 팩 변경 확인**이 열립니다.

| 확인할 값 | 의미 |
| --- | --- |
| 오른쪽 변경 요약의 현재 정기 결제 | 불러온 다음 갱신 설정을 바탕으로 계산한 월 예상액입니다. 실제 과거 청구액/현재 적용량의 증거가 아닙니다 |
| 변경 후 정기 결제 예상·월 변경액 | 선택한 팩과 기본 플랜을 합산한 월 예상액·차이입니다. 오늘 청구액과 다릅니다 |
| 견적의 오늘 결제 금액 | 이번 증가분과 남은 기간 등을 반영한 실제 요청 금액입니다. 월 가격 차이로 직접 계산하지 않습니다 |
| 견적의 다음 달 결제 예정 | 변경하지 않은 항목까지 포함한 전체 팩의 다음 주기 금액입니다. 기본 플랜 비용까지 합한 총액은 아닙니다 |
| 견적 유효시간 | 해당 견적의 만료 시각입니다. 오래된 견적·다른 조건의 캡처를 재사용하지 않습니다 |

**변경 후 총**은 선택에 따른 예상량입니다. 체험 하한·현재 유지 중인 팩·다음 갱신 적용 시점을 모두 반영한 현재 유효 한도로 보지 않습니다. 실제 현재 한도는 변경 처리 후 **사용 / 총**과 다시 대조합니다.

팩을 늘리는 변경과 줄이는 변경을 함께 하면, 늘어난 부분은 이번에 청구되며 청구가 성공한 뒤 적용됩니다. 줄어드는 부분은 다음 갱신 설정에 반영됩니다. 다른 팩으로 교체해도 기존 결제액이 다른 청구액에서 자동으로 차감되거나, 기존 결제가 자동으로 환불된다고 판단하지 않습니다. 이번 금액 0원도 실제 설정 변경을 뜻할 수 있습니다.

견적 **취소**는 창 닫기이며 기존 팩·저장된 예약 취소가 아닙니다. **변경 적용**은 실제 청구·변경 요청이며 별도 동의 체크박스나 추가 확인 창이 없을 수 있습니다. 실제 적용·청구 결과가 아직 확인되지 않았으므로 **최종 실행을 보류**하고 담당자에게 확인합니다.

> **화면 예시 준비 중** · 오늘 청구액·전체 팩의 다음 금액·플랜 포함 월 예상액을 나눠 읽습니다.

## 5. 현재 적용과 다음 갱신 설정 대조하기 <a href="#step-5" id="step-5"></a>

승인된 범위에서 요청했다면 처리 결과와 최신 사용량·팩을 함께 확인합니다.

| 변경한 내용 | 확인할 결과 |
| --- | --- |
| 팩 추가/증가 | 결제·작업 성공과 현재 추가 팩/총 한도, 같은 청구 건·금액을 대조합니다 |
| 감소/추가 팩 없음 | 현재 혜택과 **다음 갱신 시 추가 팩 / 총**을 나눠 읽습니다. **팩은 다음 갱신일부터 종료됩니다** 안내가 있다면 종료 설정을 확인합니다 |
| 팩 종류 교체 | 새 증가분의 이번 청구/현재 반영과 기존 팩의 다음 수량 감소를 각각 확인합니다 |
| 다음 갱신 시점 도달 | 날짜가 지났다는 사실뿐 아니라 실제 현재 팩·한도·갱신 청구/실패 결과를 확인합니다 |

**변경을 처리하고 있습니다**는 완료가 아닙니다. 완료 알림 뒤에도 같은 사이트의 현재/다음 설정·청구를 대조하며, 결과 불명확이면 같은 변경을 반복하지 않습니다.

청구 확인은 **팩 결제 내역 및 구독 관리** 또는 **구독 관리 → 구독 결제 내역**을 사용합니다. 감소·0원·실패·진행 중 작업 전체 목록은 아니므로 행이 없다는 이유만으로 요청이나 청구가 없었다고 판단하지 않습니다.

> **화면 예시 준비 중** · 증가는 성공 후 현재에, 감소는 다음 갱신 설정에 반영됐는지 확인합니다.

## 6. 자동 갱신·실패 상태 확인하기 <a href="#step-6" id="step-6"></a>

팩은 **월 구독 · 자동 갱신** 방식입니다. 사용량을 다 썼다고 새 팩이 자동 추가 구매되는 방식은 아닙니다.

- **결제 실패**가 보이면 팩 자체 갱신 실패인지, 기본 플랜의 결제 실패인지 구분합니다.
- 팩 갱신은 최초 실패부터 **144시간** 유예 기준이며 재시도해도 유예가 늘어나지 않습니다. 최초 팩 구매 실패에 동일 혜택·유예가 생기는 것은 아닙니다.
- 정확한 유예 종료 시각·현재 혜택/청구와 허용 작업은 최신 상태를 확인합니다. 유예 종료 카운트다운은 이 화면에 표시되지 않습니다. 정확한 종료 시각을 알 수 없으면 담당자에게 확인하며, 남은 시간을 추정하지 않습니다.
- **재결제**는 실제 갱신 청구 요청입니다. 조회 실패를 해결하거나 유예를 연장하려고 누르지 않습니다.
- **갱신 재개**는 누르는 즉시 실제 설정 변경을 요청하며 추가 확인 창이 없을 수 있습니다. 상태만 확인할 때는 누르지 않습니다. 재개가 기존 실패 청구의 결제 성공을 뜻하지도 않습니다.

버튼은 해당 팩의 상태와 클킷에서 허용한 작업에 따라 표시됩니다. 여러 보유 항목 전체를 한 번에 재개·재결제한다고 보장하지 않습니다. 현재 실제 재개·재결제는 보류합니다. 기존 결과를 먼저 확인하고 담당자에게 문의하세요.

Free/비호환 플랜 전환으로 종료된 팩은 나중에 유료 플랜으로 돌아와도 자동 복원된다고 안내하지 않습니다. 플랜을 바꾸기 전 [플랜 변경·구독 종료 예약하기](plan-change-and-subscription-end-schedule.md)의 팩 영향 확인을 함께 진행합니다.

> **화면 예시 준비 중** · 기존 상태부터 확인합니다. 갱신 재개와 재결제는 실제 설정/청구 요청입니다.

## 7. 미사용 팩의 환불 가능 수량 확인하기 <a href="#step-7" id="step-7"></a>

팩 결제 상세·환불 자격을 조회하는 과정에도 사용량이 어떤 팩에 반영되는지 확인하고 기록하는 처리가 포함됩니다. 따라서 조회만 하는 경우에도 관련 기록에 영향을 줄 수 있습니다. 필요한 업무인지 담당자에게 먼저 확인하고, 일반 예약량을 확인하려고 환불 창을 대신 열지 않습니다.

1. **구독 관리 → 구독 결제 내역**에서 해당 **사용량 팩** 결제를 엽니다.
2. **미사용 팩 환불**에서 대상 팩의 **구매 / 사용 / 환불 가능** 수량과 **환불 가능 기한**을 확인합니다.
3. **미사용 N개 환불**은 **미사용 팩 환불** 창을 엽니다. 조회도 관련 기록에 영향을 줄 수 있으므로 담당자가 확인한 업무 범위에서만 열고, 상태만 보려는 경우에는 누르지 않습니다.
4. **환불 수량**을 정하고 클킷에서 다시 계산한 **예상 환불액**·가능 여부를 읽습니다.

환불은 **승인 시각부터 승인 후 24시간 미만**의 아직 사용하지 않은 수량을 대상으로 합니다. **정확히 24시간이 되면 불가**하며 이미 환불했거나 환불 처리에 예약된 수량도 제외합니다. 화면의 24시간 이내 문구·날짜 표시만으로 마감까지 남았다고 판단하지 않습니다.

가능 수량·최신 자격과 예상액은 클킷에서 확인한 최신 결과를 사용합니다. 창을 열 때의 목록 수량이 계속 유효하다고 가정하거나 단가×수량으로 환불액을 계산하지 않습니다. **확인 불가 / 현재 선택한 수량은 환불할 수 없습니다**이면 신청을 진행하지 않습니다.

저장 팩의 환불 가능 여부는 현재 보관량뿐 아니라 과거 사용량·업로드 예약량이 어느 팩에 반영됐는지도 함께 확인해 판단합니다. **파일 삭제로 이미 사용한 팩의 환불 자격이 되살아나지 않습니다.** 환불 조건을 만들려고 파일·학생 이용 기록을 삭제하지 않습니다.

> **화면 예시 준비 중** · 승인 후 24시간 미만의 최신 가능 수량과 예상액을 확인합니다.

## 8. 환불 후 한도와 처리 결과 확인하기 <a href="#step-8" id="step-8"></a>

환불 창의 **환불 후 사용량**에서 다음을 대조합니다.

| 표시 | 확인할 내용 |
| --- | --- |
| 현재 사용량 / 예약 사용량 | 이미 사용하는 양과 진행 중 업로드 등으로 잡힌 양을 함께 확인합니다 |
| 환불 전 한도 / 환불 후 한도 | 신청 수량을 제외하면 실제 유효 한도가 얼마나 바뀌는지 확인합니다 |
| 환불 후 사용 가능량 | 사용량과 예약량까지 제외한 값입니다. 예약량을 다시 더하지 않습니다 |
| 초과 경고 | **환불 후 사용량이 한도를 초과합니다**이면 운영 영향부터 확인합니다 |

영향 정보가 없거나 조회가 실패하면 한도 변화 없음으로 판단하지 않습니다. 초과 경고가 없다는 사실도 환불 자격/실행 허용을 보장하지 않습니다.

**N개 환불 신청**은 실제 요청입니다. 실제 환불 결과가 아직 확인되지 않았으므로 **최종 신청을 보류**하고 담당자에게 확인합니다. 내용만 확인했다면 **취소**로 닫습니다.

승인된 범위에서 신청했다면 **환불 요청이 접수되었습니다**와 창 닫힘을 환불 완료로 처리하지 않습니다. 같은 요청의 최종 결과, 해당 결제의 환불 내역·금액/상태와 현재 팩/한도를 대조합니다. 실패·결과 불명확이면 새 환불이나 팩 구매로 우회하지 않고 기존 결과부터 담당자에게 확인합니다.

청구 목록의 원 승인액과 완료 환불을 반영한 상세 최종액은 다를 수 있습니다. 같은 거래의 환불 상태·금액은 [청구/환불 내역](billing-method-and-payment-history.md)과 대조하며 목록 금액이 그대로라고 새 신청을 하지 않습니다.

팩 축소/종료 예약은 별도 작업입니다. 환불 성공만으로 원하는 다음 갱신 설정까지 모두 정리됐다고 가정하지 말고 **사용량 및 팩**에서 최신 설정도 확인합니다.

> **화면 예시 준비 중** · 환불 전후 한도와 예약량을 확인합니다. 접수 알림은 완료가 아닙니다.

## 완료 후 확인 <a href="#completion-checklist" id="completion-checklist"></a>

- [ ] 대상 사이트와 조회/소유자·청구 권한을 구분했습니다.
- [ ] 저장공간의 현재 보관량과 시청시간의 실제 구독/체험 주기를 구분했습니다.
- [ ] 기본 제공량·팩·체험을 반영한 현재 유효 한도를 확인했습니다. 한도에서 사용량만 뺀 남은 양과, 업로드 예약량까지 뺀 사용 가능량을 구분했습니다.
- [ ] 최근 추이·집계 지연/표시 단위와 실제 업로드/재생 결과를 구분했습니다.
- [ ] 화면에서는 항목별로 팩 한 종류만 선택한다는 점을 확인했습니다. 기존에 여러 종류나 여러 수량의 팩이 있다면 현재 적용분과 다음 갱신 설정에서 무엇이 바뀌는지 전체 범위를 확인했습니다.
- [ ] 이번 청구액·팩만의 다음 금액·플랜 포함 예상액과 견적 유효시간을 확인했습니다.
- [ ] 요청했다면 증가/감소·처리 중/최종 결과·현재/다음 팩을 확인하고, 해당 요청의 청구 내역과 대조했습니다.
- [ ] 팩의 자동 갱신 방식과 최초 갱신 실패 시점부터 144시간인 유예 기준을 확인했습니다. 갱신 재개·재결제와 최초 구매 실패를 구분했습니다.
- [ ] 환불 검토 시 승인 후 24시간 미만인지, 사용량·예약량이 해당 팩에 반영됐는지, 최신 환불 가능 수량·금액과 환불 후 한도를 확인했습니다.
- [ ] 불명확한 요청을 반복하지 않았고, 실행이 보류된 작업은 담당자에게 확인했습니다.
