# 플랜 변경·종료 예약하기

<figure><img src="../.gitbook/assets/branding/page-headers/subscription-and-usage/plan-change-and-subscription-end-schedule-v2.png" alt="플랜 변경·구독 종료 예약하기 대표 이미지"><figcaption></figcaption></figure>

**업무 대상:** 클킷 이용 비용과 사이트 한도를 관리하는 소유자·담당자용 안내입니다. 이 업무를 맡지 않은 강사는 영상 업로드·수강 문의 때문에 플랜이나 카드를 직접 변경하지 말고 학원 운영자에게 요청하세요. 실제 작업 가능 범위는 본인 계정의 권한을 확인하세요.

**구독 관리 → 플랜 관리**에서 클킷 서비스 플랜을 변경하거나 유료 플랜 종료를 예약합니다. **상향 변경, 하향/Free 전환 예약, 예약 취소**는 서로 다른 작업입니다.

**완료 기준:** 변경 전후 플랜·이번/다음 금액과 적용 시점, 관리자·기능·한도 영향을 확인하고 요청했다면 실제 적용 또는 예약 결과까지 구분합니다. 견적을 열거나 완료 알림을 본 것만으로 처리 완료라고 판단하지 않습니다.

처음 유료로 시작하거나 체험을 확인하려면 [플랜·무료체험과 구독 시작하기](plan-trial-and-subscription-start.md)를 봅니다. 사용량/팩은 [사용량 확인·추가 팩 관리하기](usage-and-additional-packs.md)를 봅니다. 카드 등록/선택·청구 상세는 [구독 결제수단·청구 내역 확인하기](billing-method-and-payment-history.md)를 봅니다.

## 시작 전 준비 <a href="#before-you-start" id="before-you-start"></a>

| 준비할 것 | 확인할 내용 |
| --- | --- |
| 사이트·소유자 | 대상 사이트와 구독 결제자에 연결된 소유자 계정인지 확인합니다. 조회 권한이 곧 변경 권한은 아닙니다 |
| 현재 구독 | 현재 플랜·월 금액·구독 기간/다음 결제일, 기존 변경 예약·체험·실패/처리 중 안내를 확인합니다 |
| 변경 목적 | 상위 플랜 이용, 하위 플랜 예약, 유료 종료 후 Free 이용, 기존 예약 취소 중 무엇인지 정합니다 |
| 운영 영향 | 필요한 기능·저장/시청 한도·현재 팩과 관리자/강좌 담당 범위를 준비합니다 |
| 업무 승인 | 구독 담당자와 변경 목적·예산·예약/취소 범위·적용 시점을 확인합니다. 아래 실행 보류 안내를 먼저 읽습니다 |

**플랜 선택**이나 **구독 해지**로 견적을 여는 것도 견적을 생성·저장하는 동작입니다. 현재 상태만 확인하려는 경우에는 누르지 않습니다. 실제 변경·청구·환불은 구독 담당자의 업무 승인과 아래 실행 보류 조건을 확인해야 합니다.

## 먼저 변경 종류 구분하기 <a href="#section-2" id="section-2"></a>

| 목적 | 처리 기준 | 함께 확인할 것 |
| --- | --- | --- |
| 상향 변경 | 변경 성공 후 즉시 적용 대상입니다. 청구가 필요하면 승인·적용 결과까지 확인합니다 | 이번 청구액과 다음 주기 금액, 실제 현재 플랜·기간 |
| 하향 변경 | 현재 구독 주기 종료 시점에 하위 플랜을 적용하도록 예약합니다 | 현재 플랜 유지와 예약 플랜·적용 예정일 |
| 유료 구독 종료 | Free 플랜 전환을 예약하는 흐름입니다 | 즉시 사이트 중지/삭제·즉시 환불과 다름 |
| 변경 예약 취소 | 아직 남아 있고 취소 가능한 예약을 제거하는 변경 요청입니다 | 견적 창의 취소와 다르며, 이미 적용된 플랜을 되돌리는 기능이 아님 |

변경 종류와 금액은 현재 제공되는 플랜 목록과 최신 견적을 기준으로 합니다. 가격 차이만 보고 상향·하향을 정하거나 예전 플랜명·금액을 적용하지 않습니다.

## 1. 현재 플랜·예약·진행 상태 확인하기 <a href="#step-1" id="step-1"></a>

1. **구독 관리 → 플랜 관리**를 엽니다.
2. **현재 구독**에서 플랜 이름·**월 플랜 금액**, **다음 결제일**, **구독 기간**을 읽습니다.
3. **적용 예정**, 체험 중, 결제 실패/유예, 처리 중 안내가 있는지 확인합니다.
4. 기존 예약이나 결과가 불명확한 작업이 있다면 목적·현재 결과부터 확인합니다. 새 요청으로 덮어쓰거나 같은 변경을 반복하지 않습니다.

플랜 목록의 **이용 중**은 현재 플랜이며 예약 플랜과 다릅니다. **구독 정보를 불러오지 못했습니다** 오류를 Free·구독 종료·예약 없음으로 해석하지 않습니다. 결제 대기·기간 만료·구독 없음 등은 같은 변경 절차를 사용할 수 있다고 보장하지 않습니다.

> **화면 예시 준비 중** · 현재 플랜과 적용 예정인 플랜을 구분하고 기존 작업부터 확인합니다.

## 2. 변경 견적에서 금액과 시점 확인하기 <a href="#step-2" id="step-2"></a>

1. 승인된 범위에서 원하는 플랜의 **플랜 선택**을 누릅니다.
2. **플랜 변경 확인**에서 **현재 플랜 / 변경 플랜**을 대조합니다.
3. **결제 확인**의 금액과 유효시간을 읽고 상향 적용인지, 하향/Free 예약인지 구분합니다.

| 확인할 값 | 확인할 내용 |
| --- | --- |
| 최종 결제 금액 | 이번 변경 요청의 청구액입니다. 월정액·다음 주기 금액과 같은 값이라고 가정하지 않습니다 |
| 공급가액·부가세 | 견적의 구분과 최종 합계를 읽습니다. 표시된 최종액에 세금을 다시 더하지 않습니다 |
| 다음 주기 금액 | 다음 주기의 플랜 금액입니다. 별도 팩 등 모든 청구를 합한 총액으로 해석하지 않습니다 |
| 다음 결제일 | 현재 구독의 다음 결제일 표시와 실제 변경 적용 시점을 구분합니다 |
| 견적 유효시간 | 최대 15분이며 주기 종료가 먼저면 더 일찍 만료될 수 있습니다. 오래된 캡처·견적을 재사용하지 않습니다 |

상향의 이번 청구액은 남은 기간 등을 반영한 견적 결과를 사용합니다. 직접 월정액 차이·일수로 계산하지 않습니다. 하향/Free 견적의 이번 금액이 0원이어도 **예약 변경은 실제 발생하며 기존 결제의 환불을 뜻하지 않습니다**.

현재 견적 상단의 **다음 결제일**과 예약의 **적용 예정**은 날짜 중심 표시입니다. 상향의 정확한 적용 시각이나 예약 당일 몇 시에 바뀌는지까지 확인한 것으로 보지 않습니다. 필요한 정확한 시각·시간대는 담당자에게 확인하고 실제 적용 결과와 대조하기 전까지 확정하지 않습니다.

> **화면 예시 준비 중** · 이번 청구액과 다음 플랜 금액을 나눠 읽습니다. 다음 결제일이 모든 변경의 적용 시각은 아닙니다.

## 3. 기능·제공량과 팩 영향 확인하기 <a href="#step-3" id="step-3"></a>

<figure><img src="../.gitbook/assets/branding/plan-capacity-illustration-v1.png" alt="서비스 플랜 패널과 저장공간"><figcaption></figcaption></figure>

**새로 사용할 수 있는 기능** 또는 **더 이상 사용할 수 없는 기능**, **제공량 변경**의 현재/변경 후 값을 확인합니다.

| 확인할 영역 | 확인할 내용 |
| --- | --- |
| 기능 | 실제 운영 중인 상품 판매·페이지/게시판 등 필요한 기능이 대상 플랜에서도 가능한지 확인합니다 |
| 제공량 변경 | 플랜 기본 한도 비교입니다. 실제 팩·체험을 포함한 유효 한도는 **사용량 및 팩**에서 별도로 대조합니다 |
| 저장·시청 | 사용량·예약량·변경 후 한도를 함께 확인합니다. 남은 양과 바로 사용할 수 있는 양은 다릅니다. 현재 사용량 카드에 예약/가능량은 개별 표시되지 않으므로 필요한 세부량은 담당자에게 확인합니다 |
| 추가 팩 | 보유 팩의 호환성·갱신/종료·변경 후 한도와 청구 영향을 확인합니다. 플랜 변경만으로 모든 팩 정리가 끝난다고 판단하지 않습니다 |

예약량·기간의 개념과 실제 표시 위치는 [사용량 안내](usage-and-additional-packs.md)를 봅니다. 예약량을 확인하려고 환불 창을 대신 열거나 화면 밖에서 별도 요청을 보내지 않습니다.

**팩 영향 경고가 없어도 영향 없음으로 판단하지 않습니다.** 영향 목록이 비어 있거나 안내가 없더라도 보유 팩의 호환성·유효 한도·갱신 결과는 별도 확인이 필요합니다. 확인하기 전 하향 변경이나 Free 전환을 최종 실행하지 않습니다.

기능이나 한도를 맞추려고 파일·상품·운영자를 임의로 삭제하거나 팩 구매/환불을 실행하지 않습니다. 플랜 변경을 학생 수강권 회수·주문 환불로 처리하지 않습니다.

> **화면 예시 준비 중** · 기본 한도와 보유 팩의 실제 영향을 구분합니다.

## 4. 유지할 관리자 확인하기 <a href="#step-4" id="step-4"></a>

대상 플랜의 관리자 수보다 현재 관리자가 많으면 **유지할 관리자 선택**이 나타날 수 있습니다.

1. 대상 한도와 전체 후보의 이름·역할/담당 범위를 확인합니다.
2. `(소유자)`로 표시된 후보는 유지해야 하며 해제할 수 없습니다.
3. 선택이 필요한 경우 **소유자를 포함해 요구된 인원수만큼** 유지할 관리자를 정합니다. 단순히 최대 인원 이하로 고르는 방식이 아닙니다.
4. 제외 대상자의 실제 접근 권한과 강좌 담당·인계에 미치는 영향을 확인하고 필요한 동의를 받습니다.

이 선택은 화면 표시용이 아니라 적용 시 운영자 유지/제외에 영향을 줍니다. **예약 등록과 실제 관리자 변경 시점은 다릅니다.** 예약 이후 관리자 구성이 달라지면 적용 단계에서 다시 제한될 수 있으며 자동으로 다른 사람을 골라 준다고 안내하지 않습니다.

전체 강좌와 이관/해제 범위는 [운영자 지정·역할 관리하기](../members-and-operations/operator-assignment-and-roles.md)와 함께 확인합니다. 담당 강좌 전체를 확인하지 못했다면 역할 변경을 보류합니다. 견적에서 유지할 관리자를 선택하는 것으로 이 확인을 대신하지 않습니다. 후보·유지 인원·강좌/접근 영향이 확인되지 않으면 최종 변경을 보류합니다.

> **화면 예시 준비 중** · 소유자를 포함해 요구 인원수를 유지합니다. 선택과 실제 적용 시점은 다릅니다.

## 5. 상향 변경 요청 전 확인하기 <a href="#step-5" id="step-5"></a>

상향은 견적·카드·동의와 영향 확인을 거친 뒤 실제 변경 요청으로 이어집니다.

- **카드 등록하고 계속**이 보이면 카드 등록이 필요합니다. 외부 인증/등록 후 돌아온 **최신 견적**을 다시 읽고 관리자 선택·동의를 재확인합니다.
- 카드 등록 자체는 플랜 변경이나 청구 완료가 아닙니다. 기존 카드가 있을 때 새 카드를 추가·선택하는 방법과 등록 결과가 불명확할 때의 확인 사항은 [구독 결제수단·청구 내역 확인하기](billing-method-and-payment-history.md)에서 확인합니다.
- **적용 시점, 결제 금액, 기능 및 한도 변경 내용을 확인했습니다** 동의 후 **변경 적용**은 실제 요청입니다. 최종액이 0원이어도 단순 미리보기가 아닙니다.
- 체험 중 유료 전환이면 남은 체험 기간과 관계없이 체험이 종료되는 정책을 [플랜·무료체험과 구독 시작하기](plan-trial-and-subscription-start.md)에서 함께 확인합니다.

**현재 최종 실행은 보류합니다.** 실제 변경 결과와 관리자·팩에 미치는 영향이 아직 확인되지 않았습니다. 대상·금액·권한과 함께 담당자에게 확인하세요. 견적 내용만 확인했다면 **취소**로 닫습니다.

## 6. 하향·유료 구독 종료 예약 준비하기 <a href="#step-6" id="step-6"></a>

하위 플랜을 원하면 해당 플랜의 **플랜 선택**, 유료 구독을 끝내려면 현재 구독의 **구독 해지**를 통해 견적을 확인합니다. 구독 해지 버튼이 보이지 않거나 비활성이라면 소유자·현재 플랜/예약·선택 가능 상태를 먼저 확인합니다.

1. 승인된 범위에서 견적을 열고 **변경 플랜**이 원하는 하위 플랜 또는 **Free**인지 확인합니다.
2. 현재 주기 종료 시점의 예약인지, 기능·제공량/관리자·팩 영향이 확인됐는지 대조합니다.
3. 이번 청구액과 다음 주기 플랜 금액을 확인합니다. 0원 표시를 기존 결제 환불로 해석하지 않습니다.
4. 최종 **변경 적용**은 실제 예약 요청입니다. 실제 예약 결과는 아직 확인되지 않았으므로 **실행을 보류**합니다. 내용만 확인했다면 **취소**로 닫고 담당자에게 문의합니다.

**구독 해지 버튼을 누른 것만으로 종료가 예약되지는 않습니다.** 현재 화면에서는 Free 전환 견적을 여는 동작입니다. 견적 창을 취소하면 기존에 등록된 다른 예약까지 취소되는 것도 아닙니다.

Free 전환 예약은 사이트 중지/삭제·카드 삭제·학생 주문 환불이나 모든 팩 청구의 즉시 중단과 다릅니다. 사이트 운영 상태/삭제는 [사이트 중지·삭제하기](../members-and-operations/site-stop-and-delete.md)와 별도이며 기존 최종 실행 보류를 유지합니다.

> **화면 예시 준비 중** · 구독 해지는 Free 견적을 엽니다. 견적 확인만으로 종료가 예약되지 않습니다.

## 7. 실제 적용과 예약 결과 확인하기 <a href="#step-7" id="step-7"></a>

승인된 범위에서 요청한 경우 **플랜 관리**를 다시 확인합니다.

| 요청한 작업 | 확인할 결과 |
| --- | --- |
| 상향 | 작업 처리 결과와 실제 현재 플랜·기간/다음 결제일, 청구가 있었다면 같은 결제 건·금액·상태 |
| 하향/Free 예약 | 현재 플랜은 유지되는지, **[날짜]부터 [대상 플랜] 적용 예정**이 등록됐는지 |
| 예약 적용 시점 도달 | 날짜가 지났다는 사실뿐 아니라 실제 현재 플랜·기능/한도·관리자/팩·청구 결과 |
| 체험 중 유료 전환 | 실제 유료 적용과 체험 종료·유효 한도 결과를 함께 확인 |

**구독 변경이 완료되었습니다** 알림은 예약 작업에서도 표시될 수 있습니다. 예약 등록 성공을 새 플랜 즉시 적용으로 해석하지 않습니다. 예정일이 지났는데 상태가 다르다면 새 요청·재결제를 하기 전에 기존 작업의 결과를 확인합니다.

청구 확인은 **구독 결제 내역**을 사용하며 수강생의 상품 결제 내역과 구분합니다. 이 목록은 실패·진행 중·0원 작업 전체 목록이 아니므로 행이 없다는 이유만으로 요청이나 청구가 없었다고 판단하지 않습니다.

> **화면 예시 준비 중** · 완료 알림만 보지 않고 실제 현재 플랜과 변경 예약 결과를 따로 확인합니다.

### 변경 예약을 취소하려면 <a href="#section-10" id="section-10"></a>

남은 예약과 현재 플랜을 다시 읽고 소유자에게 **예약을 없애고 현재 플랜을 계속 이용하려는 것인지** 확인합니다. **변경 예약 취소**가 표시되고 클킷에서 취소를 허용하는 상태에서만 가능한 작업입니다.

현재 버튼은 **누르는 즉시 실제 취소 요청**을 보내며 추가 확인 창이 없을 수 있습니다. 실제 취소 결과가 아직 확인되지 않았으므로 **최종 실행을 보류**합니다. 예약을 취소해야 한다면 담당자에게 처리 방법을 먼저 확인하세요.

실제로 취소 요청을 했다면 처리 결과와 최신 화면에서 예약이 제거됐는지, 현재 플랜·기간이 유지되는지 확인합니다. 결과가 불명확하면 버튼을 다시 누르지 말고 담당자에게 확인합니다. 이미 적용된 변경을 원래 플랜으로 복구하거나 과거 청구를 취소하는 기능은 아닙니다.

> **화면 예시 준비 중** · 변경 예약 취소는 실제 요청입니다. 견적 창 취소나 이미 적용된 변경의 원복과 다릅니다.

## 자주 막히는 부분 <a href="#troubleshooting" id="troubleshooting"></a>

| 상황 | 먼저 확인할 것 |
| --- | --- |
| 변경/구독 해지 버튼이 없거나 비활성이에요 | 사이트·소유자·현재 플랜/구독 상태·기존 예약/진행 작업·선택 불가 사유를 확인합니다 |
| 다음 결제일이 상향 적용일인가요? | 같은 의미가 아닙니다. 변경 종류와 실제 결과를 확인하고 날짜만으로 정확한 적용 시각을 확정하지 않습니다 |
| 금액이 월정액 차이와 달라요 | 이번 견적의 남은 기간·최종액/세금과 다음 주기 금액을 구분합니다. 이전 캡처로 계산하지 않습니다 |
| 견적이 만료되거나 현재 조건이 바뀌었어요 | 기존 요청 결과가 확정됐는지 먼저 확인하고 최신 상태에서 견적을 검토합니다. 카드 등록 후에도 이전 견적/동의를 재사용하지 않습니다 |
| 유지할 관리자 선택이 완료되지 않아요 | 소유자를 포함해 요구된 인원수만큼 선택했는지, 후보 목록이 최신인지 확인합니다. 관리자 구성이 바뀌었거나 전체 담당 강좌와 이관 영향을 확인하지 못했다면 관리자 선택 내용을 저장하지 말고 담당자에게 확인합니다 |
| 팩 경고가 없으니 하향해도 되나요? | 팩 영향 안내가 비어 있어도 영향이 없다고 판단할 수 없습니다. 보유 팩의 호환성·유효 한도와 갱신 영향을 확인하기 전에는 하향 변경을 실행하지 않습니다 |
| 완료 알림은 떴는데 플랜이 그대로예요 | 하향/Free 예약인지 확인합니다. 현재/예약 플랜·예정일과 같은 작업을 대조하고 반복 요청하지 않습니다 |
| 플랜 변경을 처리하고 있습니다가 계속 보여요 | 접수·처리 중은 최종 실패가 아닙니다. 기존 결과를 확인하며 새 변경·재결제를 하지 않습니다 |
| 처리 상태를 확인하지 못했습니다가 보여요 | 해당 오류에서 **상태 다시 확인**이 표시되면 기존 작업부터 확인합니다. 조회 실패를 요청 실패로 단정하지 않습니다 |
| 예약이 없어졌는데 취소 성공인가요? | 예약 취소·실제 적용·조회 오류를 구분하고 현재 플랜/기간·처리 결과를 대조합니다 |
| 결제 실패 안내와 재결제가 보여요 | 현재 갱신 실패와 유예·청구 결과를 먼저 확인합니다. **재결제**는 실제 청구 요청이며 상태 조회/예약 취소 버튼이 아닙니다 |

문의에는 대상 사이트, 확인한 시각, 현재/변경 또는 예약 플랜, 화면 문구·이번 금액과 처리 중 여부를 적습니다. 비밀번호·카드 전체 번호·인증 키/카드 등록 주소·콘솔/요청 원문은 보내지 않습니다.

> **화면 예시 준비 중** · 결과 불명확과 확정 실패를 구분합니다. 새 요청 전에 기존 처리 상태부터 확인합니다.

> **동작 예시 준비 중** · 견적을 검토하고 닫는 예시입니다. 변경·종료 예약 완료나 기존 예약 취소가 아닙니다.

## 완료 후 확인 <a href="#completion-checklist" id="completion-checklist"></a>

- [ ] 대상 사이트와 구독 결제자에 연결된 소유자/조회 권한을 구분했습니다.
- [ ] 현재 플랜·기간과 기존 예약·체험·실패/진행 안내를 확인했습니다.
- [ ] 상향 적용·하향/Free 예약·예약 취소와 날짜/정확한 시각의 차이를 확인했습니다.
- [ ] 최신 견적의 이번 최종액·세금·다음 주기 금액·유효시간과 카드/재동의를 확인했습니다.
- [ ] 플랜의 기본 제공량과 팩·체험을 포함한 실제 한도, 현재 사용량을 구분했습니다. 팩의 영향을 확인하지 못했다면 변경 실행을 보류했습니다.
- [ ] 관리자 선택이 필요하면 소유자 포함 요구 인원·전체 후보/강좌·제외/이관 영향을 확인했습니다.
- [ ] 유료 종료 예약을 즉시 사이트 중지/삭제·환불·카드 삭제·모든 팩 청구 중단으로 처리하지 않았습니다.
- [ ] 요청했다면 알림뿐 아니라 실제 현재 플랜 또는 예약·예정일을 확인하고, 해당 요청의 청구/관리자/팩 결과도 확인했습니다.
- [ ] 견적 취소·예약 취소·재결제·조회 재시도를 구분하고 불명확 결과는 중복 요청하지 않았습니다.
- [ ] 실제 변경을 맡은 담당자와 확인이 필요한 정책·절차를 구분하고, 실행 보류 조건을 지켰습니다.
