# 주문·결제 상태 확인하기

> **검토용 가이드** · 실제 서비스 화면·동작 확인과 이미지 보완이 남아 있습니다. 본문의 실행 보류·주의사항을 먼저 확인하세요.

<figure><img src="../.gitbook/assets/branding/orders-and-shipping-illustration-v1.png" alt="주문·배송 대표 이미지"><figcaption></figcaption></figure>

수강생의 주문을 찾아 결제 상태·금액·결제 수단을 확인합니다. 학생 문의나 후속 업무를 시작하기 전에 **동일한 주문의 번호·구매자·금액**을 먼저 확인하세요.

**결제 완료는 강좌·자료 지급, 교재 배송 생성, 실제 발송 완료와 다릅니다.** 결제 상세 화면만으로 모든 후속 처리가 끝났다고 판단하지 않습니다.

**작업 순서:** 결제 내역 열기 → 검색·조건 적용 → 주문 상세 → 상태·금액 확인 → 필요한 후속 결과 별도 확인

## 시작 전 준비 <a href="#before-you-start" id="before-you-start"></a>

| 준비할 것 | 확인 기준 |
| --- | --- |
| 작업 계정 | 결제 내역 조회 권한이 있는 운영자 계정 |
| 조회 정보 | 수강생 이름·주문명·대략적인 결제 기간 |
| 문의 내용 | 결제·이용·배송·취소 중 어떤 결과를 확인하려는지 |
| 주문 식별 | 상세에서 대조할 주문번호·금액·구매자 |

가이드 이미지와 일반 문의에는 실제 학생 연락처·이메일·전체 주문번호·영수증 주소를 공개하지 않습니다. 카드번호나 인증정보를 학생에게 요청하지 마세요.

## 메뉴 위치 <a href="#menu-location" id="menu-location"></a>

관리자 화면의 **결제/정산관리 → 결제 내역**으로 이동합니다. 이 목록은 결제 조회용이며 별도의 배송 목록이나 콘텐츠 지급 결과 화면을 대신하지 않습니다.

> **화면 예시 준비 중** · 검색과 조건을 적용해 대상 주문을 찾습니다.

## 1. 주문 찾기 <a href="#step-1" id="step-1"></a>

1. 검색란에 **수강생 이름 또는 주문명**을 입력합니다.
2. **검색**을 누르거나 Enter를 누릅니다.
3. 필요하면 상태 탭을 선택합니다.
4. **필터**에서 결제 수단, **기간**에서 결제 기간을 선택하고 각 팝오버의 **적용하기**를 누릅니다.
5. 적용된 조건과 목록을 확인합니다. 조건이 지나치게 좁으면 조건을 해제하고 다시 조회합니다.

| 조건 | 선택·확인 방식 |
| --- | --- |
| 전체 | 특정 상태로 제한하지 않고 조회 |
| 결제 완료 | 결제 완료 상태의 내역 조회 |
| 결제 취소 | 취소·부분 취소·환불 상태의 내역 조회. 모두 전액 취소라는 뜻이 아님 |
| 결제 수단 | 카드·가상계좌·계좌이체·간편결제 중 필요한 조건 선택 |
| 기간 | 날짜 범위를 선택한 뒤 적용 |
| 쪽당 개수 | 10개·20개·50개씩 보기와 페이지 이동 |

검색·기간·수단·탭 조건은 함께 적용됩니다. 선택한 탭의 건수는 **현재 조건의 조회 결과**이며 모든 탭의 전체 건수를 동시에 보여주는 것은 아닙니다. 주문번호 전용 검색이나 별도 지급 처리 탭이 있다고 가정하지 않습니다.

> **동작 예시 준비 중** · 적용된 조회 조건을 확인하고 같은 주문의 상세를 엽니다.

### 결과가 없을 때 <a href="#section-4" id="section-4"></a>

**조건에 맞는 결제 내역이 없습니다**가 표시되면 검색어·기간·수단을 해제하고 전체 탭에서 다시 확인합니다. 조회 오류 안내는 빈 목록과 다릅니다. 오류가 발생하면 재조회 기능으로 다시 확인하고, 계속 실패하면 담당자에게 확인을 요청합니다.

검색 결과가 없다는 이유만으로 학생에게 다시 결제하도록 안내하지 않습니다. 문의한 사이트·계정·주문 시점이 맞는지도 확인하세요.

## 2. 주문 상세 열기 <a href="#step-2" id="step-2"></a>

목록의 주문 행을 누르거나 관리 메뉴의 **상세 보기**를 선택합니다. 상세 상단에서 주문명·주문번호·주문자명과 필요한 연락처 정보를 확인합니다.

동명이인이나 같은 상품의 반복 주문이 있을 수 있으므로 이름·상품명만으로 주문을 확정하지 않습니다. 주문번호·결제 금액·결제 시점을 함께 대조하세요.

> **화면 예시 준비 중** · 주문 식별 정보와 결제 상태를 함께 대조합니다.

## 3. 결제 상태 확인하기 <a href="#step-3" id="step-3"></a>

상단 상태와 결제 정보의 상태·일시를 함께 확인합니다. 실제 응답에 따라 표시되는 항목을 확인하며, 아래 모든 상태가 독립 탭으로 제공되는 것은 아닙니다.

| 표시 | 확인할 것 | 주의할 점 |
| --- | --- | --- |
| 결제 대기 | 결제 진행·최신 결과 | 아직 결제 완료로 안내하지 않음 |
| 입금 대기 | 가상계좌 등 입금 전 상태와 실제 반영 결과 | 입금 대기를 실패로 해석하지 않음 |
| 결제 완료 | 승인 금액·수단·시점 | 콘텐츠 지급·배송 생성·발송 완료와 별도 |
| 부분 취소 | 취소 금액과 남은 결제·구성 범위 | 전체 주문 취소로 안내하지 않음 |
| 취소·환불 | 해당 주문의 확정 상태·취소 금액 | 환불 요청·처리 중과 구분 |
| 환불 요청·환불 처리중 | 요청 이후 현재 단계 | 실제 환불 완료로 안내하지 않음 |
| 결제 실패·만료 | 오류·만료 안내와 외부 결제 결과 | 청구 여부가 불명확하면 재결제를 먼저 권하지 않음 |
| 수강권 지급 | 해당 권한 부여 내역 | 유료 결제나 교재·자료 전체 지급 완료의 증거가 아님 |

승인 결과가 불명확하거나 결제는 완료됐는데 이용할 수 없는 문의라면 **같은 주문의 결과를 확인**합니다. 새 주문·재결제·수동 중복 지급을 기본 해결책으로 안내하지 않습니다.

관리자 결제 상세와 학생 주문 상세는 다른 화면입니다. 학생 주문 상세에는 처리 안내·구성품별 제공·배송/신청 영역이 연결돼 있으나 이를 관리자에 같은 배지/타임라인이 제공된다는 뜻으로 쓰지 않습니다. [구매 후 콘텐츠 지급 확인하기](content-fulfillment-check.md)에 따라 같은 주문의 각 결과를 대조하고 결제 상태만으로 후속 성공/실패를 확정하지 않습니다.

## 4. 결제 금액·할인·배송비 확인하기 <a href="#step-4" id="step-4"></a>

상세의 **결제 금액** 영역에서 해당 주문에 저장된 값을 확인합니다.

| 항목 | 확인 기준 |
| --- | --- |
| 상품 총 금액 | 주문의 할인 전 상품 금액 |
| 상품 할인 금액 | 상품에 적용된 할인. 값이 있을 때 표시 |
| 쿠폰 할인 금액 | 주문에 적용된 쿠폰 할인. 상품 할인과 구분 |
| 배송비 | 해당 주문의 확정 배송비. 금액이 있을 때 표시 |
| 최종 결제 금액 | 해당 주문의 결제 금액 |
| 취소 금액 | 취소 정보가 표시되는 경우 확인. 원 결제 금액과 구분 |

배송비가 0원이면 금액 항목이 표시되지 않을 수 있습니다. 이를 교재 배송이 필요 없다는 뜻으로 해석하지 않습니다. 현재 상품 가격·쿠폰·배송 설정을 바탕으로 과거 주문 금액을 임의로 다시 계산하지 마세요.

0원 주문은 외부 결제 수단·일시·영수증이 없을 수 있습니다. 표시가 없다는 이유만으로 주문 실패로 판단하지 않고 해당 주문과 후속 결과를 확인합니다.

> **화면 예시 준비 중** · 원 결제 금액과 취소 금액, 확정 배송비를 구분합니다.

### 상품 구성·수량 표시가 이상하다면 <a href="#section-8" id="section-8"></a>

현재 확인한 화면에는 교재·자료의 단품 설명과 패키지 구성 표시에 보완할 부분이 있습니다. **`단일 강좌`라는 보조 문구만으로 실제 상품 종류를 확정하거나, 화면에 보이는 항목 수를 교재 출고 수량으로 사용하지 않습니다.**

혼합 구성이나 수량이 빠졌거나 상세가 정상 표시되지 않으면 원 주문과 확인된 구매 내역을 담당자가 대조해야 합니다. 이 상세만 보고 출고·권한 부여를 진행하지 않습니다.

## 5. 영수증과 거래 명세서 확인하기 <a href="#step-5" id="step-5"></a>

**영수증** 버튼이 활성화되어 있으면 눌러 연결된 영수증을 확인합니다. 영수증 주소가 없으면 버튼은 비활성화됩니다. 해당 상태만으로 결제 실패를 판단하지 않습니다.

**거래 명세서**는 별도의 확인 화면으로 이동하는 버튼입니다. 현재 거래 명세서 연동이 변경 중이므로 내용·공급자·금액을 대조한 뒤 안내해야 하며, 이 초안에서는 PDF 다운로드나 자동 증빙 발행 절차를 확정하지 않습니다. 영수증과 거래 명세서는 서로 다른 문서입니다.

> **화면 예시 준비 중** · 영수증 유무와 문서 진입을 확인합니다. 버튼 존재는 PDF 발행 성공이 아닙니다.

## 완료 후 확인 <a href="#completion-checklist" id="completion-checklist"></a>

- [ ] 주문번호·구매자·금액·시점으로 대상 주문을 대조했습니다.
- [ ] 검색·상태·수단·기간 조건이 의도한 범위인지 확인했습니다.
- [ ] 결제 완료와 지급·배송 생성·실제 발송을 구분했습니다.
- [ ] 원 결제 금액·할인·배송비·취소 금액을 구분했습니다.
- [ ] 구성·수량·처리 결과가 불명확하면 확정 업무 전에 확인을 요청했습니다.
- [ ] 영수증·거래 명세서의 실제 조회 결과를 확인하고 개인정보를 보호했습니다.

## 자주 막히는 부분 <a href="#troubleshooting" id="troubleshooting"></a>

| 상황 | 확인할 것 |
| --- | --- |
| 주문이 검색되지 않아요 | 사이트·계정·검색어·기간·수단·상태 조건을 확인하고 범위를 넓힙니다 |
| 필터를 골랐는데 결과가 같아요 | 팝오버의 적용하기와 적용된 조건을 확인합니다 |
| 결제 완료인데 영상·자료가 안 열려요 | 결제와 지급은 별도입니다. 실제 구매자 계정·주문·오류를 확인하고 중복 결제·지급을 피합니다 |
| 부분 취소인데 전체 금액이 보여요 | 원 결제 금액과 취소 금액·남은 범위를 구분합니다 |
| 교재인데 단일 강좌로 보여요 | 현재 보조 문구에 표시 차이가 있습니다. 실제 구성·수량을 대조합니다 |
| 영수증 버튼이 비활성화돼요 | 영수증 주소 유무와 0원 주문 여부 등을 확인합니다. 주문 실패로 단정하지 않습니다 |
| 거래 명세서가 열리지 않거나 내용이 달라요 | 현재 주문과 문서 결과를 대조하고 담당자에게 확인합니다. 다른 주문의 문서로 대체하지 않습니다 |
