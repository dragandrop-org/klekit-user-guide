# 배송지 변경하기

<figure><img src="../.gitbook/assets/branding/page-headers/orders-and-shipping/change-shipping-address-v2.png" alt="배송지 변경하기 대표 이미지"><figcaption></figcaption></figure>

**업무 대상:** 주문 확인·콘텐츠 제공·교재 배송을 맡은 담당자용 안내입니다. 강사는 학생이 알려 준 문제와 대상을 정리해 해당 운영자에게 전달하세요. 실제 작업 가능 범위는 본인 계정의 권한을 확인하세요.

이미 생성된 교재 배송 건의 수령인·연락처·주소·배송 요청사항을 정정할 때 사용합니다. 구매 단계의 주소 선택, 주소록 수정, 사이트의 출고지·반품지 설정과는 다른 작업입니다.

**구매자는 배송 대기, 운영자는 배송 대기·배송 준비에서만 변경할 수 있습니다. 구매자와 운영자 어느 쪽이 변경하든 해당 배송 건에 발송 이력이 없어야 합니다.** 상태를 준비 단계로 되돌려도 발송 이력이 남아 있으면 변경할 수 없습니다.

**확인 순서:** 변경할 배송 건 확인 → 역할·상태·발송 이력 확인 → 새 수령 정보와 유지할 값 대조 → 확인된 화면에서 저장 → 최신 배송 상세 재조회 → 출고 담당자에게 결과 전달

## 시작 전 준비 <a href="#before-you-start" id="before-you-start"></a>

| 준비할 것 | 확인 기준 |
| --- | --- |
| 대상 주문·배송 | 주문번호와 실제 변경할 배송 건 확인 |
| 변경 담당자 | 본인 배송을 변경하는 구매자 또는 배송 조회·변경 권한이 있는 운영자 |
| 현재 상태 | 배송 대기/준비 여부와 발송 이력 유무 |
| 변경할 정보 | 수령인·연락처·우편번호·기본/상세 주소·요청사항 |
| 유지할 정보 | 변경하지 않을 상세 주소·요청사항도 현재 값과 비교 |
| 출고 담당자 | 포장·송장 출력·택배 인계 진행 여부와 변경 결과 전달 대상 |

실제 구매자의 정보는 확인된 업무 경로에서만 다룹니다. 주소·전화·주문 식별정보를 공개 캡처나 불필요한 문의 내용에 넣지 않습니다.

## 메뉴 위치 <a href="#menu-location" id="menu-location"></a>

운영자는 **배송 관리 → 배송 관리 → 대상 배송 상세 → 주소 수정**으로, 구매자는 **마이페이지 → 구매 내역 → 결제 → 해당 주문 → 배송 정보 → 배송지 변경**으로 이동합니다. 변경 버튼은 권한과 배송 상태에 따라 다를 수 있습니다. 실제 서비스에서 각 경로가 열리는지, 저장 결과와 역할별 변경 제한이 안내대로 적용되는지는 아직 확인이 필요합니다.

구매 단계의 배송지 선택·주소록 수정과 이미 생성된 배송 건의 주소 변경은 별개입니다. 이 화면에서 바꾸는 것은 선택한 배송의 수령 정보·요청사항입니다. 주소록이나 원 주문에 기록된 구매 당시 주소는 자동으로 바뀌지 않습니다. 화면에 없는 방법으로 변경 제한을 우회하지 않습니다.

## 1. 어떤 주소를 바꾸는지 구분하기 <a href="#step-1" id="step-1"></a>

| 작업 | 바뀌는 대상 | 혼동하지 않을 것 |
| --- | --- | --- |
| 구매 단계에서 주소 선택 | 해당 구매 단계에서 사용할 주소 | 이미 생성된 주문·배송까지 자동 변경한다고 판단하지 않음 |
| 주소록의 주소 수정·기본값 변경 | 저장된 주소록 항목 | 생성된 배송 건의 수령 주소와 별개 |
| 주문별 배송지 정정 | 선택한 배송 건의 수령 정보·요청사항 | 구매 당시 주문 정보·주소록·다른 배송 건은 자동 변경하지 않음 |
| 사이트 배송 설정 변경 | 출고지·반품지·배송비 정책 등 | 구매자의 수령 주소 정정과 별개 |

원 주문에 기록된 구매 당시 주소가 남아 있어도 배송 정정 실패라고 단정하지 않습니다. 변경 결과는 **실제 출고에 사용할 해당 배송 상세**에서 확인합니다.

배송 건이 아직 생성되지 않았다면 이 가이드의 변경 대상부터 확인해야 합니다. 배송 생성 대기·조회 실패를 해결하려고 새 주문을 만들거나 주소록 수정만으로 완료됐다고 안내하지 않습니다.

## 2. 역할·상태·발송 이력 확인하기 <a href="#step-2" id="step-2"></a>

| 해당 배송의 상태·이력 | 구매자 | 운영자 |
| --- | --- | --- |
| 배송 대기·발송 이력 없음 | 본인 배송 변경 가능 | 권한이 있는 해당 사이트 배송 변경 가능 |
| 배송 준비·발송 이력 없음 | 직접 변경 불가. 담당자에게 요청 | 권한이 있으면 변경 가능 |
| 발송 완료 | 변경 불가 | 변경 불가 |
| 배송 취소 | 변경 불가 | 변경 불가 |
| 대기/준비로 보정됐지만 발송 이력 있음 | 변경 불가 | 변경 불가 |

구매자에게 배송 대기·준비가 모두 **상품 준비 중**으로 안내될 수 있습니다. 이 표시만으로 구매자 직접 변경이 가능하다고 판단하지 않습니다. 실제 허용 상태와 해당 배송의 변경 가능 여부를 확인합니다.

조회 권한이 있다고 변경 권한이 있는 것은 아닙니다. 구매자는 현재 사이트의 본인 배송만 변경하며, 운영자도 해당 사이트와 권한 범위 안에서 처리합니다.

**송장만 저장한 경우와 발송 이력이 생긴 경우는 다릅니다.** 송장이 있다는 이유만으로 변경 가능·불가를 확정하지 않습니다. 허용 상태·발송 이력을 확인하고 실제 포장·송장 출력·택배 인계 상황도 출고 담당자와 대조합니다.

> **화면 예시 준비 중** · 대상 배송과 역할별 변경 조건을 먼저 확인합니다.

## 3. 새 수령 정보와 유지할 값 확인하기 <a href="#step-3" id="step-3"></a>

| 항목 | 확인 기준 |
| --- | --- |
| 수령인 | 실제 받을 사람의 이름. 빈 값으로 저장하지 않음 |
| 연락처 | 실제 연락 가능한 번호. 입력란에 표시된 형식과 오류 안내 확인 |
| 우편번호 | 기본 주소와 맞는 숫자 5자리 |
| 기본 주소 | 도로명 등 실제 배송할 주소 확인 |
| 상세 주소 | 동·층·호수 등 필요한 정보. 기존 값을 유지할지 지울지 확인 |
| 배송 요청사항 | 유지·수정·삭제를 구분. 입력하는 경우 최대 500자 |

주소 검색·자동 완성 제공 여부와 입력 형식은 배송지 변경 화면에서 확인해야 합니다. 구매 단계와 같은 주소 검색 창을 사용할 수 있는지는 아직 확인이 필요합니다.

**저장 전 상세 주소와 배송 요청사항까지 확인합니다.** 값을 비우면 기존 내용이 지워질 수 있으므로 유지할 항목은 빠뜨리지 않습니다. 저장 후 같은 배송의 전체 수령 정보를 다시 확인하고, 의도와 다르면 반복 저장하지 말고 담당자에게 문의합니다.

주소록 수정과 해당 배송 건 정정은 다릅니다. 유지하려는 값이 누락되거나 의도치 않게 지워지지 않았는지 대조합니다.

> **화면 예시 준비 중** · 바꿀 정보와 유지할 상세 주소·요청사항을 함께 확인합니다.

## 4. 저장한 뒤 해당 배송 상세 다시 확인하기 <a href="#step-4" id="step-4"></a>

배송지 변경은 실제 수령 정보를 바꾸는 작업입니다. 원인을 확인하려고 주소를 시험 삼아 수정·저장하지 않습니다. 업무상 변경이 필요한 경우, 구매자·운영자별 허용 상태와 발송 이력을 먼저 확인한 뒤 아래 순서로 진행하세요.

1. 대상 배송을 다시 조회하고 변경 허용 상태·발송 이력·현재 주소를 확인합니다.
2. 확인된 입력 화면에서 변경할 정보와 유지할 값을 함께 대조합니다.
3. 해당 배송의 수정 화면에서 저장합니다. 주소록 저장과 혼동하지 않습니다.
4. 최신 배송 상세를 다시 조회해 수령인·연락처·우편번호·기본/상세 주소·요청사항을 확인합니다.
5. 배송 상태·택배사·송장은 주소 정정으로 임의 변경되지 않았는지 확인합니다.
6. 운영자는 확인된 변경 이력에서 변경 전후 정보를 비교해 누가 언제 무엇을 바꿨는지 확인합니다. 구매자 화면에서도 같은 관리자 이력을 볼 수 있다고 안내하지 않습니다.

저장 성공 알림만으로 출고 준비·택배사 정보까지 갱신됐다고 판단하지 않습니다. 최신 상세가 이전 주소라면 다른 배송 건을 보고 있는지, 저장 결과·권한·동시 변경을 확인합니다.

> **동작 예시 준비 중** · 주소록이 아닌 해당 배송을 정정하고 저장 결과를 확인합니다.

> **화면 예시 준비 중** · 저장 후 해당 배송의 최신 수령 정보를 다시 확인합니다.

## 5. 충돌·변경 제한·발송 이후 요청 처리하기 <a href="#step-5" id="step-5"></a>

| 상황 | 확인할 것 |
| --- | --- |
| 다른 담당자가 상태·주소를 변경함 | 최신 상세를 다시 조회하고 현재 값·허용 조건을 비교 |
| 구매자가 입력하는 동안 배송 준비로 바뀜 | 구매자 직접 변경 조건을 다시 확인. 운영자에게 요청해 처리 가능 여부 확인 |
| 발송이 먼저 처리됨 | 발송 이력에 따라 정정 불가. 상태를 되돌려 우회하지 않음 |
| 조회·저장 결과가 불명확함 | 실패·성공을 단정하거나 같은 값을 반복 저장하지 않고 대상·결과 확인 |
| 권한이 없거나 대상 배송을 찾지 못함 | 로그인·현재 사이트·본인/담당 배송·주문 식별을 확인. 다른 사용자 배송 조회로 우회하지 않음 |
| 배송 생성 전 또는 아직 정보 준비 중 | 대상 생성·현재 주문 결과를 담당자에게 확인. 미확인 변경 화면을 대신 안내하지 않음 |

입력 창을 열었을 때 가능했어도 저장 시점에는 발송·준비·다른 정정이 먼저 반영될 수 있습니다. 오래된 주소로 최신 배송지 정보를 자동으로 덮어쓰거나 무조건 재시도하지 않습니다.

발송 이후 변경 요청은 출고 담당자에게 현재 송장·실제 인계 사실과 함께 전달하고 별도 운영 절차를 확인합니다. 클킷 정정이나 상태 보정으로 이미 발송된 물건의 목적지가 바뀐다고 안내하지 않습니다. 택배사의 변경 접수·회수·재배송 성공도 이 가이드가 보장하지 않습니다.

> **화면 예시 준비 중** · 변경 제한과 최신 결과를 확인하고 운영자는 변경 이력을 대조합니다.

## 6. 출고 담당자에게 변경 결과 전달하기 <a href="#step-6" id="step-6"></a>

| 후속 확인 | 주의할 점 |
| --- | --- |
| 최신 배송 주소 | 포장·인계에 사용할 주소를 해당 배송 상세에서 다시 확인 |
| 이미 출력한 송장·포장 문서 | 이전 주소가 남아 있는지 담당자가 확인. 클킷 정정으로 자동 수정됐다고 가정하지 않음 |
| 택배사 접수 정보 | 클킷 저장과 외부 택배 업무 변경을 구분 |
| 주문·주소록 | 구매 당시 원 주문 주소와 저장 주소록은 별도 유지. 이후 구매용 주소 변경이 필요하면 별도 확인 |
| 금액·품목 | 배송지 정정으로 주문 배송비·금액·구매 품목을 다시 계산하지 않음 |

[출고 준비·송장 등록하기](dispatch-and-tracking.md)의 최신 품목·수령 정보·실제 인계 확인 기준을 이어서 적용합니다. 주소 정정 성공을 발송 완료·택배사 수정 완료로 설명하지 않습니다.

## 완료 후 확인 <a href="#completion-checklist" id="completion-checklist"></a>

- [ ] 변경할 주문·배송 건을 정확히 확인했습니다.
- [ ] 역할별 허용 상태·발송 이력·조회/변경 권한을 확인했습니다.
- [ ] 상품 준비 중 표시나 송장 존재만으로 변경 가능 여부를 판단하지 않았습니다.
- [ ] 새 수령 정보와 유지할 상세 주소·요청사항을 대조했습니다.
- [ ] 저장 후 최신 배송 상세의 모든 수령 정보를 다시 확인했습니다.
- [ ] 상태·송장·구매 당시 주문 정보·주소록·금액과 정정 범위를 구분했습니다.
- [ ] 운영자 변경 이력과 충돌/제한 결과를 확인했습니다.
- [ ] 출고 담당자에게 변경 결과를 전달하고 이전 송장·외부 접수 정보를 확인했습니다.

## 자주 막히는 부분 <a href="#troubleshooting" id="troubleshooting"></a>

| 주소록을 바꿨는데 주문 배송지는 그대로예요 | 주소록 수정과 해당 배송 정정은 별개입니다. 변경 대상과 실제 배송 상세를 확인합니다 |
| 상품 준비 중인데 구매자가 수정할 수 없어요 | 배송 준비는 구매자 직접 변경 대상이 아닙니다. 실제 상태·발송 이력과 변경 가능 안내를 확인합니다 |
| 운영자는 가능한데 구매자는 안 돼요 | 역할별 허용 상태가 다릅니다. 운영자도 변경 권한이 있는지, 해당 배송에 발송 이력이 없는지 확인해야 합니다 |
| 송장이 있는데 주소를 바꿀 수 있나요 | 송장 저장과 발송은 다릅니다. 상태·발송 이력과 실제 출고 상황을 함께 확인합니다 |
| 준비로 되돌렸는데 주소가 잠겨 있어요 | 최초 발송 이력이 남으면 정정할 수 없습니다. 상태 보정으로 제한을 우회하지 않습니다 |
| 상세 주소·요청사항이 없어졌어요 | 유지/삭제 의도와 화면의 저장 방식을 확인합니다. 다시 저장하기 전 최신 값을 대조합니다 |
| 저장 후 원 주문 주소는 그대로예요 | 원 주문에 기록된 구매 당시 주소는 유지됩니다. 실제 출고에 사용할 배송 상세에서 확인합니다 |
| 다른 담당자가 변경했다는 안내가 나와요 | 최신 상태·주소를 다시 조회하고 비교합니다. 오래된 값으로 자동 덮어쓰지 않습니다 |
| 택배사 주소도 자동으로 바뀌나요 | 클킷 정정과 외부 택배 업무는 별개입니다. 출력 송장·접수 정보는 출고 담당자와 확인합니다 |
