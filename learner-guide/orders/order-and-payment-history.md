# 주문·결제 내역 확인하기

> **검토용 가이드** · 실제 서비스 화면·동작 확인과 이미지 보완이 남아 있습니다. 본문의 실행 보류·주의사항을 먼저 확인하세요.

<figure><img src="../.gitbook/assets/branding/page-headers/orders/order-and-payment-history-v1.png" alt="주문·결제 내역 확인하기 대표 이미지"><figcaption></figcaption></figure>

구매한 주문과 결제 정보를 확인하려면 **마이페이지 → 구매 내역 → 결제**를 엽니다. **목록에서 주문 찾기 → 주문번호·상품 확인 → 결제 요약·상태 읽기 → 실제 이용 또는 문의** 순서로 확인합니다.

**완료 기준:** 내 계정의 해당 주문을 찾고 주문번호·상품·금액·상태를 대조합니다. 결제완료 배지와 실제 강좌/자료 지급·교재 배송, 환불 신청과 실제 환불 반영은 각각 따로 확인합니다.

## 시작 전 확인 <a href="#before-you-start" id="before-you-start"></a>

| 확인할 것 | 내용 |
| --- | --- |
| 사이트와 계정 | 구매한 학원 사이트와 계정이 맞는지 확인합니다. 보호자나 다른 계정으로 결제한 주문이 현재 계정에 자동 합쳐지는 것은 아닙니다 |
| 구매와 직접 지급 | 구매 내역은 주문을 확인하는 곳입니다. 학원에서 직접 지급한 수강권·자료가 결제 목록에도 반드시 생기는 것은 아닙니다 |
| 찾을 주문 | 상품명·구매한 대략적인 시각·주문번호를 준비합니다. 같은 상품을 여러 번 주문했다면 금액과 작성/결제 시각도 함께 대조합니다 |
| 확인할 목적 | 주문·결제 내역과 실제 수강/자료 이용·배송·취소/반품/교환 결과를 구분합니다. 내역 확인을 위해 재결제·자료 다운로드·취소를 실행하지 않습니다 |
| 개인정보 | 주문번호는 학원 문의에 필요한 범위에서만 전달합니다. 비밀번호·인증번호·카드 전체 번호·결제 키·영수증/파일 URL은 공유하지 않습니다 |

로그인 계정이 헷갈리면 [내 계정과 로그인 방식 확인하기](../account/check-account-and-login-method.md)를 먼저 확인합니다. 운영자의 클킷 구독 결제·청구 내역과 수강생의 상품 구매 내역은 다른 화면입니다.

## 1. 구매 내역의 결제 탭 열기 <a href="#step-1" id="step-1"></a>

1. 학원 사이트에 로그인한 뒤 **마이페이지 → 구매 내역**을 엽니다.
2. 상단 **결제** 탭을 선택합니다. **쿠폰** 탭은 보유 쿠폰을 확인하는 곳이며 주문 목록이 아닙니다.
3. 목록을 불러오는 동안 기다립니다. PC는 표, 모바일은 카드로 표시될 수 있습니다.

> **화면 예시 준비 중** · 구매 내역에서 결제 탭을 엽니다.

## 2. 목록에서 주문 찾기 <a href="#step-2" id="step-2"></a>

| 보이는 항목 | 확인할 것 |
| --- | --- |
| 주문명 | 찾는 상품과 같은 주문인지 확인합니다. 묶음/옵션의 세부 구성은 주문명만으로 판단하지 않습니다 |
| 상태 | 결제 또는 환불 처리 표시입니다. 환불 안내가 결제 상태 대신 우선 표시될 수 있습니다 |
| 결제금액 | 해당 주문의 표시 금액입니다. 취소/환불 뒤 남은 금액이나 이번에 환불된 금액으로 바로 해석하지 않습니다 |
| 결제일 | 결제 시각을 우선 사용하지만 결제 시각이 없으면 주문 생성 시각이 표시될 수 있습니다. 날짜가 보인다는 사실만으로 승인을 판단하지 않습니다 |
| 강좌 N개 | 주문 항목 수를 보여주는 보조 문구입니다. 실제 강좌 지급 개수·교재 수량·묶음의 전체 구성품 수와 같다고 보장하지 않습니다 |

1. 주문명·금액·날짜·상태를 함께 대조합니다. 목록은 최근에 생성된 주문부터 표시되며 결제일만으로 정렬되는 것은 아닙니다.
2. PC는 페이지 번호, 모바일은 **더 보기**가 있을 때 추가 목록을 확인합니다. 표시된 모든 주문을 무제한으로 불러올 수 있다고 가정하지 않습니다.
3. 해당 주문의 행/카드를 눌러 상세를 엽니다. 목록에는 주문번호가 별도 열로 표시되지 않으므로 상세에서 확인합니다.

현재 목록에는 검색창·기간 선택·상태 필터가 없습니다. 목록에 없는 조회 기능이 제공된다고 가정하지 않습니다.

**모든 결제 시도·실패·입금대기 주문이 이 목록에 표시되는 것은 아닙니다.** 기본 목록에서는 결제완료·부분취소·취소·환불 주문을 중심으로 확인합니다. 결제창을 열었거나 입금대기 상태인데 주문이 보이지 않는다고 미결제/주문 삭제로 단정하거나 같은 상품을 다시 결제하지 않습니다.

> **화면 예시 준비 중** · 주문명·금액·날짜·상태를 함께 확인합니다.

> **동작 예시 준비 중** · 해당 주문의 상세를 확인하고 목록으로 돌아갑니다.

## 3. 상세에서 주문번호와 상품 확인하기 <a href="#step-3" id="step-3"></a>

1. 상단 **주문번호**를 확인합니다. 주문명이나 상품명과 주문번호는 다릅니다. 같은 상품의 다른 주문과 혼동하지 않습니다.
2. 상품 카드의 이름·썸네일·표시된 가격을 확인합니다. 썸네일이 없거나 달라 보여도 주문이 없어진 것으로 판단하지 않습니다.
3. **수강기간**이 표시되면 해당 상품의 기간 안내로 읽습니다. 실제 남은 기간·종료일은 [수강 기간과 학습 현황 확인하기](../learning/access-period-and-progress.md)에서 확인합니다. 기간이 표시되지 않는다고 무제한 이용으로 해석하지 않습니다.
4. 상품 이름/가격에 취소 표시·취소선이나 **취소됨**이 보이면 어떤 항목인지 확인합니다. 주문 전체 상태와 항목 상태를 함께 읽습니다.

**현재 상세 카드가 옵션 교재·묶음 구성품·수량·구성품별로 배분된 결제 금액을 모두 펼쳐 보여주는 것은 아닙니다.** 카드의 개수와 단가만으로 구매 구성·총 결제액·최종 환불액을 다시 계산하지 않습니다. 예상한 구성과 다르면 주문번호와 상품명을 학원에 문의합니다.

상품 카드가 곧 강의실 입장 버튼은 아닙니다. 수강은 [내 강의 찾고 수강 시작하기](../learning/find-course-and-start.md)에서 별도로 진행합니다.

> **화면 예시 준비 중** · 상품 카드와 구성품별 제공 결과를 나눠 읽습니다.

## 4. 결제 요약 읽기 <a href="#step-4" id="step-4"></a>

| 항목 | 읽는 방법 |
| --- | --- |
| 최종 결제 금액 | 주문 상세의 결제 정보에 표시되는 금액입니다. 환불 차감 후 잔액·최종 환불 예정액과 같다고 판단하지 않습니다 |
| 강의 금액 | 화면의 결제 금액과 할인 금액을 바탕으로 표시되는 요약입니다. 옵션/배송비/세금이 독립 항목으로 모두 확인된 값이라고 보장하지 않습니다 |
| 할인 금액 | 할인 금액이 있을 때 표시됩니다. 없거나 보이지 않는다고 오류로 단정하지 않습니다 |
| 쿠폰 할인 | 적용된 쿠폰 할인 금액과 조건부 쿠폰명이 표시됩니다. 지금 보유한 쿠폰과 해당 주문에 사용한 쿠폰은 다릅니다 |
| 결제 수단 | 기록된 결제 수단입니다. 무료 주문은 **0원 결제**, 정보가 없으면 `-`로 보일 수 있습니다. 표시된 수단명을 전체 지원 목록으로 해석하지 않습니다 |
| 결제 시각 | 값이 있을 때 표시됩니다. 목록의 날짜와 대조하고 승인 정보가 없는데 임의로 결제 완료 시각을 추정하지 않습니다 |

목록과 상세의 금액이 다르거나, 취소 이후 예상한 잔액을 찾을 수 없다면 해당 주문번호·표시 금액·상태를 함께 전달합니다. 결제 요약에는 환불 누계·현재 순결제액·세금/배송비가 모두 구분돼 표시되지 않으므로 **보이지 않는 값을 0원으로 간주하거나 직접 보정하지 않습니다.**

0원 주문도 상품 제공 확인이 필요합니다. 구매하지 않고 직접 지급받은 이용권과 0원 주문을 구분하며, 무료라는 이유로 유료 영수증이 반드시 제공된다고 생각하지 않습니다.

> **화면 예시 준비 중** · 요약 금액과 결제 수단·시각을 확인합니다.

## 5. 결제 상태와 환불 안내 구분하기 <a href="#step-5" id="step-5"></a>

기본 주문 상태와 환불 요청 상태는 다릅니다. 환불이 진행 중이면 목록/상세에 환불 배지와 안내가 우선 표시될 수 있으므로, 결제완료라는 단어만 찾지 말고 실제 안내 문구를 함께 읽습니다.

| 표시 | 다음 확인 |
| --- | --- |
| 결제완료 | 해당 주문의 결제 처리 표시입니다. 강좌/자료가 실제로 제공됐는지·교재 배송이 준비됐는지는 별도로 확인합니다 |
| 부분취소 | 일부 주문 항목이 취소된 상태입니다. 상세의 취소 항목과 남은 이용 범위를 확인하며, 요약 금액을 현재 잔액으로 단정하지 않습니다 |
| 취소완료·환불완료·환불 완료 | 처리 상태를 확인한 뒤 실제 결제수단의 취소/환불 반영을 대조합니다. 반영 시점·전액 여부를 배지만으로 보장하지 않습니다 |
| 환불 요청중 | 신청 후 확인 대기 단계입니다. 접수된 것과 승인·환불 완료는 다릅니다 |
| 환불 처리중 | 처리가 진행 중인 단계입니다. 중복 신청/재결제하지 않고 기존 요청의 결과를 확인합니다 |
| 환불 거절 | 표시된 안내와 거절 사유가 있으면 확인합니다. 버튼이 없다고 다른 주소로 다시 신청하지 말고 학원에 문의합니다 |
| 환불 실패 | 완료로 해석하지 않습니다. 주문번호·상태·문구를 학원에 전달해 실제 결과를 확인합니다 |
| 결제대기·결제실패·만료 | 이런 표시를 보더라도 모든 시도가 목록에 남는 것은 아닙니다. 원 주문·승인 결과를 확인하며 같은 주문/상품의 재결제를 임의로 반복하지 않습니다 |

**결제 상태는 수강권·자료 지급, 배송, 취소·반품·교환 신청 상태를 대신하지 않습니다.** 현재 원 주문 상세에는 **구성 콘텐츠 처리 상태**, **배송 정보**, **취소·반품·교환 신청** 영역이 연결돼 있습니다. 대상별 수량·상태와 실제 강좌·자료 이용 및 교재 배송 결과를 나눠 확인하고, 영역이 비어 있거나 조회가 실패하면 전체 제공 완료/신청 없음으로 단정하지 않습니다.

환불 안내가 목록과 상세에서 다르게 보이거나 이전 상태가 남아 있으면 재조회 후 확인합니다. 새로고침·화면 이동을 했다는 사실만으로 실제 처리 결과가 확정된 것은 아닙니다.

> **화면 예시 준비 중** · 주문 배지와 신청별 상태·실제 결과를 구분합니다.

현재 목록/상세는 **교환 요청중·교환 진행중·교환 거절·교환 완료** 표시도 구분합니다. 교환 완료는 환불 완료가 아니며 원래 배송과 새 배송, 실제 수령 여부와 교환 후 반영 결과를 따로 확인합니다. 결과 확인 중·콘텐츠 준비 중·입금 대기 등 주문 처리 안내도 결제/환불 배지와 별도입니다.

## 6. 확인 목적에 맞게 이동하기 <a href="#step-6" id="step-6"></a>

| 확인하려는 것 | 이어서 할 일 |
| --- | --- |
| 강좌 수강 시작 | **내 학습 → 수강중 강좌**에서 해당 강좌를 찾습니다. [내 강의 찾고 수강 시작하기](../learning/find-course-and-start.md)를 참고합니다 |
| 디지털 자료 이용 | **내 학습 → 내 자료**에서 확인합니다. [구매하거나 지급받은 디지털 자료 이용하기](../resources/my-digital-resources.md)를 참고합니다. 내역 확인만을 위해 다운로드하지 않습니다 |
| 영수증·거래명세서 | 상세의 **영수증 / 거래명세서** 위치를 확인합니다. 영수증은 제공 조건·주소 유무에 따라 숨김/비활성일 수 있습니다. 실제 열기·브라우저 인쇄/저장은 [영수증과 거래명세서 확인하기](receipt-and-invoice.md)에서 확인합니다 |
| 교재 배송·취소/반품/교환 | 원 주문 상세의 배송 정보/배송지 변경·구성품 취소 신청·반품·교환 신청·신청 상태를 구분합니다. [교재 배송](textbook-shipping-and-address.md)·[상품 취소](../cancellations/request-cancellation.md)·[반품/교환](../cancellations/request-return-or-exchange.md)에서 조건/제출 효과를 확인하며 조회용으로 신청 버튼을 누르지 않습니다 |
| 오류·구매/제공 내용 문의 | [사이트에 1:1 문의하기](../communication/site-inquiries.md)에서 주문번호·상품·금액/상태·문구를 전달합니다. 로그인할 수 없다면 학원의 별도 연락처를 이용합니다 |

상단 뒤로 이동은 결제 목록으로 돌아가는 동작입니다. **취소 / 전체 취소**는 상품 이용·환불 처리를 시작할 수 있는 별도 동작이므로 목록 복귀나 조회용 버튼으로 누르지 않습니다. 표시된 버튼만으로 취소 자격·최종 환불액을 판단하지 않습니다.

> **화면 예시 준비 중** · 목록 복귀와 신청·주소·증빙 작업을 구분합니다.

## 내역이 보이지 않거나 내용이 다를 때 <a href="#section-8" id="section-8"></a>

| 상황 | 확인할 것·다음 행동 |
| --- | --- |
| 결제 내역이 없습니다. | 학원 사이트·구매 계정·직접 지급 여부를 확인합니다. 실패/입금대기 주문이 기본 목록에 없을 수 있으며 재결제로 확인하지 않습니다 |
| 결제 목록이 열리지 않거나 상태 표시가 비정상이에요 | 알고 있는 원 주문번호·상품·시각과 현재 화면을 학원에 전달합니다. 빈 목록·미접수·미결제로 단정하거나 새 결제/신청으로 확인하지 않습니다 |
| 결제 내역을 불러오지 못했습니다. | 목록의 재시도를 이용합니다. 조회 실패를 주문 없음·결제 실패로 해석하지 않습니다 |
| 주문을 찾을 수 없습니다. | **돌아가기** 후 내 목록·계정을 확인합니다. 조회 오류도 같은 화면으로 보일 수 있으므로 삭제/취소로 단정하거나 주소의 주문 ID를 추측하지 않습니다 |
| 같은 상품의 주문이 여러 개예요 | 상세의 주문번호·금액·시각을 대조합니다. 어떤 주문인지 확인하기 전에 전체 취소/새 결제를 하지 않습니다 |
| 목록 날짜가 예상과 달라요 | 결제 시각과 주문 생성 시각을 구분하고 상세의 결제 시각 유무를 확인합니다. 정확한 시각이 필요하면 학원에 문의합니다 |
| 금액·쿠폰·옵션 구성이 달라 보여요 | 목록/상세의 표시값과 주문번호를 전달합니다. 카드 단가 합산·누락값 0원 처리로 최종액을 확정하지 않습니다 |
| 결제완료인데 강좌·자료가 없어요 | 내 계정·상품 구성·내 학습 목록을 확인하고 학원에 문의합니다. 결제 배지만으로 지급 완료를 단정하거나 다시 구매하지 않습니다 |
| 환불 표시와 실제 결제수단 반영이 달라요 | 신청/처리/완료·부분취소 여부와 실제 내역을 나눠 설명합니다. 환불 실패/거절이나 불명확한 결과를 반복 신청으로 해결하지 않습니다 |
| 배송 정보나 증빙 버튼이 안 보여요 | 해당 주문의 제공 범위·영수증 조건을 확인합니다. 없는 배송/인쇄 화면을 우회하거나 다른 사람의 URL을 사용하지 않습니다 |

> **화면 예시 준비 중** · 불명확한 결과는 재결제하지 않고 문의합니다.

## 학원에 문의할 때 <a href="#contact-academy" id="contact-academy"></a>

학원 사이트, 주문번호·상품명, 표시된 금액·상태, 대략적인 발생 시각·기기/브라우저와 화면 문구를 전달합니다. 목록/상세 중 어느 화면인지, 결제 완료·입금대기·승인 결과 불명확 중 어떤 상황인지 설명합니다. 실제 강좌/자료 제공이나 환불 반영 문제가 있다면 해당 결과도 구분합니다.

**비밀번호·인증번호·카드 전체 번호·계좌 전체 정보·결제 키/토큰·영수증/파일 URL·다른 사람의 주문은 보내지 않습니다.** 캡처에서는 실제 학생·결제 정보와 주소창을 가립니다. 주문번호는 필요한 담당자에게만 전달합니다.

## 완료 확인 <a href="#completion-checklist" id="completion-checklist"></a>

- [ ] 구매한 학원 사이트·계정과 구매/직접 지급의 차이를 확인했다.
- [ ] 구매 내역의 결제/쿠폰 탭과 기기별 목록 이동을 구분했다.
- [ ] 주문명·금액·날짜·상태를 대조하고 모든 결제 시도가 목록에 나타난다고 가정하지 않았다.
- [ ] 상세에서 주문번호·상품·조건부 기간·취소 항목을 확인했다.
- [ ] 결제금액·할인/쿠폰·수단/시각과 환불 잔액·누락값을 구분했다.
- [ ] 결제 상태와 환불 요청/실제 반영·강좌/자료 지급·교재 배송을 구분했다.
- [ ] 옵션/구성품·배송·신규 신청 화면이 모두 연결됐다고 가정하지 않았다.
- [ ] 뒤로 이동과 증빙·취소/전체 취소 등 별도 동작을 구분했다.
- [ ] 불명확한 결과를 재결제/중복 신청·타인 접근으로 확인하지 않고 최소 정보만 문의했다.
